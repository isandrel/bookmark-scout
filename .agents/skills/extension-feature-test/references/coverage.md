## Chromium end to end (also run in Edge)

The same Playwright suite runs in Microsoft Edge against the Edge build (`Edge E2E`).

- **Popup and side panel:** popup search, saving the current page through folder matches (multi-word, typo, and recent ranking, and their settings; Enter in the search box saving into the highlighted first match in the popup and side panel, right after typing, once while held, never from an IME's composing Enter, and recording the search instead when nothing matches), the **Already saved in** line under the page to save and the another-copy note when a save adds a second bookmark of the page, folder creation, keyboard shortcuts, saved searches, context-menu saves, and popup and side panel drag-and-drop moves.
- **Popup layout:** `tests/e2e/popup-layout.spec.ts` checks that every search row control fits the narrowest popup with AI on in English, Japanese, and Simplified Chinese (inside the page, not overlapping, and leaving the configured typing width), recent folder chips for folders with the same name, folder matches holding their order under the pointer after a save, and tree row tooltips; `popup-tree-actions.spec.ts` the date-sort drag hint and refused reorder.
- **Bookmark management, settings, tools:** bookmark management, settings synchronization, maintenance tools, reports, manager column resizing, the prompt library, named AI services and the popup service switcher, live settings (language switch and a second Options tab), two Options tabs saving at once (no lost update, through Web Locks shared with the service worker), and dialog motion (no backdrop flash on close).

- **Quick save notification placement** (`quick-save-notification.spec.ts`): on screen and on top on scrolled pages whose body has a `filter`, `transform`, or `will-change`; size, left-to-right direction, and colors kept on a `dir="rtl"` page with `zoom` and `filter: invert()` on `<html>`, checked by box geometry and a painted pixel; an AI quick save the tab navigated away from ending in the popup under the page's title; **Retry** and **Save without AI** after a stubbed provider failure, in the page and in the popup; an older tab's **Undo** after a newer quick save.

## Firefox smoke

`tests/e2e-firefox/` against the Firefox build: popup search and folder creation, saved site icons in the popup, side panel page, opening the manager from the popup and side panel, manager, the manager's `?q=` address and Copy link to this folder copying the extension page's address, the manager's Delete key and Ctrl/Cmd+Z through the session-storage undo history, the manager's right-click menu (Copy and Paste, and no private window for a temporary add-on), the manager's drag and drop from scripted drag events (a move down within a folder, where Firefox's move index differs from Chrome's, and a `text/x-moz-url` link dropped on a tree folder), the manager's folder tree keys (arrow keys and Enter), settings save, JSON export and import, statistics and privacy reports, and the quick save shortcut recorder in Options with the real `commands.update` and `commands.reset` (recording a combination, rejecting a bare key and Firefox's own Ctrl+D, Tab leaving the field, and the popup notice for a cleared shortcut).

Permissions in Firefox: the AI data collection explanation (it names the AI company as Firefox's "developer") with Not now, and a Check Dead Links run asking for its bookmarks' site only, granted from a real WebDriver click with `extensions.webextOptionalPermissionPrompts` off in the test profile, which proves Firefox accepts the narrowed origins inside the MV2 `optional_permissions`.

The shortcut workflow preserves the application's smooth scrolling: `clickCentered` waits for stable, visible, hit-tested bounds before each native WebDriver click, while the assertions still read the browser's actual command assignments.

Not covered in Firefox: context-menu saves, the quick save action itself, drag and drop in the popup and real mouse drags, network and AI tools, and the browser favicon cache. The quick save notification's rendering under a strict CSP was checked by hand.

## Unit only

- **Sorting.**
- **Compiled configuration:** `toml-config.test.ts` checks every current TOML file against the original parser, including table prototypes, special keys and numeric values, strict single-owner runtime validation, and a real Vite module graph without the runtime parser; existing config tests retain namespace and schema coverage.
- **Locale messages:** `locale-messages.test.ts` checks identical keys, placeholders, and plural forms across locales, that every literal `t('key')` exists, and that every English key is used (keys built from a prefix are listed in `DYNAMIC_KEY_PREFIXES`).
- **Distribution assets:** `distribution-assets.test.ts` preserves every locale's messages and placeholders while compacting output copies; `provider-logo-assets.test.ts` and provider-catalog tests check exact-byte aliases and output cleanup; `font-coverage.test.ts` guards the fixed Options title in every locale and retains body/mono font coverage.
- **Real installed AI SDKs with HTTP stubs:** `ollama-sdk-contract.test.ts` checks structured output, streaming text/reasoning, tool arguments and HTTP errors after dependency deduplication. This does not prove live Provider compatibility.
- **Distribution size:** `distribution-size.test.ts` validates actual stored/deflated ZIP contents and checksums against the build, raw categories versus payload/overhead, stale/unsafe/unsupported archives, strict budgets and all three manifest targets. `size:check` runs after packaging in the existing three `Build Extension` checks; see `extension-performance`.
- **Storage layer:** the registry (key names, no key literals in `src`, secrets never synced), the `{ v, data }` envelope with migrations and read-only newer versions, writes from two module instances under Web Locks, and removal of unregistered keys on install and update (no E2E test; QA drove it by relaunching a persistent profile on a copy of the build with a higher manifest `version`).
- **Popup logic:** AI folder suggestion normalization (percent confidences, malformed items, an empty list, existing or new checked against the tree, and duplicates), recent chip labels, the held match order, tree drops in a sorted view, and popup saves, new folders, and drops recorded in the undo history.
- **Quick save notification:** the visibility check, the document binding, the counter-zoom, the language direction, and the failure actions.
