# Browser-extension feature testing

1. Confirm the checkout and read its applicable `AGENTS.md` files, feature code, test scripts, and browser-extension build configuration. Preserve unrelated working-tree changes.
2. Turn each requested behavior into observable acceptance criteria. Use focused unit tests for pure logic and the repository's browser end-to-end harness for UI-to-extension-API behavior. Assert the resulting state, not merely that a control was clicked.
3. Run mutating tests in a disposable browser profile with synthetic data. Never point automated tests at the user's installed profile, bookmarks, or settings. Make external network or AI behavior deterministic when it is in scope.
4. During development, rerun the narrowest relevant test. Before handing off a substantive change, run the applicable repository-required lint, build, unit, and end-to-end checks. Discover exact commands from the current project rather than assuming a particular package manager, runner, or output path.
5. On an end-to-end failure, inspect available traces, screenshots, logs, and the built extension, then fix and rerun the relevant check. A passing suite in one browser does not establish runtime behavior in another; a successful build is not an end-to-end test.
6. Report exact commands and results, behaviors asserted, browser/runtime coverage, and untested or blocked cases. Do not call a feature implemented solely because a placeholder control exists or an unrelated test passes. Check that user-facing settings actually affect the behavior they claim to configure.

For WXT projects, consult the current [WXT end-to-end testing guide](https://wxt.dev/guide/essentials/e2e-testing.html) when changing test setup; adapt it to existing fixtures rather than replacing them by default.

## Current coverage in Bookmark Scout

The map of what the unit, Chromium, Edge, and Firefox suites prove is `references/coverage.md`, one bullet per area. Read it before claiming something is covered, and update the bullet for your area in the same PR as the tests (one line per bullet, so parallel PRs extending different areas merge cleanly). Live network behavior and real provider compatibility are not covered.

Line coverage of the unit suite is measured, not the map's claims: `nx run extension:test:coverage` (V8 through `@vitest/coverage-v8`) fails when a folder falls under its floor in `apps/extension/build/unit-coverage.toml`, and CI posts the per-folder table in the `Extension Unit Tests` job summary with the HTML report as the `unit-coverage` artifact. For the pages and the background, `nx run extension:test:e2e:coverage` runs the Chromium suite on a source-mapped build in `dist-coverage/` (never the maintainer's `dist/`) and reports, through monocart, the lines of `src/` the pages and the background service worker ran (`coverage/e2e/index.html`; table with `bun scripts/coverage-summary.ts e2e`). The worker is reached over a DevTools port the browser opens in that mode, from when its test starts, so its own startup and a worker a test stops are not seen, nor a page a test closed itself. On 2026-10-21 it measured 91.1% of the lines loaded, with `src/services` lowest (88.8%); pages alone had been 87%. Use the unit report to find untested branches in `src/lib` and `src/services`; components and hooks show low numbers there because the Playwright suites cover them, which V8 unit coverage does not see. Raise a floor in the same PR as the tests that lift it.

Real providers are checked separately and on demand: `nx run extension:test:live` (`apps/extension/tests/live/README.md`, the `Live AI` workflow) runs popup folder suggestions, AI quick save, Ask AI with an approved move and undo, Auto-Tagging, Summarizer, and AI reorganization against the provider in the `BS_LIVE_AI_*` variables, and checks the API key stays out of synced storage and the AI activity log. It asserts outcomes, not model text; without the variables every test skips.

Performance is measured separately, not asserted by the E2E suites: `nx run extension:test:perf` (`apps/extension/tests/perf/`) times opening, actions, and scrolling in the popup, manager, and Options on a 19,500-bookmark library at 4x CPU throttling, nightly in the `Performance` workflow. It is Chromium-only. Selectors there must count only visible elements, because collapsed panels keep their rows in the page, and an action must be checked against text inside its own region, not anywhere on the page (the folder tree repeats folder names). How to profile, compare, and set budgets: the `extension-performance` skill.

## Lessons from past runs

- **Ground truth over UI.** Verify outcomes through the extension APIs (`chrome.bookmarks`, `chrome.storage`) from the service worker (`serviceWorker.evaluate`) or from files on disk (downloads, exports), not only through what the page renders.
- **Settings must change behavior.** For every setting a feature claims to honor, flip it in storage and assert the behavior changes. Several settings in past audits were saved correctly but never read.
- **Network features need a real server.** Playwright route mocks bypass CORS, so they hide "blocked by CORS policy" failures. Run dead-link or metadata-style features against a local HTTP server that sends no CORS headers.
- **Permission prompts cannot be answered headless.** Pre-grant optional permissions in a copy of the build (`grantWebHostAccess`, `grantPermissions: ['tabs']`), or stub `permissions.request` for the denied path, and report the live prompt as a manual check. Chrome grants a permission without a warning (`contextMenus`) silently, so that request can run for real; revoke with `chrome.permissions.remove` from the service worker to test the revoked path.
- **Assert exact templated text.** Match full user-facing strings such as `Deleted "News". Undo within 10 seconds.` so missing placeholder substitutions fail tests. Use `exact: true`; toast libraries render screen-reader copies that make loose text matches ambiguous.
- **Locale parity.** Keep a unit test that every locale has identical keys and placeholders and that every literal `t('key')` exists. New strings go into every locale in the same change.
- **Untrusted text is data.** Include a test that a title such as `<img src=x onerror=alert(1)><style>*{display:none}</style>` renders literally. Never render user data through `dangerouslySetInnerHTML`.
- **Avoid timing-coupled assertions.** Do not assert exact call counts that depend on async scheduling; wait for the queue to settle, then assert the final state.
- **Flakiness check.** Run each new end-to-end test at least three times before handing off.
- **Destructive paths.** For delete, dedupe, import, and cleanup flows, assert exactly which items were removed or kept, and test undo, partial failure, and stale previews (the item changed after the preview opened).
- **Prove the test catches the bug.** Run the new test once against the unfixed build and confirm it fails, then against the fix. A test that passes on both proves nothing. Agents skip this step unless it is spelled out, so do it this way: commit, then `git checkout origin/main -- apps/extension/src apps/extension/public/_locales` plus any `apps/extension/config/` file you changed (the strict config loader rejects a new key on old source), keep `tests/`, rebuild, run only the new specs and expect them to fail, then `git checkout HEAD -- <the same paths>` and confirm `git status` is clean. Say in the PR that you did.
- **Wall-clock bounds in unit tests.** Bound time only to catch a complexity blow-up, at about 5x the measured CI time, with a comment saying so: a 1,000 ms bound in `tests/unit/folder-ranking.test.ts` passed at 214 ms locally and failed at 1,035 ms on a CI runner. Real speed is measured by `extension-performance`, not by unit tests.
- **Wait for the previous command's result before the next key.** A paste could read the clipboard before Copy stored it. Wait for the toast or the stored state between steps (PRs #641, #648); a fixed sleep is not a fix. Undo and redo keys pressed during a step now wait their turn instead of being dropped (only a held key's repeats are), because a quick Ctrl+Z then Ctrl+Shift+Z lost the redo for users too.
- **Specs are not type-checked.** `extension:typecheck` covers `src` only (`apps/extension/tsconfig.json`), so a wrong field name in a spec shows up only at run time. Run the spec, and when you change a shared helper's signature, grep its callers.
- **Measure layout after transitions settle.** Sidebars and dialogs animate. Wrap geometry checks (`getBoundingClientRect`, `scrollWidth > clientWidth`) in `expect.poll` so a one-shot measurement mid-transition does not pass locally and fail in CI.
- **Firefox smooth scrolling before native clicks.** Geckodriver's visible check does not require an element to be in the viewport, and `scrollIntoView` returns before the application's smooth scroll ends. `clickCentered` in `tests/e2e-firefox/smoke.spec.ts` scrolls once, polls consecutive stable bounds and a viewport hit test, then uses the native click; it re-centers after a layout change and retries only intercepted, not-interactable, or stale-element errors. Keep application motion and browser sandboxing intact, retain the resulting API-state assertions, and repeat the affected spec at least three times on the minimum supported Firefox version as well as running the current-version smoke suite. Fixed sleeps, DOM `.click()`, or disabling smooth scrolling conceal the race.
- **Clipped text.** For tooltips, cells and toasts, assert `scrollWidth <= clientWidth` and `scrollHeight <= clientHeight` on the text element. Inline popovers inherit ancestor `whitespace-nowrap` and `overflow` styles, which is how the toolbar tooltip got cut off.
- **Theme versus OS.** Tailwind v4 `dark:` follows `prefers-color-scheme` unless the CSS declares `@custom-variant dark (&:where(.dark, .dark *));`. Test with `page.emulateMedia({ colorScheme })` set opposite to the app theme.
- **Toast assertions.** Toasts are Base UI, kept as `role="status"`, inside a region named `Notifications (F6)`. Use `toastRegion(page, label)` from `tests/e2e/fixtures.ts` (the label is localized) instead of an unscoped `getByText`.
- **Base UI timing.** Dialogs unmount one frame after closing, so wait for the dialog to be hidden instead of asserting at once. Once a Select has opened, its `[role=listbox]` stays in the page for good inside a hidden `data-closed` popup, so `getByRole('option')` can match an invisible option (look options up inside the visible listbox), and a check for "is any menu open" must ignore hidden, inert, and `data-closed` overlays the way `hasOpenOverlay` (`src/lib/keyboard-shortcuts.ts`) does. Counting every `[role=listbox]` blocked every manager shortcut after Rows per page was changed (PR #641); `waitForNoOverlay` in `tests/e2e/manager-helpers.ts` still counts them, so call it before opening a Select.
- **Reduced motion is on.** `tests/e2e/fixtures.ts` sets `reducedMotion: 'reduce'`. A test about an animation must call `page.emulateMedia({ reducedMotion: 'no-preference' })` first. To catch a one-frame flash, sample `getComputedStyle(el).opacity` on every `requestAnimationFrame`.
- **Hover transforms.** Before measuring geometry, move the pointer away (`page.mouse.move(0, 0)`) and wait for transitions; a 1% hover scale once failed a 0.07px check on `main`. Do not loosen the tolerance.
- **Mock the endpoint the SDK really calls.** Switching custom providers to `@ai-sdk/openai-compatible` moved requests from `/responses` to `/chat/completions` and broke a mocked test.
- **Unit-test language.** `getSettings()` in unit tests resets the language to `auto`, and the fake browser then makes `t()` return raw keys. Call `saveSettings({ language: 'en' })` and then `setLanguage('en')`.
- **Parallel-safe tests.** The suite runs `fullyParallel` on several workers (locally half the cores up to 4, on CI 2 per shard; `PW_WORKERS` or `--workers` overrides), so any test can run next to any other, in any order, in any worker. Launch the browser only through the `context` fixture (a fresh profile under `testInfo.outputPath`). Write files only under `testInfo.outputPath(...)` or a `workerTempDir(...)` folder from `tests/e2e/temp-dirs.ts`, never a fixed path or the system temp folder, and remove scratch folders in fixture teardown (`removeTempDir`); the suite's global teardown removes any browser profile or build copy left behind and fails a run in which no attempt failed (it once left dozens of build copies and 2.8 GB of profiles per run; a browser launch that hangs until the test timeout skips teardown, so after a failed attempt leftovers are only reported). In a test that waits on the popup search, wait for the filtered tree (`mark` highlights) before measuring rows: the filter is debounced, and a drag measured before it landed dropped in the wrong place under load. Start local servers with `listen(0, '127.0.0.1')` and read the port back; never a fixed port. Close them with `server.close()` plus `server.closeAllConnections()`: the browser keeps connections alive, so a plain `close()` hung `afterEach` for its full timeout, on CI only (PR #612; see `tests/e2e/quick-save-helpers.ts`). One exception to the folder rule: the bridge spec puts the native host's launcher under the system temp folder on purpose (`mcp-bridge-change`). Keep per-test state in `beforeEach`/`afterEach` or the test itself, not in `beforeAll` or module variables another test depends on, and never assume an earlier test seeded or cleaned anything. Check a new spec with `--repeat-each=3 --workers=4` before handing off.
- **One Playwright run per worktree.** Two concurrent runs in the same worktree fail with a trace-file `ENOENT`. Never stop a run with a pattern that could match another worktree's run (`pkill -f "playwright test"` once killed a parallel agent's suite); include your worktree path in the pattern, or stop the process you started by its PID.
- **After resolving a conflict in a spec,** run `bunx playwright test --list <spec>` before pushing. A merge once dropped a test's closing `});`; Playwright then reported only "No tests found", which an output filter for `passed|failed` hid, and the broken merge was pushed.
- **Unresolved auto-imports.** After a build, run `scripts/scan-unresolved-imports.ts` (usage in its header). It catches imports WXT failed to inject, which lint, `tsc`, and unit tests all miss. It also flags an export whose name is used elsewhere as an object property or a third-party name (`canOpenPrivateWindows`, `ContextMenu`); renaming the export cleared those (PR #623).
- **Painted result.** Computed style cannot show a `filter` on `<html>` recolouring a top-layer element; sample a screenshot pixel (`pixelAt` in `tests/e2e/quick-save-helpers.ts`).
- **Waiting on a suite.** A background waiter that greps Playwright output for the summary can miss it, because the reporter colours its text. Wait on the command's exit code, or run with `NO_COLOR=1` (or `--reporter=line`) and give the waiter a timeout longer than the suite. When the machine is under load, lower the workers (`PW_WORKERS=2`) instead of starting several runs: 8 workers at load 30 were slower than 4 and timed out starting a browser. If you do run shards side by side, give each its own `--output` folder: runs sharing `test-results/` collided on trace files and reported false failures.
- **Settings matrix.** `tests/settings-matrix.ts` maps every setting to its consumer file and exact test titles, and a unit test fails when they drift. Adding a setting or renaming a referenced test means updating the matrix in the same change.
- **Native UI the browser hides.** Context menus cannot be clicked by Playwright; dispatch `chrome.contextMenus.onClicked` from the service worker with realistic `info` and `tab` objects. Keyboard commands the same way: `chrome.commands.onCommand.dispatch(name, tab)` (`pressShortcut` in `tests/e2e/quick-save-helpers.ts`). Playwright cannot press a browser accelerator: `page.keyboard.press` never reaches `commands.onCommand`, not even for the extension's own Alt+Shift+S. It can drive `chrome://extensions/shortcuts` and record a real key there, which is how a test sets a real shortcut (`tests/e2e/shortcut-setup.spec.ts`). Chrome cannot clear a shortcut from a test, so a "no key set" state is faked by wrapping `chrome.commands.getAll` in the page with `addInitScript`. "The browser reports the key" is not "the key works": Firefox reports a Ctrl+D it never delivers, and Chrome silently leaves a conflicting suggested key unset; record the real key press as a manual check. A dispatched command grants no `activeTab`, so a test that injects into the page uses `grantWebHostAccess` in its place, and one without it covers the page-cannot-show-it path. Drag and drop works with stepped `page.mouse` moves: Chromium sends `dragover` only on a move inside the target, so a hover that must last (a tree folder opening) moves a few steps over it. Drops from other apps are scripted: dispatch `dragover` and `drop` with one `new DataTransfer()` holding the data. Chromium's `getData()` returns `''`, not `undefined`, for a missing type, so a `??` chain of types never reaches its fallback (use `||`), and dropped data cannot be read during `dragover`, only on drop. Ctrl/Cmd+C, X, and V reach the page as `copy`, `cut`, and `paste` events in Chromium, also on macOS.
- **Closed shadow roots.** Playwright selectors cannot enter the quick save notification's closed shadow root. Read it from the browser's accessibility tree (`Accessibility.getFullAXTree` over a CDP session) and click its buttons with `page.mouse` at the center of `DOM.getBoxModel` for the node's `backendDOMNodeId`; that is real input, so the notification's `isTrusted` check passes (`readToast` and `clickToastButton` in `tests/e2e/quick-save-helpers.ts`).
- **Other browsers.** Edge runs the Chromium suite (Playwright `msedge` channel still honors `--load-extension` as of Edge 154). Firefox cannot: Playwright's Firefox never commits a `moz-extension://` navigation and its BiDi mode rejects it, so `tests/e2e-firefox/` uses geckodriver with `--allow-system-access`, a temporary add-on with an explicit gecko ID, and a fixed UUID from `extensions.webextensions.uuids`. Never type one browser's words in a spec: Edge says "Favorites bar", "Other favorites", and "InPrivate", uses `edge://` links, and sends `browser: 'edge'` to the MCP bridge. Take names from `seedFolder()`'s `barTitle` (`tests/e2e/popup-helpers.ts`) or ids, and browser identity from the `extensionBrowser` fixture; four Edge E2E failures in one series came from literals (PRs #621, #623, #625, #648). When every Firefox test fails with `Test timeout of 60000ms exceeded while setting up "extension"`, check for a hung `selenium-manager` process: it resolves geckodriver over the network on each run. Rerun with `SE_OFFLINE=true` to use the cached driver in `~/.cache/selenium`. Firefox limits: the background page cannot be scripted through geckodriver (so context-menu tests do not port), the real sidebar cannot be opened by automation, and `find()` waits for visibility, so read hidden text with `executeScript`. Locally, run Chromium and Firefox only; Edge is covered by the required `Edge E2E` CI check, so do not list it as an unrun risk.
- **Failures under load.** When one test fails in a full run while other suites or worktrees are also running, rerun it alone with `--repeat-each` before investigating; it is usually load (one test passed 12 of 12 alone). Run at most one full E2E suite on the machine at a time.
- **Flaky tests on CI.** CI does not retry (it did until 2026-10-21, which hid flakes and cost the rerun): a test that fails once fails the run, so fix it rather than rerun it. The **Weekly reports** workflow runs `scripts/ci-flaky-tests.ts` over the last hundred CI runs and puts the ranking in its job summary. `scripts/ci-flaky-tests.ts` (usage in its header) ranks the tests that failed in recent CI runs, retried or not, with the line each stopped at; pick from it rather than re-running suites to find one. Reproduce with `--repeat-each=40 --workers=8` (most CI-only flakes show 1 to 3 times in 40 locally), fix the cause, and show the same run passing. Half of the 2026-10-21 batch were product bugs, not test timing: a redo pressed during an undo was dropped, an outside change made while recording was paused was recorded live when recording came back on before the event's turn, and a tab panel being left stayed visible for one frame next to the new one. The rest were reads of state an async step was still writing (a restored folder appears before its contents), a window that closes itself during the click that answers it, and toasts restacking under the pointer (`dispatchEvent('click')` when the test is not about pointing).
- **Opt-in real-server specs** skip, not fail, when their environment variables are missing, so the normal suite stays green; report them as "N skipped".
- **Secrets in live runs.** Never print a real key: store it with `seedAIServices` instead of typing it into a page, compare it inside the browser (`expectKeyKeptPrivate` in `tests/live/live-helpers.ts`) so a failed check cannot echo it, keep traces and screenshots off, and print through `tests/live/redacting-reporter.ts`, because the built-in reporters print an assertion's received page text as is. Several tool runs leave several toasts with Undo; scope a toast button to its toast's title. Have the user write the key file through a hidden prompt (`read -rs`), not a clipboard one-liner: copying the command replaced the key on the clipboard and the file got the command text. Check the file by permissions and key length only. Take the model id from the provider's own `/models` list (a proxy listed `-high` variants only), and leave reasoning models room: they spend output tokens on reasoning even for a one-word answer.
- **Stored data.** Seed and read storage only through `tests/e2e/storage.ts` (end to end) or `tests/unit/storage-helpers.ts` (unit), which take the key and the `{ v, data }` envelope from the registry; a raw `chrome.storage` write under a spelled-out key is ignored by the extension. Older releases' keys are removed on update, not migrated, so there is no old data to keep loading. To prove a cross-page race is fixed, make each page's storage read return late with the value it had when the read began (a delay before the real read hides the race), and check the test fails on a build without the fix. Keep secrets such as API keys out of sync storage.
