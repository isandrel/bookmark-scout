description: 掃描書籤中的失效連結、查看哪些需要手動檢查，並透過刪除、追蹤重新導向、使用封存副本或編輯網址來修復。

「**檢查失效連結**」位於書籤管理員「**工具**」側欄的「**維護**」下。這項工具會要求每個已加入書籤的網頁，確認是否仍可載入。

<Callout title="Firefox">
在 Firefox 中，請從彈出式視窗中的「**開啟書籤管理員**」開啟書籤管理員。
</Callout>

## 執行掃描 [#run-a-scan]

<Steps>
<Step>
在「**檢查失效連結**」的範圍選單中選擇目前資料夾或所有書籤，然後按一下「**掃描**」。
</Step>
<Step>
第一次使用時，Bookmark Scout 會說明為何需要網站存取權。按一下「**允許存取**」，然後接受瀏覽器的提示。如果你選擇「**暫時不要**」或拒絕，就不會掃描任何內容。
</Step>
<Step>
等待結果。頂端的摘要會統計確定失效、需要手動檢查和已重新導向的連結數量。
</Step>
</Steps>

網站存取權為選用項目，安裝時不會授予。要求傳送時不會附帶 Cookie，而且你可以在瀏覽器的擴充功能設定中撤銷存取權。請參閱「[權限](/permissions)」。

## 解讀結果 [#read-the-results]

| 結果 | 意義 |
| --- | --- |
| **確定失效** | 找不到網頁 (404 或 410)、連線遭拒、找不到主機，或重新導向形成迴圈 |
| **需手動檢查** | 在瀏覽器中通常仍可正常使用：需要登入或拒絕存取 (401、403、407)、要求次數受到限制 (429)、網站拒絕自動檢查 (405 或 501)、伺服器錯誤 (5xx)、其他 HTTP 錯誤，或逾時 |
| **已重新導向** | 連結可以使用，但現在指向其他位置；會顯示目的地 |
| **已略過** | 不是網頁連結，例如書籤小程式 (bookmarklet) |

`HEAD` 要求發生任何錯誤時，系統都會先以 `GET` 要求確認後才回報，因為部分伺服器不支援 `HEAD`。

<Callout type="info" title="Chrome 中的主控台訊息">
每個失敗的要求，Chrome 都會在網頁的開發人員主控台中記錄一行「Failed to load resource」。擴充功能無法隱藏這些訊息；掃描本身不會記錄任何內容。
</Callout>

## 修復連結 [#repair-links]

<Steps>
<Step>
按一下「**確認修復項目**」。所有失敗、逾時或已重新導向的連結都會列出。
</Step>
<Step>
為每個連結選擇處理方式：

- 「**維持不變**」(預設選項，因此除非你選擇其他選項，否則不會有任何變更)
- 「**刪除書籤**」
- 「**使用重新導向的目的地**」，只有在掃描時偵測到重新導向才會提供
- 「**使用封存副本 (Wayback Machine)**」，會將書籤指向 `https://web.archive.org/web/<original URL>`。這個連結是在本機產生且未經檢查，因此該網頁可能從未被封存。
- 「**編輯網址**」，只接受與目前網址不同的有效 `http` 或 `https` 網址
</Step>
<Step>
確認摘要中將刪除、替換網址和保留的書籤數量，然後按一下「**套用**」。
</Step>
</Steps>

在你套用之前，不會有任何變更。每次變更前，系統都會重新讀取書籤：掃描後已被刪除或編輯的書籤會被略過並列出，因此過時的掃描結果絕不會覆寫較新的編輯。

訊息中的「**復原**」(或部分套用後對話方塊中的「**復原**」) 可在 10 秒內還原已刪除的書籤，並將已替換的網址改回原本的網址 (除非這些網址之後又被編輯過)。

## 調整掃描 [#tune-the-scan]

在「[設定](/settings)」的「**維護**」分頁中：

| 設定 | 預設值 |
| --- | --- |
| **要求逾時** | 每個要求 8 秒 |
| **同時要求數** | 同時 4 個要求 |
| **重試次數** | 重試 1 次 |
| **追蹤重新導向** | 開啟 |
| **成功狀態碼** | 200, 201, 202, 204, 301, 302, 307, 308 |
