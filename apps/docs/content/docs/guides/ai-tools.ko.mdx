AI 기능은 **선택 사항이며 기본적으로 꺼져 있습니다**. Bookmark Scout는 AI 없이도 모든 기능을 사용할 수 있습니다. Bookmark Scout에는 자체 AI 서비스가 없습니다. AI를 사용하려면 다음이 필요합니다.

- **AI 회사의 계정**: OpenAI, Anthropic, Google 같은 회사의 계정입니다. 설정에서는 이 회사를 **제공업체**라고 부릅니다. 대부분의 제공업체는 사용할 때마다 보통 적은 금액을 청구하므로, 시작하기 전에 요금을 확인하세요. Ollama처럼 내 컴퓨터에서 실행하는 AI 프로그램은 무료지만 꽤 성능이 좋은 컴퓨터가 필요합니다.
- **API 키**: 그 회사의 계정 페이지에서 받는 비밀 코드로, Bookmark Scout가 내 계정을 사용할 수 있게 해 줍니다. 비밀번호처럼 남에게 알려 주지 마세요.

**모델**도 고릅니다. 모델은 회사가 제공하는 AI 버전으로, 더 빠른 모델이나 더 똑똑한 모델 등이 있습니다. AI가 켜져 있으면 요청은 내 키로 브라우저에서 내가 고른 제공업체로 바로 전송됩니다.

<Callout type="warn" title="AI를 켜기 전에">
AI 도구는 북마크 제목, URL, 폴더 이름이나 경로를 설정한 제공업체로 보냅니다. 제공업체는 자체 약관에 따라 이 데이터를 처리하며, API 사용에는 비용이 들 수 있습니다. 모든 제안은 적용하기 전에 검토하세요.
</Callout>

## AI 켜기 [#turn-on-ai]

<Steps>
<Step>
Bookmark Scout 설정을 열고(Chrome에서는 툴바 아이콘을 마우스 오른쪽 버튼으로 클릭하고 **옵션** 선택) **AI** 탭으로 이동합니다. 서비스를 설정하기 전까지는 맨 위의 **AI는 선택 사항입니다** 상자에서 AI로 할 수 있는 일, 필요한 것, 들 수 있는 비용, 전송되는 내용을 요약해 보여 줍니다.
</Step>
<Step>
**AI 기능**을 켭니다.
</Step>
<Step>
**AI 서비스**에서 **서비스 추가**를 클릭하고 제공업체를 고릅니다. 선택 창에는 잘 알려진 제공업체가 **추천**에 나오고, 이어서 **로컬 서버**와 **사용자 지정**이 나옵니다. 검색창에 입력하면 <strong>기타 제공업체 (models.dev)</strong>에서 약 200개를 더 찾을 수 있습니다. 그런 다음 **AI 모델**을 고릅니다.
</Step>
<Step>
제공업체가 요구하면 **API 키**를 입력합니다. 추천 제공업체는 **(제공업체 이름)에서 API 키 받기**를 클릭하면 로그인 후 키를 만들 수 있는 페이지가 열립니다. 키는 입력란을 벗어날 때 저장되며 이 기기에만 보관됩니다. 제공업체의 키 형식과 맞지 않는 키는 거부되어 저장되지 않습니다.
</Step>
<Step>
선택 사항: **모델 새로 고침**을 클릭해 제공업체의 현재 모델 목록을 불러오거나, **서비스 확인**을 클릭해 제공업체에 연결할 수 있는지, 키가 받아들여지는지, 선택한 모델을 제공하는지 확인합니다. 둘 다 제공업체의 모델 목록을 읽으며, 비용이 들지 않습니다. 서비스 확인은 Azure OpenAI처럼 모델 목록이 없는 제공업체에만 짧은 테스트 프롬프트를 보냅니다. 처음에는 브라우저가 해당 제공업체 주소 하나에 대한 접근 권한을 요청합니다. 새로 고친 목록은 다시 새로 고칠 때까지 모델 선택 창에 유지됩니다.
</Step>
</Steps>

<Screenshot name="options-ai" />

팝업과 사이드 패널의 AI 버튼은 **AI 기능**이 켜져 있고 기본 서비스가 설정되어 있어야(제공업체가 요구하면 키까지) 나타납니다. 그전까지 팝업에는 **AI가 켜져 있지만 아직 설정되지 않았습니다**와 함께 이 탭을 여는 **AI 설정 마치기**가 표시되고, 북마크 관리자의 AI 도구는 비활성화된 상태로 남습니다.

설정은 자동으로 저장됩니다. AI 서비스와 그 API 키, **기본 URL**, <strong>추가 헤더(JSON)</strong>는 이 브라우저의 로컬 저장소에 보관되며 동기화되지 않습니다. AI 사용 여부 같은 다른 AI 설정은 브라우저가 지원하는 경우 브라우저 계정을 통해 동기화됩니다.

## 이 컴퓨터에서 무료로 쓰는 AI [#free-ai-on-this-computer]

Chrome에서는 Bookmark Scout가 **Chrome의 내장 AI**를 사용할 수 있습니다. 내 컴퓨터에서 실행되는 작은 모델(Gemini Nano)로, 계정, API 키, 비용이 필요 없고 어떤 데이터도 컴퓨터 밖으로 나가지 않습니다. 폴더 추천만 합니다.

<Steps>
<Step>
**AI** 탭의 **AI는 선택 사항입니다** 상자 맨 위에 있는 **이 컴퓨터에서 무료**에서 **내장 AI 사용**을 클릭합니다. **내장 AI(이 컴퓨터에서 실행)** 서비스는 **서비스 추가**에서도 맨 처음에 있습니다. 둘 다 Chrome이 모델을 실행할 수 있는 경우에만 표시됩니다.
</Step>
<Step>
**모델 다운로드**를 클릭합니다. Chrome이 한 번만 다운로드하며, 그래픽 카드가 있는 컴퓨터에서는 약 4GB, 없으면 약 2.7GB입니다. 서비스에 **준비되었습니다**가 표시되면 모델이 이 컴퓨터에 있는 것입니다. 다운로드 중에 설정을 닫아도 Chrome이 백그라운드에서 계속 다운로드합니다.
</Step>
<Step>
**AI 기능**이 꺼져 있으면 켭니다. 서비스를 추가해도 AI가 켜지지는 않습니다.
</Step>
</Steps>

- Chrome 138 이상, macOS 13 이상·Windows 10 또는 11·Linux·Chromebook Plus 중 하나, 디스크 여유 공간 22GB, 그리고 메모리가 4GB보다 큰 그래픽 카드 또는 메모리 16GB와 프로세서 코어 4개가 필요합니다. 직접 확인할 필요는 없습니다. 서비스 아래(또는 **이 컴퓨터에서 무료** 상자)의 **이 컴퓨터 확인**이 Chrome 버전, 운영체제, 메모리, 프로세서 코어를 보여 주고, 브라우저에서 확인할 수 없는 항목(디스크 여유 공간과 그래픽 메모리)도 알려 줍니다. Chrome에서 모델을 실행할 수 없다고 하지만 컴퓨터를 제외하는 조건이 없으면 Chrome 플래그를 바로 열 수 있습니다. **Enabled BypassPerfRequirement**로 설정하고 Chrome을 다시 시작한 뒤 **다시 확인**을 클릭하세요. 조직에서 끈 경우 서비스에 그렇게 표시됩니다. Firefox에는 내장 AI가 없습니다.
- 폴더 추천만 하며, 팝업과 사이드 패널, AI 빠른 저장 단축키에서 사용됩니다. AI에게 묻기, 자동 태그 지정, 콘텐츠 요약, AI 폴더 재구성은 켜져 있는 다른 서비스나 새로 추가한 서비스를 사용합니다.
- 페이지의 제목과 주소, 그 페이지에 가장 잘 맞는 폴더 이름(기기에서 고른 짧은 목록), **페이지 내용 읽기**를 켠 경우 페이지 본문의 앞부분을 읽습니다. 답은 그 목록의 폴더로만 합니다.
- 영어, 일본어, 스페인어, 독일어, 프랑스어에서 가장 잘 작동합니다. 모델이 실패하거나 너무 오래 걸리면 대신 기기에서의 단순한 단어 일치로 추천합니다.
- 팝업과 AI 빠른 저장 단축키는 다운로드를 시작하지 않습니다. 모델이 준비될 때까지 팝업은 AI 버튼 대신 **설정에서 내장 AI 모델을 다운로드하세요**를 표시하고, 빠른 저장은 아래의 가장 잘 맞는 폴더를 사용합니다.
- AI 빠른 저장은 저장 후 5분 동안 모델을 준비된 상태로 두어 다음 저장이 더 빠릅니다. 모델이 준비되지 않았거나 실패하거나 너무 오래 걸리면, **최적 일치** 설정처럼 페이지에 가장 잘 맞는 폴더에 저장합니다.
- **요청 기록**을 켜면 각 호출이 **AI 활동**에 **기기에서**로 표시됩니다.

## 여러 서비스 사용 [#use-more-than-one-service]

서비스는 원하는 만큼 저장할 수 있으며, 같은 제공업체의 서비스를 여러 개 저장할 수도 있습니다. 예를 들어 회사용 프록시와 집용 프록시를 각각 별도의 키, 주소, 모델로 저장할 수 있습니다.

- 모든 AI 도구는 **기본** 서비스를 사용합니다. 서비스 메뉴에서 **기본으로 설정**을 선택하거나, 서비스가 두 개 이상 켜져 있으면 팝업의 반짝이 버튼 옆 화살표에서 하나를 고릅니다.
- **내장 AI**는 폴더 추천만 합니다. 내장 AI가 기본 서비스인 동안 다른 AI 도구는 켜져 있는 다른 서비스 중 첫 번째를 사용합니다.
- 서비스의 스위치를 끄면 삭제하지 않고 팝업에서만 숨길 수 있습니다.
- **복제**는 키를 포함해 서비스를 복사합니다. **삭제**는 서비스와 그 키를 이 기기에서 제거합니다. 내장 AI는 한 번만 추가할 수 있으므로 **복제**가 없습니다.
- **기본 URL**, **추가 헤더(JSON)**, OpenAI의 조직처럼 제공업체별 입력란은 **추가 설정** 아래에 있습니다.

**AI 제공자** 선택 창에는 검색창이 있습니다. 추가 제공업체 목록은 확장 프로그램에 포함된 공개 [models.dev](https://models.dev) 카탈로그의 사본에서 가져오므로, 제공업체를 골라도 models.dev에는 아무것도 전송되지 않습니다. 요청은 내가 고른 제공업체로만 전송됩니다.

**기본 URL**은 프록시를 사용할 때처럼 모든 요청에서 제공업체의 주소를 대신합니다. `http://` 또는 `https://`로 시작해야 합니다. <strong>추가 헤더(JSON)</strong>는 모든 요청에 헤더를 추가하며, **사용자 지정 모델**은 임의의 모델 이름을 허용하는 제공업체용 모델 ID를 지정합니다.

### 로컬 서버 [#local-servers]

로컬 서버는 확장 프로그램의 요청을 허용해야 합니다.

- **Ollama:** `OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*`를 설정하고 Ollama를 다시 시작합니다. 이 설정이 없으면 Ollama가 403으로 응답하고, 서비스 확인에서 서버가 확장 프로그램을 거부했다고 표시됩니다.
- **LM Studio:** 서버 설정에서 **Enable CORS**를 켜거나, `lms server start --cors`로 시작합니다.
- **LocalAI:** API 키를 설정합니다. LocalAI의 CSRF 검사는 브라우저에서 키 없이 보낸 요청을 거부합니다.
- **text-generation-webui:** `--api`로 시작합니다.
- **CLIProxyAPI:** 기본 설정 그대로 확장 프로그램의 요청을 허용합니다. **서비스 확인**을 클릭하기 전에 실행하세요. 실행 중이 아니면 서비스 확인에서 `localhost:8317`에 연결할 수 없다고 표시됩니다.

### 확인에 실패했을 때 [#when-a-check-fails]

서비스 확인과 모델 새로 고침은 가능성이 높은 원인을 알려 줍니다: 키 거부(401, Google과 xAI는 400), 잘못된 기본 URL(404), 제공업체의 요청 빈도 제한(429, 이 경우 키는 정상), 서버가 확장 프로그램의 출처를 거부함, 8초 안에 응답 없음, 해당 주소가 제공업체 API를 제공하지 않음.

## 나만의 프롬프트 작성 [#write-your-own-prompts]

각 AI 도구는 기본 제공 프롬프트로 시작합니다. 도구의 동작 방식을 바꾸려면 **옵션**, **AI 도구**, **프롬프트** 순서로 이동합니다.

1. 도구의 기본 제공 프롬프트를 먼저 읽으려면 옆의 눈 아이콘을 클릭합니다. 여기나 보기 화면에서 **사용자 지정**을 클릭하면 기본 제공 프롬프트가 들어 있는 편집기가 열립니다.
2. 텍스트를 편집합니다. `{{maxTags}}` 같은 변수를 클릭하면 삽입되며, 도구가 설정 값으로 채웁니다. **현재 설정으로 미리 보기**로 결과를 확인할 수 있습니다.
3. **프롬프트 저장**을 클릭합니다. 새 프롬프트가 해당 도구의 프롬프트가 됩니다.

도구마다 여러 프롬프트를 전체 10개까지 보관하고 도구의 메뉴에서 바꿔 쓸 수 있으며, <strong>기본값(기본 제공)</strong>을 고르면 원래 프롬프트로 돌아갑니다. 내 프롬프트는 브라우저 계정을 통해 기기 간에 동기화되므로, 각 프롬프트는 7 KB 미만이어야 합니다. Bookmark Scout는 내 프롬프트 뒤에 자체 출력 형식 규칙을 덧붙이므로, 프롬프트가 다른 형식을 요청하더라도 결과는 정상적으로 불러옵니다.

## 도구별 전송 데이터 [#what-each-tool-sends]

| 도구 | 위치 | 제공업체로 보내는 내용 |
| --- | --- | --- |
| 폴더 추천 | 팝업, 검색창 옆의 반짝이 버튼(AI가 켜져 있을 때만 표시) | 현재 페이지의 제목과 URL, 북마크 폴더 이름. **페이지 내용 읽기**가 켜져 있으면 페이지 본문도 전송. 내장 AI를 쓰면 아무것도 컴퓨터 밖으로 나가지 않음 |
| **자동 태그 지정** | 관리자, 도구, **AI** | 현재 폴더에 있는 북마크의 제목, URL, 폴더 경로. **페이지 내용 읽기**가 켜져 있으면 각 페이지의 본문도 전송 |
| **콘텐츠 요약** | 관리자, 도구, **AI** | 현재 폴더에 있는 북마크의 제목, URL, 폴더 경로. **페이지 내용 읽기**가 켜져 있으면 각 페이지의 본문도 전송 |
| **AI 폴더 재구성** | 관리자, 도구, **AI** | 선택한 범위에 있는 북마크의 제목, URL, 폴더 경로 |
| **AI에게 묻기** | 팝업과 사이드 패널, 검색창 옆의 채팅 버튼(AI가 켜져 있을 때만 표시) | 내 메시지와 지금까지의 대화, 그리고 조회하는 내용: 일치하는 북마크(폴더, 추가한 날짜, 태그, 요약 포함), 폴더 이름, 현재 페이지의 제목과 URL, AI가 확인한 북마크 링크가 아직 작동하는지 여부, **페이지 내용 읽기**가 켜져 있으면 읽는 페이지의 텍스트 |
| **AI 컨텍스트 패커** | 관리자, 도구, **AI** | 없음. 내 컴퓨터에 파일을 저장하며, AI가 꺼져 있어도 동작합니다. |

**열 때 자동 추천**을 켜면 팝업을 열 때마다 폴더 추천을 요청합니다. 꺼 두면 버튼을 클릭할 때만 요청을 보냅니다.

## 페이지 내용 읽기 [#read-page-content]

제목과 URL만으로는 페이지의 내용을 알 수 없을 때가 있습니다. **옵션**, **AI** 순서로 이동해 **페이지 내용 읽기**를 켜면 폴더 추천, **자동 태그 지정**, **콘텐츠 요약**이 각 페이지의 본문도 보냅니다. 켜면 웹사이트 접근 권한을 요청하며, 거부하면 꺼진 상태로 유지됩니다.

- Bookmark Scout가 각 페이지를 쿠키 없이 직접 내려받으므로, 로그아웃 상태의 사이트 내용을 받게 됩니다. 메뉴, 스크립트, 이미지, 링크 주소를 제외한 본문 텍스트만 남깁니다.
- 페이지마다 최대 약 3,000자를 보내며, 도구를 한 번 실행할 때 최대 40개 페이지를 읽습니다. 큰 폴더에서 그 이후의 북마크와 열리지 않는 페이지는 제목과 URL만 보냅니다.
- `localhost`, 사설 IP 주소, `.local` 이름 같은 로컬 네트워크의 페이지는 읽지 않으므로, 인트라넷 페이지가 클라우드 제공업체로 전송되지 않습니다.
- 페이지 텍스트는 웹에서 가져오므로 AI를 겨냥한 지시가 들어 있을 수 있습니다. Bookmark Scout는 모델에게 이를 데이터로만 취급하도록 지시하며, 모든 제안은 저장하기 전에 직접 검토하게 됩니다.

## AI에게 묻기 [#ask-ai]

팝업이나 사이드 패널에서 검색창 옆의 채팅 버튼을 클릭하면 북마크, 보고 있는 페이지, 또는 그 밖의 무엇이든 물어볼 수 있습니다. 기본 AI 서비스를 사용하며, 머리글의 메뉴에서 서비스를 바꿀 수 있습니다.

- AI는 답하기 위해 북마크를 검색하고(폴더, 태그, 사이트, 추가한 날짜로도 검색), 폴더 목록을 확인하고, 북마크의 태그와 요약을 조회하고, 중복을 찾고, 페이지에 맞는 폴더를 제안하고, 현재 페이지를 확인하며, **페이지 내용 읽기**가 켜져 있으면 북마크한 페이지나 열려 있는 페이지를 읽을 수 있습니다(다른 페이지는 읽지 않음). 모든 웹사이트에 대한 접근을 허용했다면(20개가 넘는 사이트에서 깨진 링크 확인을 실행하거나 **페이지 내용 읽기**를 사용하기 위해), 북마크한 링크가 아직 작동하는지도 확인할 수 있습니다. 요청하면 페이지를 저장하고, 북마크를 옮기거나 이름을 바꾸거나 삭제하고, 폴더를 만들 수도 있습니다. 이런 변경은 먼저 계획으로 보여 주며, 채팅에서 승인하기 전에는 아무것도 바뀌지 않습니다. 웹 페이지를 읽은 뒤에는 저장하기 전에도 확인을 요청합니다. 모든 변경은 한 단계로 되돌릴 수 있으며, 북마크 관리자에서 <Shortcut id="manager.undo" />로도 되돌릴 수 있습니다. AI가 수행하는 각 단계가 채팅에 표시됩니다.
- 일부 답변 아래에는 다음에 할 일을 제안하는 버튼이 표시됩니다. 후속 질문하기, 몇 가지 선택지나 아이디어 중 고르기, 제안된 폴더에 페이지 저장하기, 북마크 열기 또는 보기 등입니다. 클릭하기 전에는 아무 일도 일어나지 않으며, 각 버튼은 한 번만 작동하고, 저장은 알림에서 되돌릴 수 있습니다.
- 저장 버튼에는 폴더 이름과 그 아래에 페이지 제목과 사이트가 표시되며, 마우스를 올리면 전체 주소를 볼 수 있습니다. 저장 버튼은 보고 있는 페이지, AI가 북마크에서 찾았거나 읽은 페이지, 직접 입력한 주소만 제안하며, 웹 페이지의 텍스트에만 나오는 주소는 제안하지 않습니다. 채팅에서 웹 페이지를 읽었거나 웹을 검색한 뒤에는 버튼을 클릭하면 먼저 그 페이지를 그 폴더에 저장하는 것을 승인하도록 요청합니다.
- OpenAI, Anthropic, Google Gemini, xAI는 웹도 검색할 수 있습니다. 메시지 입력란 옆의 지구본 버튼으로 켜며, 켜기 전까지는 꺼져 있고 검색은 제공업체가 직접 수행합니다.
- 대화는 채팅이 열려 있는 동안에만 유지됩니다. **새 채팅**을 누르면 대화가 지워지고, 팝업을 닫으면 대화가 끝납니다.
- AI가 따르는 지시는 프롬프트 라이브러리의 **AI에게 묻기** 프롬프트이므로, 다른 프롬프트처럼 보거나 바꿀 수 있습니다.
- **옵션**, **AI** 순서로 이동하면 나오는 **AI에게 묻기가 할 수 있는 일**에 AI에게 묻기가 할 수 있는 모든 조회와 변경이 나열됩니다. 끈 작업은 AI에게 묻기에 아예 제공되지 않습니다. 변경 계획을 적용할 때는 항상 먼저 확인합니다.
- 개발자용: Claude Code 같은 이 컴퓨터의 AI 에이전트도 같은 조회와 변경을 사용할 수 있습니다. [로컬 AI 에이전트와 함께 사용](/guides/local-agents)을 참고하세요.

## 전송된 내용 확인 [#see-what-was-sent]

도구가 정확히 무엇을 보냈고 제공업체가 무엇을 답했는지 확인하려면 **옵션**, **AI** 순서로 이동해 **AI 활동** 아래의 **요청 기록**을 켭니다. 그러면 각 AI 호출의 출처, 주소, 상태, 시간이 표시되며, 항목을 열어 요청 헤더와 요청 및 응답 본문을 보거나 버그 보고용으로 JSON으로 복사할 수 있습니다.

기록은 기본적으로 꺼져 있습니다. 로그는 이 기기에만 보관되며 가장 최근 호출만 유지합니다. API 키, 이름으로 보아 자격 증명으로 보이는 헤더(`key`, `token`, `secret`, `auth`, `cookie`가 포함된 헤더 등), <strong>추가 헤더(JSON)</strong>에 설정한 모든 헤더는 저장하기 전에 `[redacted]`로 바뀝니다. 하지만 요청에 들어 있는 북마크 제목과 URL은 그대로 남으므로, 확인이 끝나면 기록을 끄세요. 끄면 로그도 삭제됩니다.

## 폴더 추천으로 페이지 저장 [#save-a-page-with-a-folder-recommendation]

팝업에서 반짝이 버튼을 클릭합니다. 추천된 기존 폴더를 고르면 페이지가 그곳에 저장됩니다. 추천된 새 폴더를 고르면 전체 경로와 페이지가 표시된 **새 폴더 검토**가 열리며, **폴더를 만들고 저장**은 없는 폴더만 만들고 페이지를 저장합니다. 페이지가 이미 그 폴더에 있으면 다시 저장하지 않으며, 경로에 있는 폴더 이름 중 하나를 이미 북마크가 사용하고 있으면 아무것도 만들지 않습니다. **취소**를 누르면 아무것도 바뀌지 않습니다.

## 태그와 요약 제안 [#suggest-tags-and-summaries]

**자동 태그 지정**이나 **콘텐츠 요약**을 **분석**으로 실행합니다. 제안은 검토용으로 표시되며, **추천 태그 저장**이나 **추천 요약 저장**을 클릭해야만 저장됩니다. **병합 모드**는 저장하는 제안을 기존 내용에 추가할지 교체할지 정합니다.

저장된 태그와 요약은 이 브라우저의 로컬 저장소에 보관됩니다. **북마크 세부정보**에서 직접 편집할 수도 있습니다. 동기화되지 않고 검색할 수 없습니다. JSON 북마크 내보내기에는 포함되며, 그 파일을 가져오면 가져오기로 만들어지는 북마크에 적용됩니다.

설정의 태그 수와 스타일, 요약 길이, 재구성 제한은 제공업체에 지시 사항으로 전달되며, 제공업체의 결과가 이를 지키는지는 확인하지 않습니다.

## 폴더 재구성 [#reorganize-folders]

**AI 폴더 재구성**은 각 북마크가 어느 폴더에 속하는지 제공업체에 묻습니다. 계획은 항상 먼저 북마크 이동 목록으로 열리며, 새 폴더로의 이동은 표시되고 개수가 집계됩니다. **변경 사항 적용**을 클릭하기 전에는 아무것도 바뀌지 않습니다.

- **변경 사항 적용**은 북마크를 옮기고 계획에 나온 새 폴더를 만듭니다. 같은 위치에 같은 이름의 폴더가 이미 있으면 그 폴더를 사용합니다.
- 미리 본 뒤 옮기거나, URL을 바꾸거나, 삭제한 북마크는 건너뛰고 그대로 두므로, 계획이 더 최근의 변경을 덮어쓰지 않습니다. 계획의 일부만 적용되면 메시지에 옮긴 북마크, 새 폴더, 건너뛴 항목과 실패한 항목의 수가 표시되고 건너뛴 북마크의 이름이 나옵니다.
- 메시지나 검토 화면에서 **실행 취소**를 클릭하거나 북마크 관리자에서 <Shortcut id="manager.undo" />를 누르면 북마크가 원래 위치로 돌아가고, 아직 비어 있는 새 폴더는 제거됩니다. 그사이에 다시 옮긴 북마크는 옮긴 위치에 그대로 남습니다.

## AI 채팅용 컨텍스트 내보내기 [#export-context-for-an-ai-chat]

**AI 컨텍스트 패커**는 선택한 북마크를 어떤 AI 채팅에든 붙여 넣을 수 있는 Markdown이나 XML로 내보냅니다. 폴더 경로, 날짜, 저장된 태그와 요약(**저장된 태그 포함**, **저장된 요약 포함**)을 포함할 수 있습니다. 북마크 내보내기와 마찬가지로, 파일에 개인 정보일 수 있는 값이 포함되면 개인정보 검토 화면이 열립니다.

<Callout title="Firefox">
Firefox에서 관리자의 AI 도구를 사용하려면 툴바 팝업의 **북마크 관리자 열기**로 관리자를 여세요. AI는 Firefox 자동 테스트에서 다루지 않습니다.
</Callout>
