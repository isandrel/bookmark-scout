**깨진 링크 확인**은 북마크 관리자의 **도구** 사이드바에서 **유지 관리** 아래에 있습니다. 북마크한 각 페이지를 요청해 아직 열리는지 확인합니다.

<Callout title="Firefox">
Firefox에서는 팝업의 **북마크 관리자 열기**로 관리자를 엽니다.
</Callout>

## 검사 실행 [#run-a-scan]

<Steps>
<Step>
**깨진 링크 확인**의 범위 메뉴에서 현재 폴더 또는 모든 북마크를 선택하고 **검색**을 클릭합니다.
</Step>
<Step>
Bookmark Scout가 어떤 사이트에 대한 접근이 필요한지 설명합니다. 검사하는 북마크의 사이트만 요청하며, 사이트가 20개를 넘으면 모든 웹사이트를 요청합니다. **접근 허용**을 클릭한 뒤 브라우저의 확인 창에서 수락하세요. 이전에 허용한 사이트는 다시 요청하지 않습니다. **나중에**를 선택하거나 거부하면 아무것도 검사하지 않습니다.
</Step>
<Step>
결과를 기다립니다. 맨 위의 요약에 깨진 것으로 확인된 링크, 직접 확인이 필요한 링크, 리디렉션된 링크의 수가 표시됩니다.
</Step>
</Steps>

웹사이트 접근은 선택 사항이며 설치할 때 부여되지 않습니다. 요청은 쿠키 없이 전송되며, 브라우저의 확장 프로그램 설정에서 언제든지 접근 권한을 회수할 수 있습니다. 검사 범위 밖의 사이트로 리디렉션되는 링크는 따라갈 수 없으므로 **깨진 링크 확인됨** 대신 **직접 확인 필요**로 표시됩니다. [권한](/permissions)을 참고하세요.

## 백그라운드에서 실행하기 [#let-it-run-in-the-background]

확인은 백그라운드에서 실행됩니다. 관리자, 팝업, 사이드 패널을 닫아도 브라우저가 열려 있는 동안 계속되며, 브라우저가 확장 프로그램의 백그라운드를 멈추거나 다시 시작하면 이미 확인한 링크 다음부터 이어 갑니다. 실행 중에는 팝업과 사이드 패널에 진행 상황이 한 줄로 표시되고, 누르면 관리자의 **백그라운드 작업**이 열립니다.

- **일시 중지**는 새 요청을 멈추고, **다시 시작**은 아직 확인하지 않은 링크만 확인합니다. 일시 중지한 확인은 다시 시작한 뒤에도 일시 중지 상태로 남습니다.
- 확인 중에 웹사이트 접근 권한이 해제되면 일시 중지하고 그 사실을 알려 줍니다. **다시 시작**하면 권한을 다시 요청합니다.
- **취소**는 확인을 멈추고 지금까지의 결과를 남깁니다. 북마크는 바꾸지 않습니다.
- **결과 보기**로 언제든 결과를 열 수 있고, **삭제**로 끝난 확인을 지울 수 있습니다. 끝난 확인은 시간이 지나면 저절로 지워집니다.

복구는 백그라운드에서 일어나지 않습니다. 아래처럼 검토한 뒤 적용합니다.

## 결과 읽기 [#read-the-results]

| 결과 | 의미 |
| --- | --- |
| **깨진 링크 확인됨** | 페이지를 찾을 수 없음(404 또는 410), 연결이 거부됨, 호스트를 찾을 수 없음, 리디렉션이 반복됨 |
| **직접 확인 필요** | 브라우저에서는 여전히 동작하는 경우가 많음: 로그인 필요 또는 접근 거부(401, 403, 407), 요청 빈도 제한(429), 사이트가 자동 검사를 거부(405 또는 501), 서버 오류(5xx), 기타 HTTP 오류, 시간 초과 |
| **리디렉션** | 링크는 동작하지만 이제 다른 곳을 가리킴. 이동하는 대상이 표시됨 |
| **건너뜀** | 북마클릿처럼 웹 링크가 아닌 항목 |

429 또는 503으로 응답하며 몇 초 뒤에 다시 요청해 달라는 사이트는 그 시간을 기다린 뒤 **재시도 횟수** 안에서 다시 확인합니다. 더 오래 기다리라는 사이트는 바로 여기에 표시됩니다.

일부 서버는 `HEAD`를 지원하지 않으므로, `HEAD` 요청에서 발생한 오류는 보고하기 전에 `GET`으로 다시 확인합니다.

<Callout type="info" title="Chrome의 콘솔 메시지">
Chrome은 실패한 요청마다 페이지의 개발자 콘솔에 "Failed to load resource" 한 줄을 기록합니다. 확장 프로그램은 이 기록을 숨길 수 없으며, 검사 자체는 아무것도 기록하지 않습니다.
</Callout>

## 링크 복구 [#repair-links]

<Steps>
<Step>
**복구 검토**를 클릭합니다. 실패했거나, 시간이 초과되었거나, 리디렉션된 모든 링크가 나열됩니다.
</Step>
<Step>
각 링크의 처리 방법을 선택합니다.

- **그대로 유지**(기본값이므로 다른 항목을 고르지 않으면 아무것도 바뀌지 않음)
- **북마크 삭제**
- **리디렉션 대상으로 교체**: 검사에서 리디렉션이 확인된 경우에만 표시됨
- **보관된 사본으로 교체 (Wayback Machine)**: 북마크가 `https://web.archive.org/web/<original URL>`을 가리키도록 바꿈. 링크는 로컬에서 만들어지며 확인하지 않으므로, 페이지가 한 번도 보관되지 않았을 수 있음
- **URL 편집**: 현재 URL과 다른 유효한 `http` 또는 `https` URL만 입력 가능
</Step>
<Step>
삭제될 북마크, URL이 교체될 북마크, 유지될 북마크가 각각 몇 개인지 요약을 확인한 뒤 **적용**을 클릭합니다.
</Step>
</Steps>

적용하기 전에는 아무것도 바뀌지 않습니다. 각 변경 전에 북마크를 다시 읽으며, 검사 이후 삭제되거나 편집된 북마크는 건너뛰고 목록에 표시하므로 오래된 검사 결과가 더 최근의 편집 내용을 덮어쓰지 않습니다.

메시지 안이나 일부만 적용된 경우 대화 상자 안에 10초 동안 표시되는 **실행 취소**와 북마크 관리자의 <Shortcut id="manager.undo" />는 같은 복구를 실행 취소합니다. 삭제된 북마크가 복원되고, 교체된 URL은 그 뒤에 다시 편집되지 않았다면 원래대로 돌아갑니다.

| 설정 | 기본값 |
| --- | --- |
| **요청 제한 시간** | 요청당 <SettingDefault path="maintenance.dead_links.request_timeout_ms" seconds />초 |
| **동시 요청 수** | 한 번에 요청 <SettingDefault path="maintenance.dead_links.concurrency" />개 |
| **재시도 횟수** | 재시도 1회 |
| **리디렉션 따라가기** | 켜짐 |
| **성공 상태 코드** | 200, 201, 202, 204, 301, 302, 307, 308 |
