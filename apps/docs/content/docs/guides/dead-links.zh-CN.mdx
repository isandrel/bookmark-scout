title: 查找并修复失效链接
description: 扫描书签中的失效链接，查看哪些需要手动检查，并通过删除、跟随重定向、使用存档副本或修改网址来修复它们。
---

**检查失效链接**位于书签管理器的**工具**侧栏中的**维护**下。它会请求每个已加入书签的网页，以确认其是否仍能加载。

<Callout title="Firefox">
在 Firefox 中，请通过弹出窗口中的**打开书签管理器**打开书签管理器。
</Callout>

## 运行扫描 [#run-a-scan]

<Steps>
<Step>
在**检查失效链接**中，从范围菜单中选择当前文件夹或所有书签，然后点击**扫描**。
</Step>
<Step>
Bookmark Scout 会说明它需要访问哪些网站：只有你所扫描书签的网站，或在超过 20 个网站时访问所有网站。点击**允许访问**，然后接受浏览器的提示。之前已允许的网站不会再次请求。如果你选择**以后再说**或拒绝，则不会扫描任何内容。
</Step>
<Step>
等待结果。顶部的摘要会统计确认失效、需要手动检查以及已重定向的链接数量。
</Step>
</Steps>

网站访问权限是可选的，安装时不会授予。请求不会携带 Cookie，你可以在浏览器的扩展程序设置中撤回此访问权限。重定向到扫描范围以外网站的链接无法被跟随，因此会显示为**需手动检查**，而不是**确认失效**。请参阅[权限](/permissions)。

## 在后台运行 [#let-it-run-in-the-background]

检查在后台运行。你可以关闭管理器、弹出窗口或侧边栏，只要浏览器开着，检查就会继续；如果浏览器停止了扩展的后台或重新启动，它会从已检查的链接之后继续。运行期间，弹出窗口和侧边栏会用一行显示进度，点击即可打开管理器中的**后台任务**。

- **暂停**会停止发出新请求，**继续**只检查尚未检查的链接。已暂停的检查在重启后仍保持暂停。
- 如果检查期间网站访问权限被收回，检查会暂停并说明原因；**继续**会重新请求权限。
- **取消**会停止检查，并保留已有的结果。不会更改任何书签。
- **查看结果**随时打开结果，**删除**移除已完成的检查。已完成的检查过一段时间会自动移除。

修复从不在后台进行：你需要像下文那样先查看再应用。

## 查看结果 [#read-the-results]

| 结果 | 含义 |
| --- | --- |
| **确认失效** | 页面不存在（404 或 410）、连接被拒绝、找不到主机，或重定向陷入循环 |
| **需手动检查** | 在浏览器中通常仍可正常访问：需要登录或访问被拒绝（401、403、407）、请求频率受限（429）、网站拒绝自动检查（405 或 501）、服务器错误（5xx）、其他 HTTP 错误，或请求超时 |
| **已重定向** | 链接可以访问，但现在指向其他地方；会显示目标地址 |
| **已跳过** | 不是网页链接，例如书签小程序（bookmarklet） |

网站返回 429 或 503 并要求几秒后再试时，会在等待后于**重试次数**内再次检查；要求等待更久的网站会立即列在这里。

`HEAD` 请求返回的任何错误都会先用 `GET` 请求确认后再报告，因为有些服务器不支持 `HEAD`。

<Callout type="info" title="Chrome 中的控制台消息">
Chrome 会为每个失败的请求在网页的开发者控制台中记录一行“Failed to load resource”。扩展程序无法屏蔽这些日志；扫描本身不会记录任何内容。
</Callout>

## 修复链接 [#repair-links]

<Steps>
<Step>
点击**检查修复方案**。所有失败、超时或已重定向的链接都会列出。
</Step>
<Step>
为每个链接选择一项操作：

- **保持不变**（默认选项，因此除非你选择其他操作，否则不会有任何更改）
- **删除书签**
- **使用重定向目标**，仅当扫描检测到重定向时才提供
- **使用存档副本（Wayback Machine）**，会将书签指向 `https://web.archive.org/web/<original URL>`。该链接是在本地生成的，未经检查，因此该网页可能从未被存档。
- **修改网址**，只接受与当前网址不同的有效 `http` 或 `https` 网址
</Step>
<Step>
查看摘要，确认将删除、替换网址或保留的书签数量，然后点击**应用**。
</Step>
</Steps>

在你应用之前，不会做任何更改。每次更改前，都会重新读取该书签：自扫描以来已被删除或修改的书签会被跳过并列出，因此过时的扫描结果永远不会覆盖较新的修改。

**撤消**（在消息中，或在部分应用后的对话框中，显示 10 秒）和书签管理器中的 <Shortcut id="manager.undo" /> 撤消的是同一批修复：恢复已删除的书签，并将被替换的网址改回原样，除非这些网址之后又被修改过。

## 调整扫描设置 [#tune-the-scan]

在[设置](/settings)的**维护**标签页中：

| 设置 | 默认值 |
| --- | --- |
| **请求超时** | 每个请求 <SettingDefault path="maintenance.dead_links.request_timeout_ms" seconds /> 秒 |
| **并发数** | 同时 <SettingDefault path="maintenance.dead_links.concurrency" /> 个请求 |
| **重试次数** | 重试 1 次 |
| **跟随重定向** | 开启 |
| **成功状态码** | 200、201、202、204、301、302、307、308 |
