---
title: Clean up duplicates and tracking URLs
description: Remove duplicate bookmarks after a review, strip tracking parameters such as utm_source from bookmark URLs with a preview first, and refresh missing site icons.
---

Both tools live in the **Tools** sidebar of the bookmarks manager, under **Maintenance**. In Chrome, open the browser's bookmarks page, then click **Show tools** in the manager's header if the sidebar is hidden.

<Callout title="Firefox">
Firefox does not let extensions replace its own bookmarks page, so open the manager there with **Open bookmark manager** in the toolbar popup, then open the Tools sidebar.
</Callout>

## Remove duplicate bookmarks

<Steps>
<Step>
In **Duplicate Cleaner**, click **Scan**. It always checks all bookmarks.
</Step>
<Step>
Review the groups. Each group shows the address its bookmarks share once, then each bookmark with its folder and date added. The one marked **Keep** follows **Keep Rule** until you pick another with its radio button; every other copy has a **Remove** checkbox, checked at first. Uncheck a copy, or a group's checkbox, to leave it alone.
</Step>
<Step>
Click **Remove N duplicates** to delete the checked copies, or **Cancel** to change nothing.
</Step>
<Step>
Changed your mind? Click **Undo** in the message within 10 seconds to restore what was removed. Later, <Shortcut id="manager.undo" /> in the bookmark manager restores it too.
</Step>
</Steps>

<Screenshot name="duplicates" />

What counts as a duplicate is set on the **Maintenance** tab of [Settings](/settings):

| Setting | Default | What it does |
| --- | --- | --- |
| **Match Strategy** | Normalized URL | Compare by **Exact URL**, **Normalized URL**, **Title + URL**, or **Title only** |
| **Normalize www** | On | Treat `www.example.com` and `example.com` as the same host |
| **Ignore Protocol** | On | Treat `http` and `https` versions as duplicates |
| **Ignore Trailing Slash** | On | Treat URLs with and without a trailing `/` as duplicates |
| **Keep Rule** | Oldest | Keep the **Oldest**, the **Newest**, or the **First found** bookmark in each group |
| **Max Groups** | <SettingDefault path="maintenance.duplicates.max_groups" /> | Most groups returned by one scan |

Before removing anything, each group is checked again. If the bookmark marked **Keep** was deleted or now points elsewhere, the whole group is left untouched and the message says how many groups were skipped. With **Title only** matching, a warning appears when a group contains different URLs, because removing those copies deletes different pages.

## Strip tracking parameters

<Steps>
<Step>
In **URL Cleaner**, choose the current folder or all bookmarks in the scope menu, and click **Clean**.
</Step>
<Step>
Review the URLs that would change, grouped by the rule that cleans them (a **Remove Parameters** entry such as `utm_*`, a repeated parameter, or a fragment). Each starts on **Clean**; set one, or every selected one with **Set selected to…**, to **Keep as is** to leave it alone.
</Step>
<Step>
Click **Clean N URLs** to update the ones left on **Clean**, or close the dialog to change nothing.
</Step>
</Steps>

If a bookmark changed after the preview, it is skipped and counted in the message. Click **Undo** in the message, or press <Shortcut id="manager.undo" /> in the bookmark manager, to put the old URLs back; a bookmark changed again since is left as it is.

The rules are on the **Maintenance** tab of Settings:

- **Remove Parameters**: parameters to strip. The default list is <SettingDefault path="maintenance.url_cleaner.remove_params" />. A name ending in `*` matches every name that starts with it.
- **Preserve Parameters**: parameters that are never removed. Default: <SettingDefault path="maintenance.url_cleaner.preserve_params" />.
- **Deduplicate Query Parameters** (on by default) removes repeated parameters.
- **Sort Query Parameters** (on by default) sorts the remaining parameters alphabetically.
- **Remove Fragments** (off by default) also removes parts such as `#section`.

## Refresh site icons

Bookmarks show a generic globe until Bookmark Scout has an icon for the site. In Chrome and Edge, the quickest way is **Show browser icons** on the **Refresh Site Icons** card, or **Use the browser's icon cache** in [Settings](/settings#appearance): it shows the icons your browser already saved for the sites you visit, and the browser only asks to read site icons. For sites the browser has no icon for, and in Firefox, which gives extensions no icon cache, **Refresh Site Icons**, under **Page Titles & Icons** in the Tools sidebar, downloads each site's own icon.

<Steps>
<Step>
Choose the current folder or all bookmarks in the scope menu, and click **Refresh**. When asked, allow access to the sites in that scope (a scope with more than 20 sites asks for all websites); if you decline, nothing is requested.
</Step>
<Step>
Review the sites by tab: **New icon**, **Same icon**, **No icon**, and **Failed**, each with how many, and a note on how many bookmarks were skipped because they are not web links. Each icon found starts on **Save icon**; set one to **Skip**, or select several and use **Set selected to…**.
</Step>
<Step>
Click **Save** (for example **Save 12 icons**) to keep the icons left on **Save icon**, or close the dialog to keep nothing.
</Step>
</Steps>

For each website (origin) in scope, the tool requests one bookmarked page without cookies, reads only its head, and downloads the icon the page lists that is closest to **Preferred Icon Size**, or the site's `/favicon.ico`. Only icon files on the bookmark's own domain are used, never a third-party icon service. Files over **Maximum Icon File Size** (<SettingDefault path="metadata_content.site_icons.max_icon_kb" /> KB) or that are not images are skipped.

The refresh runs in the background: it keeps going after you close the manager, and its card and **Background tasks** show its progress, with **Pause**, **Resume**, and **Cancel**. Its results wait for **Review results**; nothing is saved until you click **Save**.

Saved icons are stored in this browser's local storage, not synced, and show in the popup, side panel, and manager. They take priority over the browser's cached icon. The card shows how many are saved; **Clear saved icons** deletes them all. When the total reaches **Icon Storage Limit** (4 MB), the oldest icons are removed first. A site that fails on a later refresh keeps the icon saved earlier.

<Callout title="Firefox">
In Firefox, open the manager with **Open bookmark manager** in the toolbar popup to run the tool. After you save icons there, the popup and side panel show them.
</Callout>

## Tag and move with Smart Rules

A smart rule finds bookmarks with a search, in the same words and [operators](/guides/search#search-words-and-operators) as the search boxes, and adds tags to them, moves them to a folder, or both. Rules act on their own only where you turn that on, below; otherwise each run is a review you apply.

<Steps>
<Step>
In [Settings](/settings#maintenance), under **Smart Rules**, click **Add rule**, or **Start from a template** for a rule that tags GitHub pages, YouTube videos, or tutorials, or one that moves bookmarks out of a **Work / Reading** folder. Templates start turned off. The one that moves opens in the editor, because it has no folder yet: it cannot be turned on or saved until you choose one.
</Step>
<Step>
Give the rule a name and a search, such as `domain:github.com`, `folder:Reading -tag:read`, or `(domain:github.com OR domain:gitlab.com) -tag:archived`. The editor says how many bookmarks it matches now, or what is wrong with the search, such as a parenthesis that is not closed; a rule cannot be saved until its search reads. Type a web address or a title under **Test with an address or title** to see whether the search matches it; this is worked out on your device, and nothing is saved or sent. Add tags (press Enter or type a comma after each one), choose a folder to move them to, or both, and save.
</Step>
<Step>
In the manager's Tools sidebar, choose the scope on the **Smart Rules** card and click **Run**: the folder shown, all bookmarks, or, while the manager has them, **Search results** (what the search box lists) or **Selected bookmarks**. The scope is taken when you click, and a bookmark outside it is never reviewed or changed.
</Step>
<Step>
Review the bookmarks by tab: **Changes**, **Conflicts** (two rules would move it to different folders), **Blocked** (its folder is gone or managed, or in that folder another rule would move it again), and **Already done**. Changes start on **Apply** and conflicts on **Skip**; set others one at a time or with **Set selected to…**, then click **Apply** (for example **Apply 12 changes**).
</Step>
</Steps>

Good to know:

- Rules run in list order. Every matching rule adds its tags; the first one that moves a bookmark wins, and folders later rules name show as conflicts. Drag a rule to change the order.
- Runs settle: a bookmark already in a folder a matching rule names stays there, and a move is made only when, in its new folder and with its new tags, no rule would move it again. So running the rules twice never moves a bookmark back and forth.
- Rules work on each bookmark by itself: two bookmarks of the same address in different folders are matched and changed apart.
- A tag a bookmark already has, in any spelling, is not added again. Folders are never tagged or moved.
- **Undo** in the message after applying puts back both the moves and the tags. The moves are one change in the History. The run is also listed under **Changed by rules** in Settings with the bookmarks it tagged, where **Undo** later removes those tags where they still are; its moves are undone from the History.
- Tags and moves are saved separately, so the message counts what was tagged, moved, skipped, and failed. A move is never made without its record in the History: when that record cannot be saved, nothing moves, the tags are still added, and the message says so.
- Applying checks each bookmark again first. One deleted, renamed, given another address, or moved elsewhere since the review is skipped and keeps your change, and so is one whose rule was edited, turned off, or deleted since (renaming a rule does not count); the message says how many. One already as the review would leave it is not changed again.
- A run that changes more bookmarks than **Apply in the Background Above** (Settings, **Background tasks**) is applied by a background task, tags and moves together, in parts. It keeps going after you close the manager and after the browser restarts, and you can pause, resume, or cancel it under **Background tasks**; cancelling keeps what was done. Each part's moves are one change in the History, and the run's tags are listed under **Changed by rules**, recorded before they are added. If the browser stops while a part is being applied, the task waits for **Resume**, which checks each remaining bookmark again, so nothing is tagged or moved twice. Turning Smart Rules off pauses the task until you turn it on and resume; a rule edited or turned off meanwhile has its bookmarks skipped.
- In Settings, each rule shows its last reviewed run: when, and how many bookmarks it tagged, moved, and left out. **Conflicts in the last run** lists the bookmarks two rules would have moved to different folders, with the folders they named; **Review** opens the manager on that bookmark's folder with Smart Rules ready to run there.
- Rules stay on this device and are part of **Back up settings**. A rule restored on another device moves bookmarks only if its folder exists there; otherwise its moves are blocked until you choose the folder again. It finds that folder by its path when the folder has another id there, as long as only one folder has that path.
- With **Tag New Bookmarks** on in Settings, enabled rules add their tags to each new bookmark that **New Bookmarks From** allows. By default that is **Saved with Bookmark Scout**: bookmarks you save with quick save, the popup, the manager, or Ask AI. Choose **Anywhere** to include bookmarks from the browser's star, another extension, or sync; the browser does not say where a bookmark came from, so these are all treated alike. It never moves anything. Many bookmarks added at once (a sync or an import) are left alone, and so is a bookmark added while a setting did not allow it. Each automatic tagging is listed under **Changed by rules** in Settings, with an Undo that removes its tags.
- Moving without a review takes two choices of yours, apart from tagging: **Move new bookmarks automatically** on the rule, next to its folder, and **Move New Bookmarks** in Settings. The rules list says **Moves new bookmarks automatically** under such a rule. A new bookmark it matches then goes to that folder, and only that one: if the folder is deleted, renamed, moved, or managed, the rule says its automatic moves stopped and nothing moves until you choose the folder again and save the rule; a folder with the same path is never used instead. As in a run, the first rule that moves a bookmark decides, and a bookmark two rules would move to different folders stays put. Bookmarks Bookmark Scout saves (quick save, the manager) stay where they were put, so automatic moves need **New Bookmarks From** set to **Anywhere**; many added at once and one moved again within a few seconds stay too. Each batch of moves is one change in the [History](/guides/save-and-organize), from Bookmark Scout, named Smart Rules, automatically, and nothing moves when that record cannot be saved. Each move is listed under **Changed by rules**, where Undo puts the bookmark back in its earlier folder unless it was moved since.
- A rule saved before searches read `OR` and parentheses keeps finding what it found: they are read as text, in quotes.

## Search inside pages

**Index Page Text** keeps the readable text of bookmarked pages on this device, so search finds words that are only inside a page. It is off until you turn it on, and it downloads each page you index.

<Steps>
<Step>
Turn on **Enable Index Page Text** in [Settings](/settings#index-page-text).
</Step>
<Step>
In the manager's Tools sidebar, choose the scope on the **Index Page Text** card and click **Index**. Choose the sites to read: each site with pages to download is listed with its number of bookmarks, all checked at first. Uncheck the ones to leave out (**Select all**, **Select none**, and a filter for a long list help), then click the start button with the number of sites (for example **Start with 2 sites**). When asked, allow access to those sites; no other site is asked for or downloaded. Indexing runs in the background: it keeps going after you close the manager, and its card and **Background tasks** show its progress, with **Pause**, **Resume**, and **Cancel**; the pages then wait for **Review results**.
</Step>
<Step>
Review the pages by tab: **Text found**, **No text**, **Sign-in page** (the page asked you to sign in instead of showing its content; its text is never saved), **Redirected** (the address sends you to another one, which is not opened, so a site you have not allowed is never contacted; bookmark the address it leads to instead), **Failed**, **Already indexed** (from the same address before), **Not chosen** (on a site you left out, so never downloaded), and **Skipped** (not a web page, or on your local network). Pages with text start on **Save text**; click **Save** (for example **Save text of 12 pages**). Before a page is listed as redirected, its `https:` address and its address with or without `www.` are tried, only on the bookmark's own site and never following a further redirect; a page read that way shows **Read from** and the address it was read from. If this device's storage for the extension runs out while saving, the pages saved before that are kept and a message says how many were not saved; free up disk space or use **Delete page text** in Settings, then index again.
</Step>
</Steps>

Search then finds those bookmarks by their text in the popup, the side panel, and the manager. `content:` looks only in page text, and `has:content` finds the bookmarks that have it. A page is read again when its bookmark's address changes. **Delete page text** in Settings deletes the index; bookmarks, tags, and the History stay as they are. A result found in page text says where its text came from: **downloaded page** or **page from your tab**. Ask AI and local AI agents never search page text, which stays on this device: `content:` and `has:content` find nothing there, and the answer says so.

Indexing downloads pages without your cookies, so a page you can read only when signed in shows its sign-in page instead and lands under **Sign-in page**. To index what you see on such a page, open it: when it is bookmarked and Index Page Text is on, the button on the popup line that says where the page is saved, **Index this page's text**, reads the text the tab shows and shows it with a reminder to check it for anything private. It is kept only when you click **Save text**. Text is read only from the toolbar popup, never in a private window, never from a sign-in page, and only while the tab shows the bookmarked page before and after reading it; if the tab moves to another page in between, nothing is kept.

Bookmarks with the same address share one download, and each keeps its own text. Two more cases are listed apart: **Not a web page** (the address answers with a file such as a PDF, which is not downloaded), and under **Skipped**, addresses that hold a user name and password, or a parameter listed in the Privacy Scanner's **Sensitive Parameters** (such as a token), which the site would receive: they are not requested while **Skip Addresses with Sign-in Details or Secrets** is on in Settings (the default). Text is kept as plain text, paragraph by paragraph, so a phrase in quotes matches inside one paragraph only. A site that answers that it is busy and names a short wait is asked again after that wait, a few times at most; after that, the page is listed under **Failed**. To keep Index Page Text off a site altogether, add it to **Never Read These Sites** in [Settings](/settings#index-page-text): its pages, and those of its subdomains, are never downloaded or read from the tab, are listed under **Skipped** with the reason, and the text already indexed from it is deleted.

The **Page text index** panel in [Settings](/settings#index-page-text) shows how many of the bookmarks that can be indexed are, how many are out of date (read at an earlier address or by an older version; the next run reads them again), and how many failed in the last run. **Retry failed** runs Index Page Text again on just those, in the background, asking for access to their sites only; save the text from **Review results** on the card. Taking back the extension's access to a website deletes the text indexed from it, and deleting a bookmark deletes its text. The panel also says when text was last indexed, and **Refresh outdated** reads the out-of-date pages again the same way.

## Show covers on cards

**Fetch Covers** keeps a small copy of the preview image a page names for itself (its Open Graph or Twitter card image), so the manager's **Cards** show it. It is off until you turn it on. Showing cards never downloads anything: a card without a stored cover shows a tile with its site's icon and name, on a color picked from the site, drawn on your computer.

<Steps>
<Step>
Turn on **Enable Fetch Covers** in [Settings](/settings#fetch-covers).
</Step>
<Step>
In the manager's Tools sidebar, choose the scope on the **Fetch Covers** card and click **Fetch**. When asked, allow access to the sites in that scope.
</Step>
<Step>
Review the pages by tab: **Cover found** (with the picture), **No cover**, **Unusable image** (the page names an image that is not a supported picture, is too large, or cannot be read), **On another site** (the image is on a site you did not allow), **Redirected** (the address sends you to another one, which is not opened; its `https:` and `www.` addresses are tried first, as for Index Page Text), **Failed**, **Already fetched**, and **Skipped**. Found covers start on **Save cover**; click **Save** (for example **Save 12 covers**). If this device's storage for the extension runs out while saving, the covers saved before that are kept and a message says how many were not saved; free up disk space or use **Delete covers** in Settings, then fetch again.
</Step>
</Steps>

Switch the manager to **Cards** with the button beside **View** to see them. A cover belongs to the address it came from, so a bookmark moved to another address shows its icon until you fetch again. Covers are kept on this device only, never in backups or exports; **Delete covers** in Settings removes them, and bookmarks, tags, and the History stay as they are.

You can also use the page you are on: when it is bookmarked and Fetch Covers is on, the button at the end of the popup line that says where the page is saved, **Use this view as the cover**, takes a picture of the tab and shows it with a reminder to check it for anything private. It is kept only when you click **Save cover**. Pictures are taken only from the toolbar popup, never of a private window, and only while the tab still shows the bookmarked page.

**Fetch cover** in a bookmark's menu (right-click or **⋯**, in the list or on cards, also for a selection) or in its **Preview** runs Fetch Covers on just those bookmarks, with the same review and the same request for access to their sites; a cover you saved with **Use this view as the cover** is listed under **Chosen by you** and kept. On the **Fetch Covers** card, **Selected bookmarks** does the same for the manager's selection. **Remove cover** deletes a bookmark's cover (each selected bookmark's, for a selection): the card shows its placeholder at once, and **Undo** in the message puts the same cover back.

### Capture covers while you browse

Turn on **Capture Covers While Browsing** under Fetch Covers in [Settings](/settings#fetch-covers) to get covers without fetching. When a bookmarked page without a cover finishes loading in the tab you are viewing, Bookmark Scout waits a moment, checks that the tab still shows that page, and takes a screenshot of it as the bookmark's cover. Turning it on asks your browser for access to all pages, because that is the only way browsers let an extension take a picture of a tab without a click; the same access lets the tools that read websites run without asking again.

- It takes no picture in a private window unless you also turn on **Also Capture in Private Windows** and your browser lets Bookmark Scout run there, and never one of the extension's or the browser's own pages, of local files, or of a page you have not bookmarked.
- A screenshot shows whatever the page showed, such as an account page or messages. Add sites you want left alone to **Never Capture These Sites** (a site covers its subdomains; sites on **Never Read These Sites** are skipped too), and delete any cover with **Delete covers** in Settings.
- **Cover Source** decides which cover wins when both are possible. With **Page image first, then screenshot** (the default), a screenshot never replaces an image Fetch Covers saved, and Fetch Covers replaces a screenshot taken while browsing. **Screenshot first** does the opposite, and **Page image only** takes none. A cover you saved with **Use this view as the cover** is never replaced by either; only another picture you save replaces it.
- A screenshot taken while browsing is taken again on your next visit once it is older than **Retake Screenshots Older Than** (0 never retakes one). **Wait Before Capturing** and **Time Between Pictures** set how long it waits. Screenshots are kept on this device only, like every cover, and never sent anywhere. Turn the setting off to stop; remove the access in your browser's extension settings.

The bookmark's **Preview** and its details card say where its cover came from: the page's own image, a picture of your tab, or one captured while browsing, with the day it was saved.

## Related tools

- [Find and repair dead links](/guides/dead-links) checks whether bookmarked pages still load.
- **Privacy Scanner** (under **Security**) flags URLs that contain tokens, email addresses, UUIDs, or sensitive parameters (and titles, if **Scan Titles** is on). Its review groups them as **High**, **Medium**, and **Low**; each starts on **Keep as is**, and the ones you set to **Delete bookmark** (one at a time, or with **Set selected to…**) are deleted when you click **Delete**, with undo. Ordinary in-page links and app addresses such as Gmail's `#inbox` are not flagged.
- **Metadata Fetcher** (under **Page Titles & Icons**) suggests page titles from the live pages and applies only the ones you select. It uses the same website access as the dead link check. It runs in the background too, and its titles wait for **Review results**.
