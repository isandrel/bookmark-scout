title: Clean up duplicates and tracking URLs
description: Remove duplicate bookmarks after a review, strip tracking parameters such as utm_source from bookmark URLs with a preview first, and refresh missing site icons.
---

Both tools live in the **Tools** sidebar of the bookmarks manager, under **Maintenance**. In Chrome, open the browser's bookmarks page, then click **Show tools** in the manager's header if the sidebar is hidden.

<Callout title="Firefox">
Firefox does not let extensions replace its own bookmarks page, so open the manager there with **Open bookmark manager** in the toolbar popup, then open the Tools sidebar.
</Callout>

## Remove duplicate bookmarks

<Steps>
<Step>
In **Duplicate Cleaner**, click **Scan**. It always checks all bookmarks.
</Step>
<Step>
Review the groups. Each group shows the address its bookmarks share once, then each bookmark with its folder and date added. The one marked **Keep** follows **Keep Rule** until you pick another with its radio button; every other copy has a **Remove** checkbox, checked at first. Uncheck a copy, or a group's checkbox, to leave it alone.
</Step>
<Step>
Click **Remove N duplicates** to delete the checked copies, or **Cancel** to change nothing.
</Step>
<Step>
Changed your mind? Click **Undo** in the message within 10 seconds to restore what was removed. Later, <Shortcut id="manager.undo" /> in the bookmark manager restores it too.
</Step>
</Steps>

<Screenshot name="duplicates" />

What counts as a duplicate is set on the **Maintenance** tab of [Settings](/settings):

| Setting | Default | What it does |
| --- | --- | --- |
| **Match Strategy** | Normalized URL | Compare by **Exact URL**, **Normalized URL**, **Title + URL**, or **Title only** |
| **Normalize www** | On | Treat `www.example.com` and `example.com` as the same host |
| **Ignore Protocol** | On | Treat `http` and `https` versions as duplicates |
| **Ignore Trailing Slash** | On | Treat URLs with and without a trailing `/` as duplicates |
| **Keep Rule** | Oldest | Keep the **Oldest**, the **Newest**, or the **First found** bookmark in each group |
| **Max Groups** | <SettingDefault path="maintenance.duplicates.max_groups" /> | Most groups returned by one scan |

Before removing anything, each group is checked again. If the bookmark marked **Keep** was deleted or now points elsewhere, the whole group is left untouched and the message says how many groups were skipped. With **Title only** matching, a warning appears when a group contains different URLs, because removing those copies deletes different pages.

## Strip tracking parameters

<Steps>
<Step>
In **URL Cleaner**, choose the current folder or all bookmarks in the scope menu, and click **Clean**.
</Step>
<Step>
Review the URLs that would change, grouped by the rule that cleans them (a **Remove Parameters** entry such as `utm_*`, a repeated parameter, or a fragment). Each starts on **Clean**; set one, or every selected one with **Set selected to…**, to **Keep as is** to leave it alone.
</Step>
<Step>
Click **Clean N URLs** to update the ones left on **Clean**, or close the dialog to change nothing.
</Step>
</Steps>

If a bookmark changed after the preview, it is skipped and counted in the message. Click **Undo** in the message, or press <Shortcut id="manager.undo" /> in the bookmark manager, to put the old URLs back; a bookmark changed again since is left as it is.

The rules are on the **Maintenance** tab of Settings:

- **Remove Parameters**: parameters to strip. The default list is <SettingDefault path="maintenance.url_cleaner.remove_params" />. A name ending in `*` matches every name that starts with it.
- **Preserve Parameters**: parameters that are never removed. Default: <SettingDefault path="maintenance.url_cleaner.preserve_params" />.
- **Deduplicate Query Parameters** (on by default) removes repeated parameters.
- **Sort Query Parameters** (on by default) sorts the remaining parameters alphabetically.
- **Remove Fragments** (off by default) also removes parts such as `#section`.

## Refresh site icons

Bookmarks show a generic globe until Bookmark Scout has an icon for the site. In Chrome and Edge, the quickest way is **Show browser icons** on the **Refresh Site Icons** card, or **Use the browser's icon cache** in [Settings](/settings#appearance): it shows the icons your browser already saved for the sites you visit, and the browser only asks to read site icons. For sites the browser has no icon for, and in Firefox, which gives extensions no icon cache, **Refresh Site Icons**, under **Page Titles & Icons** in the Tools sidebar, downloads each site's own icon.

<Steps>
<Step>
Choose the current folder or all bookmarks in the scope menu, and click **Refresh**. When asked, allow access to the sites in that scope (a scope with more than 20 sites asks for all websites); if you decline, nothing is requested.
</Step>
<Step>
Review the sites by tab: **New icon**, **Same icon**, **No icon**, and **Failed**, each with how many, and a note on how many bookmarks were skipped because they are not web links. Each icon found starts on **Save icon**; set one to **Skip**, or select several and use **Set selected to…**.
</Step>
<Step>
Click **Save** (for example **Save 12 icons**) to keep the icons left on **Save icon**, or close the dialog to keep nothing.
</Step>
</Steps>

For each website (origin) in scope, the tool requests one bookmarked page without cookies, reads only its head, and downloads the icon the page lists that is closest to **Preferred Icon Size**, or the site's `/favicon.ico`. Only icon files on the bookmark's own domain are used, never a third-party icon service. Files over **Maximum Icon File Size** (<SettingDefault path="metadata_content.site_icons.max_icon_kb" /> KB) or that are not images are skipped.

The refresh runs in the background: it keeps going after you close the manager, and its card and **Background tasks** show its progress, with **Pause**, **Resume**, and **Cancel**. Its results wait for **Review results**; nothing is saved until you click **Save**.

Saved icons are stored in this browser's local storage, not synced, and show in the popup, side panel, and manager. They take priority over the browser's cached icon. The card shows how many are saved; **Clear saved icons** deletes them all. When the total reaches **Icon Storage Limit** (4 MB), the oldest icons are removed first. A site that fails on a later refresh keeps the icon saved earlier.

<Callout title="Firefox">
In Firefox, open the manager with **Open bookmark manager** in the toolbar popup to run the tool. After you save icons there, the popup and side panel show them.
</Callout>

## Tag and move with Smart Rules

A smart rule finds bookmarks with a search, in the same words and [operators](/guides/search#search-words-and-operators) as the search boxes, and adds tags to them, moves them to a folder, or both. Rules never act on their own: each run is a review you apply.

<Steps>
<Step>
In [Settings](/settings#maintenance), under **Smart Rules**, click **Add rule**, or **Start from a template** for a rule that tags GitHub pages, YouTube videos, or tutorials. Templates start turned off.
</Step>
<Step>
Give the rule a name and a search, such as `domain:github.com` or `folder:Reading -tag:read`. The editor says how many bookmarks it matches now. Add tags, separated by commas, choose a folder to move them to, or both, and save.
</Step>
<Step>
In the manager's Tools sidebar, choose the scope on the **Smart Rules** card and click **Run**.
</Step>
<Step>
Review the bookmarks by tab: **Changes**, **Conflicts** (two rules would move it to different folders), **Blocked** (its folder is gone or managed), and **Already done**. Changes start on **Apply** and conflicts on **Skip**; set others one at a time or with **Set selected to…**, then click **Apply** (for example **Apply 12 changes**).
</Step>
</Steps>

Good to know:

- Rules run in list order. Every matching rule adds its tags; the first one that moves a bookmark wins, and folders later rules name show as conflicts. Drag a rule to change the order.
- A tag a bookmark already has, in any spelling, is not added again. Folders are never tagged or moved.
- **Undo** in the message after applying puts back both the moves and the tags. The moves are one change in the History.
- Rules stay on this device and are part of **Back up settings**. A rule restored on another device moves bookmarks only if its folder exists there; otherwise its moves are blocked until you choose the folder again.
## Search inside pages

**Index Page Text** keeps the readable text of bookmarked pages on this device, so search finds words that are only inside a page. It is off until you turn it on, and it downloads each page you index.

<Steps>
<Step>
Turn on **Enable Index Page Text** in [Settings](/settings#index-page-text).
</Step>
<Step>
In the manager's Tools sidebar, choose the scope on the **Index Page Text** card and click **Index**. When asked, allow access to the sites in that scope.
</Step>
<Step>
Review the pages by tab: **Text found**, **No text**, **Failed**, **Already indexed** (from the same address before), and **Skipped** (not a web page, or on your local network). Pages with text start on **Save text**; click **Save** (for example **Save text of 12 pages**).
</Step>
</Steps>

Search then finds those bookmarks by their text in the popup, the side panel, and the manager. `content:` looks only in page text, and `has:content` finds the bookmarks that have it. A page is read again when its bookmark's address changes. **Delete page text** in Settings deletes the index; bookmarks, tags, and the History stay as they are.

## Related tools

- [Find and repair dead links](/guides/dead-links) checks whether bookmarked pages still load.
- **Privacy Scanner** (under **Security**) flags URLs that contain tokens, email addresses, UUIDs, or sensitive parameters (and titles, if **Scan Titles** is on). Its review groups them as **High**, **Medium**, and **Low**; each starts on **Keep as is**, and the ones you set to **Delete bookmark** (one at a time, or with **Set selected to…**) are deleted when you click **Delete**, with undo. Ordinary in-page links and app addresses such as Gmail's `#inbox` are not flagged.
- **Metadata Fetcher** (under **Page Titles & Icons**) suggests page titles from the live pages and applies only the ones you select. It uses the same website access as the dead link check. It runs in the background too, and its titles wait for **Review results**.
