---
title: Import and export
description: Export bookmarks as HTML, JSON, Markdown, or CSV with a privacy review, and import HTML or JSON files after a preview that shows duplicates.
---

Both tools are in the **Tools** sidebar of the bookmarks manager, under **Data**.

<Callout title="Firefox">
In Firefox, open the manager with **Open bookmark manager** in the popup.
</Callout>

## Export bookmarks

<Steps>
<Step>
In **Export Bookmarks**, pick a **Format**: **HTML (Chrome)**, **JSON**, **Markdown**, or **CSV**.
</Step>
<Step>
Choose the current folder or all bookmarks, and click **Export**.
</Step>
<Step>
If the file would contain values that may be private, a review opens first. Choose **Export original**, **Export redacted**, or **Cancel**.
</Step>
</Steps>

The review looks for sensitive query parameters, tokens in URL fragments, email-like and token-like values, and user names or passwords inside URLs. A redacted export replaces those values with `REDACTED` in the downloaded file only; your bookmarks do not change. Exports with nothing sensitive download directly.

File details:

- File names start with **Filename Prefix** (default `bookmarks_`) and keep non-ASCII folder names.
- CSV files start with a UTF-8 byte order mark. The Folder column joins folders with `/`, and writes a `/` inside a folder name as `\/` and a backslash as `\\`.
- Separators, which only Firefox has, are written as separators in HTML (`<HR>`) and JSON and come back as separators when you import that file in Firefox. Markdown and CSV leave them out, and Chrome and Edge, which have no separators, leave them out of an import; the preview counts them.
- **Include Dates** and **Include URLs**, and the indent sizes for each format, are on the **Data** tab of [Settings](/settings).

A JSON export includes each bookmark's tags and summary, and importing that file gives them to the bookmarks it creates, but not to ones it skips as duplicates. HTML, Markdown, and CSV exports leave them out. To hand bookmarks with their tags and summaries to an AI tool, use **AI Context Packer**; see [Set up AI tools](/guides/ai-tools#export-context-for-an-ai-chat).

## Import bookmarks

<Steps>
<Step>
In **Import Bookmarks**, click **Import** and choose an HTML or JSON bookmark file, such as one exported from a browser. You can also drop the file onto the **Import Bookmarks** card.
</Step>
<Step>
Review the **Import preview**. It shows the target folder, how many bookmarks and folders will be created or skipped, and which URLs already exist in the target folder, elsewhere in your bookmarks, or earlier in the same file.
</Step>
<Step>
Change **Import into** if needed. It starts as the folder open in the manager.
</Step>
<Step>
Choose how to handle **Duplicates**: skip bookmarks that already exist anywhere, skip only those already in the target folder, or import everything.
</Step>
<Step>
Click **Import**. A message lists how many items were created, skipped, and failed, with **Undo** for 10 seconds. Undo removes only what is still exactly as the import made it: an imported item you renamed, moved, re-tagged, or added to since stays, and the message counts it as kept.
</Step>
</Steps>

Nothing is written until you click **Import**. If your bookmarks change while the preview is open, the preview is refreshed instead of applied.

## Settings files are separate

The **Back up settings** and **Restore settings** buttons at the bottom of the Settings page save and restore a backup file of Bookmark Scout's settings, custom prompts, AI services (without API keys), and saved searches. They do not touch bookmarks, tags, or summaries. See [Settings](/settings) for what the backup holds. You can also drop a backup file anywhere on the Settings page to restore it.

### Covers in a backup [#covers-in-a-backup]

Covers never sync, and bookmark exports do not hold them, so a backup is how they reach another computer.

- While covers are stored, **Back up settings** asks whether to **Include covers**, and says how many and about how much they add to the file. The box starts checked; **Include Covers in Backups** in [Settings](/settings#data) changes that. The file holds one cover per address, newest first, up to the backup's limits.
- Restoring a backup that holds covers first shows a review: how many covers the file holds, how many match a bookmark with the same address on this device and how many do not, and how many bookmarks would get a cover, have theirs replaced, or keep their own. Uncheck **Restore covers** to restore only the rest of the backup.
- A cover you picked with **Use this view as the cover** ranks first: it is replaced only by a newer picked cover from the file, and a picked cover from the file replaces one that was not picked; otherwise the newer cover wins. A date in the future counts as today. **Cover Storage** still applies, so the oldest covers are removed past it, the ones you picked last.
- A restore cannot be undone. The covers stay in the file wherever you save it; nothing is sent anywhere.
