---
title: Trouver et réparer les liens morts
description: Analysez vos favoris pour trouver les liens morts, repérez ceux qui doivent être vérifiés manuellement, et réparez-les en les supprimant, en suivant une redirection, en utilisant une copie archivée ou en modifiant l'URL.
---

**Vérifier les liens morts** se trouve dans la barre latérale **Outils** du gestionnaire de favoris, sous **Maintenance**. L'outil demande chaque page enregistrée en favori pour savoir si elle se charge toujours.

<Callout title="Firefox">
Dans Firefox, ouvrez le gestionnaire avec **Ouvrir le gestionnaire de favoris** dans la fenêtre pop-up.
</Callout>

## Lancer une analyse [#run-a-scan]

<Steps>
<Step>
Dans **Vérifier les liens morts**, choisissez le dossier actuel ou tous les favoris dans le menu de portée, puis cliquez sur **Analyser**.
</Step>
<Step>
Bookmark Scout explique de quels sites il a besoin : uniquement les sites des favoris que vous analysez, ou tous les sites Web lorsqu'il y en a plus de 20. Cliquez sur **Autoriser l'accès**, puis acceptez la demande du navigateur. Les sites que vous avez déjà autorisés ne sont pas demandés à nouveau. Si vous choisissez **Pas maintenant** ou refusez, rien n'est analysé.
</Step>
<Step>
Attendez les résultats. Un résumé en haut indique le nombre de liens morts confirmés, de liens à vérifier manuellement et de liens redirigés. Des boutons au-dessus de la liste nomment chaque groupe avec son nombre ; cliquez sur l’un d’eux pour n’afficher que ces liens. Chaque cible de redirection est un lien que vous pouvez ouvrir.
</Step>
</Steps>

L'accès aux sites Web est facultatif et n'est pas accordé à l'installation. Les requêtes sont envoyées sans cookies, et vous pouvez révoquer cet accès dans les paramètres des extensions du navigateur. Un lien qui redirige vers un site extérieur à l'analyse ne peut pas être suivi : il s'affiche donc comme **À vérifier manuellement** au lieu de **Lien mort confirmé**. Consultez [Autorisations](/permissions).

## La laisser tourner en arrière-plan [#let-it-run-in-the-background]

La vérification s'exécute en arrière-plan. Vous pouvez fermer le gestionnaire, la fenêtre contextuelle ou le panneau latéral : elle continue tant que le navigateur est ouvert ; si le navigateur arrête l'arrière-plan de l'extension ou redémarre, elle reprend à partir des liens déjà vérifiés. Pendant qu'elle tourne, la fenêtre contextuelle et le panneau latéral affichent sa progression sur une ligne, qui ouvre **Tâches en arrière-plan** dans le gestionnaire.

- **Mettre en pause** arrête les nouvelles requêtes, et **Reprendre** ne vérifie que les liens pas encore vérifiés. Une vérification en pause le reste après un redémarrage.
- Si l'accès aux sites web est retiré pendant la vérification, elle se met en pause et l'indique ; **Reprendre** redemande l'accès.
- **Annuler** arrête la vérification et garde les résultats obtenus. Aucun favori n'est modifié.
- **Voir les résultats** ouvre les résultats à tout moment, et **Supprimer** retire une vérification terminée. Les vérifications terminées sont retirées d'elles-mêmes au bout d'un certain temps.

Les réparations ne se font jamais en arrière-plan : vous les examinez et les appliquez comme expliqué ci-dessous.

## Lire les résultats [#read-the-results]

| Résultat | Signification |
| --- | --- |
| **Lien mort confirmé** | Page introuvable (404 ou 410), connexion refusée, hôte introuvable ou boucle de redirections |
| **À vérifier manuellement** | Fonctionne souvent encore dans un navigateur : connexion requise ou accès refusé (401, 403, 407), limite de débit atteinte (429), site qui rejette les vérifications automatisées (405 ou 501), erreur serveur (5xx), autre erreur HTTP, ou délai d'expiration dépassé |
| **Redirigé** | Le lien fonctionne, mais pointe désormais ailleurs ; la destination est affichée |
| **Ignoré** | Pas un lien Web, par exemple un bookmarklet |

Un site qui répond 429 ou 503 et demande d'être réessayé dans quelques secondes est revérifié après ce délai, dans la limite de **Nombre de nouvelles tentatives** ; un site qui demande plus longtemps apparaît ici aussitôt.

Toute erreur renvoyée par une requête `HEAD` est confirmée par une requête `GET` avant d'être signalée, car certains serveurs ne prennent pas en charge `HEAD`.

<Callout type="info" title="Messages de la console dans Chrome">
Chrome consigne une ligne « Failed to load resource » dans la console de développement de la page pour chaque requête qui échoue. Les extensions ne peuvent pas supprimer ces lignes ; l'analyse elle-même ne consigne rien.
</Callout>

## Réparer les liens [#repair-links]

<Steps>
<Step>
Cliquez sur **Réparer ou supprimer les liens**. Tous les liens en échec, ayant dépassé le délai d'expiration ou redirigés sont listés. Les mêmes boutons de groupe restreignent la liste. Cochez des liens, ou la case au-dessus de la liste pour tous ceux affichés, puis choisissez une action dans **Appliquer à la sélection…** pour l’appliquer à tous en une fois ; vous pouvez ensuite modifier chacun. Chaque lien commence sur l’action définie pour son groupe dans les [Paramètres](/settings), **Laisser tel quel** sauf si vous la changez.
</Step>
<Step>
Choisissez une action pour chacun :

- **Laisser tel quel** (l'action par défaut : rien ne change, sauf si vous choisissez autre chose)
- **Supprimer le favori**
- **Utiliser la cible de la redirection**, proposé uniquement lorsque l'analyse a détecté une redirection
- **Utiliser une copie archivée (Wayback Machine)**, qui fait pointer le favori vers `https://web.archive.org/web/<original URL>`. Le lien est construit localement et n'est pas vérifié : il se peut donc que la page n'ait jamais été archivée.
- **Modifier l'URL**, qui n'accepte qu'une URL `http` ou `https` valide et différente de l'URL actuelle
</Step>
<Step>
Vérifiez le récapitulatif du nombre de favoris qui seront supprimés, dont l'URL sera remplacée ou qui seront conservés, puis cliquez sur **Appliquer**.
</Step>
</Steps>

Rien ne change tant que vous n'appliquez pas les réparations. Avant chaque modification, le favori est relu : un favori supprimé ou modifié depuis l'analyse est ignoré et listé, de sorte qu'une analyse obsolète n'écrase jamais une modification plus récente.

**Annuler**, affiché pendant 10 secondes dans la notification ou dans la boîte de dialogue après une application partielle, et <Shortcut id="manager.undo" /> dans le gestionnaire de favoris annulent les mêmes réparations : ils restaurent les favoris supprimés et rétablissent les URL remplacées, sauf si elles ont été modifiées de nouveau entre-temps.

## Ajuster l'analyse [#tune-the-scan]

Dans l'onglet **Maintenance** des [Paramètres](/settings) :

| Paramètre | Valeur par défaut |
| --- | --- |
| **Délai d'expiration des requêtes** | <SettingDefault path="maintenance.dead_links.request_timeout_ms" seconds /> secondes par requête |
| **Requêtes simultanées** | <SettingDefault path="maintenance.dead_links.concurrency" /> requêtes à la fois |
| **Nombre de nouvelles tentatives** | 1 nouvelle tentative |
| **Suivre les redirections** | Activé |
| **Codes d'état de réussite** | 200, 201, 202, 204, 301, 302, 307, 308 |
