どちらのツールも、ブックマークマネージャーの **ツール** サイドバーの **メンテナンス** にあります。Chrome では、ブラウザのブックマークページを開き、サイドバーが隠れている場合はマネージャーのヘッダーにある **ツールを表示** をクリックします。

<Callout title="Firefox">
Firefox では拡張機能が Firefox 自体のブックマークページを置き換えられないため、ツールバーのポップアップの **ブックマークマネージャーを開く** でマネージャーを開き、ツール サイドバーを開いてください。
</Callout>

サイドバーに表示するツールと、各セクション内での順序は、[設定](/settings#tools-sidebar)の **サイドバーのツール** で選べます。そこで非表示にしたツールも自動の処理は続けます。同じ場所の **最初に開くタブ** で、サイドバーを開いたときのタブを選べます。

## 重複したブックマークを削除する [#remove-duplicate-bookmarks]

<Steps>
<Step>
**重複クリーナー** で **スキャン** をクリックします。スキャンは常にすべてのブックマークを対象にします。
</Step>
<Step>
グループを確認します。各グループには共通のアドレスが一度だけ表示され、その下に各ブックマークがフォルダと追加日とともに並びます。**保持** の印は **保持ルール** に従って付きますが、ラジオボタンで別のものを選べます。ほかのコピーにはそれぞれ **削除** のチェックボックスがあり、最初はチェックされています。残したいコピーやグループのチェックを外します。
</Step>
<Step>
**重複 N 件を削除** をクリックするとチェックしたコピーが削除されます。何も変更しない場合は **キャンセル** をクリックします。
</Step>
<Step>
気が変わった場合は、10 秒以内にメッセージの **元に戻す** をクリックすると、削除したものが復元されます。後からでも、ブックマークマネージャーで <Shortcut id="manager.undo" /> を押すと復元できます。
</Step>
</Steps>

<Screenshot name="duplicates" />

何を重複とみなすかは、[設定](/settings)の **メンテナンス** タブで設定します。

| 設定 | 初期値 | 内容 |
| --- | --- | --- |
| **照合方法** | 正規化したURL | **URLが完全一致**、**正規化したURL**、**タイトル + URL**、**タイトルのみ** のいずれかで比較します |
| **wwwを正規化** | オン | `www.example.com` と `example.com` を同じホストとして扱います |
| **プロトコルを無視** | オン | `http` と `https` の URL を重複として扱います |
| **末尾のスラッシュを無視** | オン | 末尾の `/` の有無だけが異なる URL を重複として扱います |
| **保持ルール** | 最も古いもの | 各グループで **最も古いもの**、**最も新しいもの**、**最初に見つかったもの** のいずれかを残します |
| **最大グループ数** | <SettingDefault path="maintenance.duplicates.max_groups" /> | 1 回のスキャンで返すグループの最大数です |

削除の前に、各グループはもう一度確認されます。**保持** の印が付いたブックマークが削除されていたり、別の場所を指すようになっていたりした場合、そのグループ全体には手を加えず、スキップしたグループの数がメッセージで示されます。**タイトルのみ** で照合している場合、グループに異なる URL が含まれていると警告が表示されます。そのコピーを削除すると、別々のページを削除することになるためです。

## トラッキングパラメータを取り除く [#strip-tracking-parameters]

<Steps>
<Step>
**URLクリーナー** の範囲メニューで現在のフォルダかすべてのブックマークを選び、**クリーン** をクリックします。
</Step>
<Step>
変更される URL を、クリーンする理由（`utm_*` などの **削除するパラメータ** の項目、重複したパラメータ、フラグメント）ごとに確認します。最初はすべて **クリーン** です。残したいものは 1 件ずつ、または **選択した項目を設定…** でまとめて **そのまま残す** にします。
</Step>
<Step>
**N 件の URL をクリーン** をクリックすると **クリーン** のままの URL を更新します。何も変更しない場合はダイアログを閉じます。
</Step>
</Steps>

プレビューの後にブックマークが変更された場合、そのブックマークはスキップされ、件数がメッセージに含まれます。メッセージの **元に戻す** をクリックするか、ブックマークマネージャーで <Shortcut id="manager.undo" /> を押すと、元の URL に戻ります。その後に再び変更されたブックマークはそのままになります。

ルールは設定の **メンテナンス** タブにあります。

- **削除するパラメータ**: 取り除くパラメータです。初期設定のリストは <SettingDefault path="maintenance.url_cleaner.remove_params" /> です。末尾が `*` の名前は、その文字列で始まるすべての名前に一致します。
- **保持するパラメータ**: 削除しないパラメータです。初期設定: <SettingDefault path="maintenance.url_cleaner.preserve_params" />。
- **クエリパラメータの重複を削除**（初期設定でオン）は、繰り返し出てくるパラメータを削除します。
- **クエリパラメータを並べ替え**（初期設定でオン）は、残ったパラメータをアルファベット順に並べ替えます。
- **フラグメントを削除**（初期設定でオフ）は、`#section` のような部分も削除します。

## サイトアイコンを更新する [#refresh-site-icons]

Bookmark Scout がサイトのアイコンを持つまで、ブックマークには汎用の地球儀アイコンが表示されます。Chrome と Edge でいちばん手軽なのは、**サイトアイコンを更新** カードの **ブラウザのアイコンを表示**、または[設定](/settings#appearance)の **ブラウザのアイコンキャッシュを使う** です。アクセスしたサイトについてブラウザがすでに保存しているアイコンを表示し、ブラウザが求めるのはサイトアイコンの読み取りだけです。ブラウザにアイコンがないサイトや、拡張機能にアイコンキャッシュを提供しない Firefox では、ツール サイドバーの **ページの詳細** にある **サイトアイコンを更新** が、各サイト自身のアイコンをダウンロードします。

<Steps>
<Step>
範囲メニューで現在のフォルダかすべてのブックマークを選び、**更新** をクリックします。確認が表示されたら、その範囲のサイトへのアクセスを許可してください（20 を超えるサイトを含む範囲では、すべてのウェブサイトへのアクセスを求めます）。許可しなかった場合、リクエストは送信されません。
</Step>
<Step>
サイトをタブごとに確認します: **新しいアイコン**、**同じアイコン**、**アイコンなし**、**失敗** があり、それぞれ件数が表示されます。ウェブリンクではないためスキップしたブックマークの件数も表示されます。見つかったアイコンは最初 **アイコンを保存** になっています。**スキップ** に変えるか、複数選択して **選択した項目を設定…** を使います。
</Step>
<Step>
**保存**（たとえば **アイコン 12 件を保存**）をクリックすると、**アイコンを保存** のままのアイコンを残します。何も残さない場合はダイアログを閉じます。
</Step>
</Steps>

範囲内のウェブサイト（オリジン）ごとに、ツールはブックマークしたページを 1 つ Cookie なしでリクエストし、その head 部分だけを読み取ります。そして、ページに記載されたアイコンのうち **優先するアイコンサイズ** に最も近いもの、またはサイトの `/favicon.ico` をダウンロードします。使われるのはブックマーク自身のドメインにあるアイコンファイルだけで、サードパーティのアイコンサービスは使いません。**アイコンファイルの最大サイズ**（<SettingDefault path="metadata_content.site_icons.max_icon_kb" /> KB）を超えるファイルや画像でないファイルはスキップされます。

更新はバックグラウンドで実行されます。マネージャーを閉じても続き、カードと **バックグラウンドのタスク** に進行状況が表示され、**一時停止**、**再開**、**キャンセル** ができます。結果は **結果を見る** から確認でき、**保存** をクリックするまで何も保存されません。

保存したアイコンはこのブラウザのローカルストレージに保存され、同期されません。ポップアップ、サイドパネル、マネージャーに表示され、ブラウザがキャッシュしたアイコンより優先されます。カードには保存済みの件数が表示され、**保存したアイコンを消去** ですべて削除できます。合計が **アイコンの保存容量上限**（4 MB）に達すると、古いアイコンから削除されます。後の更新で失敗したサイトは、以前に保存したアイコンをそのまま使います。

<Callout title="Firefox">
Firefox でこのツールを実行するには、ツールバーのポップアップの **ブックマークマネージャーを開く** でマネージャーを開きます。そこでアイコンを保存すると、ポップアップとサイドパネルにも表示されます。
</Callout>

## スマートルールでタグ付けと移動 [#tag-and-move-with-smart-rules]

スマートルールは、検索ボックスと同じ単語と[演算子](/guides/search#search-words-and-operators)を使った検索でブックマークを見つけ、タグを追加する、フォルダに移動する、またはその両方を行います。ルールが自動で動くのは、下で説明する設定をオンにした場合だけです。それ以外は、実行するたびに確認画面が開き、適用したものだけが変わります。

<Steps>
<Step>
[設定](/settings#maintenance) の **スマートルール** で **ルールを追加** をクリックします。GitHub のページ、YouTube の動画、チュートリアルにタグを付けるルールや、**Work / Reading** フォルダのブックマークを移動するルールなら **テンプレートから始める** も使えます。テンプレートは最初オフです。移動するテンプレートはまだフォルダがないため編集画面で開き、フォルダを選ぶまでオンにすることも保存することもできません。
</Step>
<Step>
ルールに名前と検索（`domain:github.com`、`folder:あとで読む -tag:既読`、`(domain:github.com OR domain:gitlab.com) -tag:archived` など）を付けます。エディターには、現在一致するブックマークの数か、閉じていないかっこなど検索の問題点が表示されます。検索を読み取れるようになるまでルールは保存できません。**アドレスやタイトルで試す** にウェブアドレスやタイトルを入力すると、検索がそれに一致するかを確認できます。これは端末上で判定され、何も保存も送信もされません。タグ（1 つずつ Enter キーを押すかカンマを入力）、移動先のフォルダ、またはその両方を指定して保存します。
</Step>
<Step>
マネージャーのツールサイドバーで、**スマートルール** カードの範囲を選び、**実行** をクリックします。範囲は表示中のフォルダ、すべてのブックマーク、またはマネージャーにある間は **検索結果**（検索ボックスに一覧表示されたもの）か **選択したブックマーク** です。範囲はクリックした時点で決まり、範囲外のブックマークが確認や変更の対象になることはありません。
</Step>
<Step>
ブックマークをタブごとに確認します: **変更**、**競合**（2 つのルールが別々のフォルダに移動しようとしている）、**ブロック**（フォルダがない、管理されている、またはそのフォルダでは別のルールがまた移動させる）、**適用済み**。変更は最初 **適用**、競合は **スキップ** になっています。1 件ずつ、または **選択した項目を設定…** で変え、**適用**（たとえば **12 件の変更を適用**）をクリックします。
</Step>
</Steps>

知っておくと便利なこと:

- ルールは一覧の順に実行されます。一致したルールはすべてタグを追加し、ブックマークを移動するルールは最初のものが優先されます。後のルールが指定したフォルダは競合として表示されます。ルールをドラッグすると順序を変えられます。
- 実行結果は落ち着きます。一致するルールが指定するフォルダにすでにあるブックマークはそこに残り、移動するのは、新しいフォルダと新しいタグで、どのルールもそれ以上移動させない場合だけです。そのため、ルールを 2 回実行してもブックマークが行ったり来たりすることはありません。
- ルールはブックマークを 1 件ずつ扱います。同じアドレスのブックマークが別々のフォルダにあれば、それぞれ別に判定して変更します。
- ブックマークにすでにあるタグは、表記が違っても追加されません。フォルダにタグを付けたり、フォルダを移動したりすることはありません。
- 適用後のメッセージの **元に戻す** で、移動とタグの両方が元に戻ります。移動は履歴の 1 つの変更になります。実行は設定の **ルールによる変更** にも、タグを付けたブックマークとともに一覧表示され、そこにある **元に戻す** で後からでも、まだ残っているそのタグを削除できます。移動は履歴から元に戻します。
- タグと移動は別々に保存されるため、メッセージにはタグ付け、移動、スキップ、失敗の件数が表示されます。履歴への記録なしに移動することはありません。記録を保存できない場合は何も移動せず、タグは追加し、そのことをメッセージで伝えます。
- 適用するときは、まず各ブックマークをもう一度確認します。確認後に削除、名前の変更、アドレスの変更、別の場所への移動が行われたブックマークはスキップされ、あなたの変更が残ります。確認後にルールが編集、オフ、削除されたブックマークも同じです（ルールの名前の変更は含みません）。スキップした件数はメッセージに表示されます。すでに確認どおりの状態になっているブックマークは、もう一度変更されません。確認後にタグや要約を変更したため、ルールに一致しなくなったブックマークもスキップされます。
- **バックグラウンドで適用する件数**（設定の **バックグラウンドのタスク**）より多くのブックマークを変更する実行は、バックグラウンドのタスクによって、タグと移動をまとめて分割して適用されます。マネージャーを閉じても、ブラウザを再起動しても続き、**バックグラウンドのタスク** で一時停止、再開、キャンセルできます。キャンセルしても、それまでに行った変更は残ります。各部分の移動は履歴の 1 つの変更になり、実行のタグは追加する前に記録され、**ルールによる変更** に一覧表示されます。部分を適用している途中でブラウザが停止した場合、タスクは **再開** を待ちます。再開すると残りの各ブックマークをもう一度確認するため、タグ付けや移動が二重に行われることはありません。スマートルールをオフにすると、オンに戻して再開するまでタスクは一時停止します。その間に編集またはオフにしたルールのブックマークはスキップされます。
- 設定では、各ルールに前回の確認済みの実行が表示されます。日時と、タグを付けた、移動した、対象外にしたブックマークの数です。**前回の実行での競合** には、2 つのルールが別々のフォルダに移動しようとしたブックマークが、それぞれのルールが指定したフォルダとともに一覧表示されます。**確認** を押すと、そのブックマークのフォルダでマネージャーが開き、そこでスマートルールをすぐに実行できます。
- ルールはこの端末に保存され、**設定をバックアップ** に含まれます。別の端末で復元したルールは、そこにフォルダがある場合だけブックマークを移動します。ない場合は、フォルダを選び直すまで移動はブロックされます。 フォルダのIDが異なる場合は、同じパスのフォルダが1つだけなら、そのパスでフォルダを見つけます。
- 設定で **新しいブックマークにタグを付ける** をオンにすると、有効なルールが、**対象とする新しいブックマーク** で許可された新しいブックマークにタグを付けます。既定は **Bookmark Scout で保存したもの** で、クイック保存、ポップアップ、マネージャー、Ask AI で保存したブックマークです。ブラウザのスター、ほかの拡張機能、同期で追加されたブックマークも含めるには **すべて** を選びます。ブラウザはブックマークの追加元を伝えないため、これらはすべて同じように扱われます。移動は一切しません。一度に多数追加されたブックマーク（同期やインポート）と、設定で許可されていないときに追加されたブックマークはそのままです。自動で付けたタグは設定の **ルールによる変更** に一覧表示され、元に戻すボタンでそのタグを削除できます。
- 確認なしの移動には、タグ付けとは別に 2 つの選択が必要です。ルールのフォルダの横にある **新しいブックマークを自動で移動** と、設定の **新しいブックマークを移動する** です。そのようなルールの下には、ルール一覧で **新しいブックマークを自動で移動します** と表示されます。ルールに一致する新しいブックマークは、そのフォルダにだけ移動します。フォルダが削除、名前変更、移動されたか管理対象になると、ルールに自動移動が停止中と表示され、フォルダを選び直してルールを保存するまで何も移動しません。同じパスの別のフォルダが代わりに使われることはありません。実行時と同じく、ブックマークを移動する最初のルールが優先され、2 つのルールが別々のフォルダに移動しようとするブックマークはそのままです。Bookmark Scout で保存したブックマーク（クイック保存、マネージャー）は置いた場所のままなので、自動移動には **対象とする新しいブックマーク** を **すべて** にする必要があります。一度に多数追加されたものや、数秒以内に再び移動されたものもそのままです。移動はまとまりごとに[履歴](/guides/save-and-organize)の 1 つの変更として、Bookmark Scout から「スマートルール、自動」の名前で記録され、その記録を保存できない場合は何も移動しません。各移動は **ルールによる変更** に一覧表示されます。そこで元に戻すと、その後に移動されていなければ、ブックマークを前のフォルダに戻します。
- 検索が `OR` とかっこに対応する前に保存したルールは、これまでと同じブックマークを見つけます。それらは引用符で囲んだテキストとして読み取られます。引用符によって検索が読み取れる長さを超える場合は、収まる語句だけを残し（見つかるブックマークは増えます）、ルールはもう一度オンにするまでオフになります。
- ルールはページのテキストを検索しません。ルールはインデックスされたページのテキストなしでブックマークを照合するため、`content:` や `has:content` を含む検索はルールに保存できません（[ページの中を検索](#search-inside-pages)）。
- ルールの一覧に保存できるルールの数には上限があります。一覧がいっぱいのときは、ルールやテンプレートを追加する代わりに設定がそのことを知らせます。また、ルールを削除した後の**元に戻す**で別のルールが押し出されることはありません。一覧がいっぱいであることを知らせて、もう一度**元に戻す**を表示し、別のルールを削除した後にそれを選ぶとルールが元に戻ります。

## ページの中を検索 [#search-inside-pages]

**ページ本文の索引** は、ブックマークしたページの読み取れる本文をこの端末に保存し、ページの中にしかない単語でも検索で見つけられるようにします。オンにするまでオフで、索引を作るページはダウンロードされます。

<Steps>
<Step>
[設定](/settings#index-page-text) で **ページ本文の索引を有効にする** をオンにします。
</Step>
<Step>
マネージャーのツールサイドバーで、**ページ本文の索引** カードの範囲を選び、**索引を作成** をクリックします。次に読み込むサイトを選びます。ダウンロードするページのあるサイトが、それぞれのブックマーク数とともに一覧され、最初はすべてチェックされています。除外するサイトのチェックを外し（**すべて選択**、**すべて解除**、長い一覧ではフィルターも使えます）、サイト数の入った開始ボタン（たとえば **2 サイトで開始**）をクリックします。確認されたら、それらのサイトへのアクセスを許可します。ほかのサイトにアクセスを求めたり、ダウンロードしたりすることはありません。索引の作成はバックグラウンドで実行されます。マネージャーを閉じても続き、カードと **バックグラウンドのタスク** に進行状況が表示され、**一時停止**、**再開**、**キャンセル** ができます。その後、ページは **結果を見る** から確認できます。
</Step>
<Step>
ページをタブごとに確認します: **本文あり**、**本文なし**、**ログインページ**（内容の代わりにログインを求めたページ。本文は保存されません）、**リダイレクト**（別のアドレスへ移動するページ。移動先は開かないため、許可していないサイトに接続することはありません。移動先のアドレスをブックマークしてください）、**失敗**、**索引済み**（以前に同じアドレスから作成済み）、**選択外**（除外したサイトにあるため、ダウンロードされません）、**スキップ**（ウェブページではない、または **ローカルネットワークのページを読まない** がオン（初期設定）の間にローカルネットワーク上にある）。本文のあるページは最初 **本文を保存** になっています。**保存**（たとえば **12 ページの本文を保存**）をクリックします。リダイレクトとして一覧に入れる前に、そのページの `https:` のアドレスと、`www.` を付けた（または外した）アドレスを、ブックマーク自身のサイトに限って試します。さらにリダイレクトする場合はたどりません。こうして読み取ったページには「（アドレス）から読み取り」と表示されます。保存中にこのデバイスの拡張機能用ストレージがいっぱいになった場合は、それまでに保存したページは残り、保存できなかった数がメッセージで表示されます。ディスクの空き容量を増やすか、設定の **ページ本文を削除** を使ってから、もう一度インデックスを作成してください。
</Step>
</Steps>

その後は、ポップアップ、サイドパネル、マネージャーでそのブックマークを本文から検索できます。`content:` はページ本文だけを探し、`has:content` は本文のあるブックマークを見つけます。ブックマークのアドレスが変わると、そのページはもう一度読み取られます。設定の **ページ本文を削除** で索引を削除しても、ブックマーク、タグ、履歴はそのままです。ページ本文で見つかった結果には、本文の出どころが **ダウンロードしたページ** か **タブから読み込んだページ** かが表示されます。「AI に質問」とローカルの AI エージェントは、この端末にとどまるページ本文を検索しません。そこでは `content:` と `has:content` は何も見つけず、回答でそのことを伝えます。

索引の作成はページを Cookie なしでダウンロードするため、ログインしないと読めないページはログインページが表示され、**ログインページ** に入ります。そのようなページで見ている内容を索引に追加するには、そのページを開きます。ページがブックマーク済みでページ本文の索引がオンのとき、ポップアップでページの保存先を示す行にあるボタン **このページの本文を索引に追加** が、タブに表示されている本文を読み取り、個人的な内容が含まれていないか確認するよう促して表示します。**本文を保存** をクリックしたときだけ保存されます。本文の読み取りはツールバーのポップアップからのみで、プライベートウィンドウやログインページからは読み取らず、読み取りの前後でタブにブックマークのページが表示されている場合だけ行います。途中でタブが別のページに移った場合は何も保存しません。

同じアドレスのブックマークは 1 回のダウンロードを共有し、それぞれが自分の本文を保持します。ほかに 2 つの場合が別に表示されます。**Web ページではない** (アドレスが PDF などのファイルを返すもので、ダウンロードしません) と、**スキップ** の中の、ユーザー名とパスワード、またはプライバシースキャナーの **機密パラメータ** にあるパラメータ (トークンなど) を含むアドレスです。これらはサイトに送られてしまうため、設定の **ログイン情報や秘密を含むアドレスをスキップ** がオン (既定) のあいだは取得しません。本文は段落ごとのプレーンテキストとして保存されるので、引用符で囲んだフレーズは 1 つの段落の中でだけ一致します。混雑していると応答し、短い待ち時間を示したサイトには、その待ち時間の後に数回まで取得し直し、それでもだめなら **失敗** に表示します。あるサイトをページ本文の索引の対象から完全に外すには、[設定](/settings#index-page-text) の **読み込まないサイト** に追加します。そのサイトとサブドメインのページはダウンロードもタブからの読み込みもされず、理由とともに **スキップ** に表示され、そのサイトから索引に追加済みの本文は削除されます。

[設定](/settings#index-page-text) の **ページ本文の索引** パネルには、索引に追加できるブックマークのうち索引済みの数、古くなった数 (以前のアドレスまたは古いバージョンで読み込んだもの。次回の実行で読み込み直します)、前回の実行で失敗した数が表示されます。**失敗したものを再試行** は、それらだけを対象にページ本文の索引をバックグラウンドで再実行し、それらのサイトへのアクセスだけを求めます。本文はカードの **結果を見る** から保存してください。ウェブサイトへの拡張機能のアクセスを取り消すと、そのサイトから索引した本文は削除され、ブックマークを削除するとその本文も削除されます。パネルには最後に本文を索引に追加した日時も表示され、**古いものを更新** は古くなったページを同じ方法で読み込み直します。

## カードにカバー画像を表示 [#show-covers-on-cards]

**カバー画像の取得** は、ページが自ら指定しているプレビュー画像（Open Graph や Twitter カードの画像）の小さなコピーを保存し、マネージャーの **カード** に表示できるようにします。オンにするまでオフです。カードを表示しても何もダウンロードされません。保存されたカバー画像がないカードには、サイトのアイコンと名前を、そのサイトから選んだ色の上に配置したタイルが表示されます。このタイルはお使いのコンピューター上で描画されます。

<Screenshot name="manager-cards" />

<Steps>
<Step>
[設定](/settings#fetch-covers) で **カバー画像の取得を有効にする** をオンにします。
</Step>
<Step>
マネージャーのツールサイドバーで、**カバー画像の取得** カードの範囲を選び、**取得** をクリックします。確認されたら、その範囲のサイトへのアクセスを許可します。
</Step>
<Step>
ページをタブごとに確認します: **カバー画像あり**（画像付き）、**カバー画像なし**、**使えない画像**（ページが示す画像が対応形式でない、大きすぎる、または読み取れない）、**別のサイト**（許可していないサイトに画像がある）、**リダイレクト**（別のアドレスへ移動するページ。移動先は開かない。ページ本文の索引と同じく、先に `https:` と `www.` のアドレスを試す）、**失敗**、**取得済み**、**スキップ**。見つかったカバー画像は最初 **カバー画像を保存** になっています。**保存**（たとえば **12 件のカバー画像を保存**）をクリックします。保存中にこのデバイスの拡張機能用ストレージがいっぱいになった場合は、それまでに保存したカバー画像は残り、保存できなかった数がメッセージで表示されます。ディスクの空き容量を増やすか、設定の **カバー画像を削除** を使ってから、もう一度取得してください。
</Step>
</Steps>

**表示** の横のボタンでマネージャーを **カード** に切り替えると表示されます。リストでは、**表示** の **カバー画像** 列に小さく表示され、ポインタを置くと大きく表示されます。カバー画像は取得元のアドレスに属するため、アドレスが変わったブックマークは、もう一度取得するまでアイコンを表示します。カバー画像はこの端末だけに保存されて同期されず、ブックマークのエクスポートにも含まれません。別のパソコンへ移すには、バックアップに含めてください（[バックアップに含まれるもの](/guides/import-export#what-a-backup-holds) を参照）。設定の **カバー画像を削除** で削除しても、ブックマーク、タグ、履歴はそのままです。ブックマークを削除すると、そのカバー画像も削除されます。1 回の取得では見つけたカバー画像を保存するまで保持するため、1 回で保持できる数のカバー画像が見つかるとページの読み込みを止めます。残したブックマークの数は確認画面に表示され、次の取得で読み込まれます。

開いているページをカバー画像にすることもできます。ページがブックマーク済みでカバー画像の取得がオンのとき、ポップアップでページの保存先を示す行の末尾にあるボタン **この画面をカバー画像にする** がタブの画面を撮影し、個人的な内容が写っていないか確認するよう促して表示します。**カバー画像を保存** をクリックしたときだけ保存されます。撮影はツールバーのポップアップからのみで、プライベートウィンドウは撮影せず、タブにブックマークのページが表示されている間だけ行います。

ブックマークのメニュー（右クリックまたは ⋯、リストでもカードでも、選択した複数のブックマークでも）や「プレビュー」の「カバー画像を取得」は、そのブックマークだけにカバー画像の取得を実行します。確認画面もサイトへのアクセスの求め方も同じです。「この画面をカバー画像にする」で保存したカバー画像は「自分で選択」に表示され、そのまま残ります。「カバー画像の取得」カードの「選択したブックマーク」は、マネージャーで選択中のブックマークに同じことをします。「カバー画像を削除」はブックマークのカバー画像を削除します（選択中なら各ブックマークのもの）。カードはすぐにプレースホルダーに戻り、メッセージの「元に戻す」で同じカバー画像が戻ります。

### 閲覧中にカバー画像を撮影する [#capture-covers-while-you-browse]

[設定](/settings#fetch-covers) のカバー画像の取得にある **閲覧中にカバー画像を撮影** をオンにすると、取得しなくてもカバー画像が手に入ります。カバー画像のないブックマーク済みのページが、表示中のタブで読み込みを終えると、Bookmark Scout は少し待ってからタブがまだそのページを表示しているか確認し、そのページのスクリーンショットをブックマークのカバー画像として撮影します。オンにすると、ブラウザにすべてのページへのアクセスを求めます。ブラウザが、クリックなしで拡張機能にタブの画面を撮影させる方法はこれしかないためです。同じアクセス権により、ウェブサイトを読み取るツールも改めて確認せずに実行できるようになります。

- プライベートウィンドウでは撮影しません。撮影するのは、**プライベートウィンドウでも撮影** もオンにして、ブラウザが Bookmark Scout にそこでの実行を許可している場合だけです。拡張機能やブラウザ自身のページ、ローカルファイル、ブックマークしていないページは決して撮影しません。
- スクリーンショットには、アカウントページやメッセージなど、ページに表示されていたものがそのまま写ります。撮影されたくないサイトは **撮影しないサイト** に追加し（サイトを追加するとそのサブドメインも対象になります）、カバー画像は設定の **カバー画像を削除** で削除してください。「読み込まないサイト」にあるサイトも撮影しません。
- **カバー画像のソース** は、両方が使えるときにどちらのカバー画像を優先するかを決めます。**ページの画像を優先し、なければスクリーンショット**（既定）では、スクリーンショットがカバー画像の取得で保存した画像を置き換えることはなく、カバー画像の取得はスクリーンショットを置き換えます。**スクリーンショットを優先** は、閲覧中に撮影したスクリーンショットについてその逆になり、**ページの画像のみ** ではスクリーンショットを撮りません。「この画面をカバー画像にする」で保存したカバー画像は、カバー画像の取得でも閲覧中のスクリーンショットでも自動で置き換えられません。置き換わるのは、あなたが別の画像を保存したときだけです。**スクリーンショットのみ** ではスクリーンショットだけを使い、カバー画像の取得はページを読み込まず、確認画面でそのことを伝えます。
- 閲覧中に撮影したスクリーンショットは、**次より古いスクリーンショットを撮り直す** で決めた日数より古くなると、次にアクセスしたときに撮り直します（0 にすると撮り直しません）。どれだけ待つかは **撮影までの待ち時間** と **撮影の間隔** で決まります。スクリーンショットは、ほかのカバー画像と同じくこの端末にだけ保存され、どこにも送信されません。止めるには設定をオフにし、アクセス権はブラウザの拡張機能の設定で削除してください。

ブックマークの **プレビュー** と詳細カードには、カバー画像の取得元（ページ自身の画像、タブの画面、閲覧中の撮影）と保存した日が表示されます。クイック保存で撮影した画像も、そのことが表示されます。

### クイック保存でカバー画像も保存する [#save-a-cover-with-quick-save]

カバー画像の取得がオンなら、クイック保存のショートカットは保存したページのカバー画像も保存します（[設定](/settings#quick-save) の **クイック保存でカバー画像も保存**、既定はオフで、カバー画像の取得もオンのときだけ動作）。ページ自身のプレビュー画像がそのページのサイトか許可したサイトにあればそれを、なければショートカットを押した瞬間、通知が表示される前に撮ったタブのスクリーンショットを使います。**クイック保存のカバー画像のソース** で独自の順序を選ばない限り **カバー画像のソース** に従い、**ブックマークにカバー画像があるとき** で置き換えを選ばない限り、すでにあるカバー画像を残します。**この画面をカバー画像にする** で保存したカバー画像は置き換えません。スクリーンショットは確認なしで保存されるため、通知に **カバー画像を削除** が表示され、**元に戻す** はブックマークとともにカバー画像を削除します。プライベートウィンドウや **撮影しないサイト**、**読み込まないサイト** のサイトでは何も撮影しません。設定の **カバー画像の画質** で、すべてのカバー画像の保存画質を決めます。カバー画像がブックマークの既存のカバー画像を置き換えた場合、**カバー画像を削除** で元のカバー画像に戻ります。

## 関連するツール [#related-tools]

- [リンク切れの検出と修復](/guides/dead-links)では、ブックマークしたページが今も読み込めるかを確認します。
- **プライバシースキャナー**（**セキュリティ** の下）は、トークン、メールアドレス、UUID、機密パラメータを含む URL（**タイトルをスキャン** がオンの場合はタイトルも）を検出します。確認画面では **高**、**中**、**低** に分けて表示されます。各項目は最初 **そのまま残す** になっており、**ブックマークを削除** に変えた項目（1 件ずつ、または **選択した項目を設定…** で）は **削除** をクリックすると削除され、元に戻せます。通常のページ内リンクや、Gmail の `#inbox` のようなアプリのアドレスは検出されません。
- **メタデータ取得**（**ページの詳細** の下）は、実際のページからページタイトルを提案し、選んだものだけを適用します。リンク切れチェックと同じウェブサイトへのアクセス権限を使います。これもバックグラウンドで実行され、タイトルは **結果を見る** から確認できます。
