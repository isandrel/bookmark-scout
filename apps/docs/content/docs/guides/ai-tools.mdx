title: Set up AI tools
description: Turn on the optional AI features, choose a provider and model, add your API key, and know exactly what bookmark data each AI tool sends.
---

AI features are **off by default**, and Bookmark Scout works fully without them. When you turn them on, requests go directly from your browser to the provider you choose, with your own API key. Bookmark Scout has no AI service of its own.

<Callout type="warn" title="Before you turn AI on">
AI tools send bookmark titles, URLs, and folder names or paths to the provider you configure. The provider handles that data under its own terms, and API use may cost money. Review every suggestion before you apply it.
</Callout>

## Turn on AI

<Steps>
<Step>
Open Bookmark Scout's settings (in Chrome, right-click the toolbar icon and choose **Options**) and go to the **AI** tab.
</Step>
<Step>
Turn on **AI Features**.
</Step>
<Step>
Under **AI services**, open the service that is already there, or click **Add service** and pick a provider. The picker has a search box, and groups providers under **Featured**, **Local servers**, **Custom**, and **More providers (models.dev)**. Then choose an **AI Model**.
</Step>
<Step>
Enter your **API Key** if the provider needs one. It is saved when you leave the field, and stored only on this device. A key that does not match the provider's format is rejected and not saved.
</Step>
<Step>
Optional: click **Refresh Models** to load the provider's current model list, or **Verify Service** to check that the provider is reachable, accepts the key, and offers the chosen model. Both read the provider's model list, which costs nothing; Verify only sends a short test prompt to providers without a list, such as Azure OpenAI. The browser asks for access to that one provider's address the first time. A refreshed list is kept for the model picker until you refresh again.
</Step>
</Steps>

<Screenshot name="options-ai" />

Settings save automatically. AI services, with their API keys, **Base URL**, and **Extra Headers JSON**, stay in this browser's local storage and are never synced. Other AI settings, such as whether AI is on, sync through your browser account where the browser supports it.

## Use more than one service

Save as many services as you like, even several of the same provider: for example a work proxy and a home proxy, each with its own key, address, and model.

- Every AI tool uses the **Default** service. Choose **Set as default** in a service's menu, or, when more than one service is turned on, pick one from the arrow next to the sparkle button in the popup.
- Turn a service off with its switch to hide it from the popup without deleting it.
- **Duplicate** copies a service, key included. **Delete** removes it and its key from this device.
- **Base URL**, **Extra Headers JSON**, and provider-specific fields such as OpenAI's organization sit under **More settings**.

The **AI Provider** picker has a search box. The extra providers come from a copy of the open [models.dev](https://models.dev) catalog that ships with the extension, so choosing one sends nothing to models.dev; requests go only to the provider you pick.

**Base URL** overrides the provider's address for every request, for example to use a proxy. It must start with `http://` or `https://`. **Extra Headers JSON** adds headers to every request, and **Custom Model** sets a model ID for providers that accept any model name.

### Local servers

Local servers must accept requests from the extension:

- **Ollama:** set `OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*` and restart Ollama. Without it, Ollama answers 403 and Verify says the server refused the extension.
- **LM Studio:** turn on **Enable CORS** in the server settings, or start it with `lms server start --cors`.
- **LocalAI:** set an API key; its CSRF check rejects keyless requests from the browser.
- **text-generation-webui:** start it with `--api`.
- **CLIProxyAPI:** accepts the extension's requests as configured by default. Start it before you click **Verify Service**; if it is not running, Verify says it could not reach `localhost:8317`.

### When a check fails

Verify and Refresh name the likely cause: a rejected key (401, or 400 from Google and xAI), a wrong Base URL (404), a provider that is rate-limiting requests (429, which still means the key works), a server that refused the extension's origin, no answer within 8 seconds, or an address that does not serve a provider API.

## Write your own prompts

Each AI tool starts with a built-in prompt. To change how a tool behaves, go to **Options**, then **AI Tools**, then **Prompts**:

1. Click **Customize** next to the tool. The editor opens with the built-in prompt to start from.
2. Edit the text. Click a variable such as `{{maxTags}}` to insert it; the tool fills it in from your settings. **Preview with current settings** shows the result.
3. Click **Save prompt**. The new prompt becomes the tool's prompt.

Keep as many prompts per tool as you like and switch between them with the tool's menu; **Default (built in)** goes back to the original. Your prompts sync across your devices through your browser account, so each one must stay under 7 KB. Bookmark Scout adds its own output format rules after your prompt, so results still load even if your prompt asks for something else.

## What each tool sends

| Tool | Where | Sends to the provider |
| --- | --- | --- |
| Folder recommendations | Popup, the sparkle button next to the search box (shown only when AI is on) | The current page's title and URL, and your bookmark folder names. With **Read page content** on, also the page's main text |
| **Auto-Tagging** | Manager, Tools, **AI & Intelligence** | Titles, URLs, and folder paths of the bookmarks in the current folder, and with **Read page content** on, each page's main text |
| **Content Summarizer** | Manager, Tools, **AI & Intelligence** | Titles, URLs, and folder paths of the bookmarks in the current folder, and with **Read page content** on, each page's main text |
| **AI Folder Reorganization** | Manager, Tools, **AI & Intelligence** | Titles, URLs, and folder paths of the bookmarks in the scope you choose |
| **AI Context Packer** | Manager, Tools, **AI & Intelligence** | Nothing. It saves a file on your computer and works with AI turned off. |

Turn on **Auto-recommend on Open** to request folder recommendations every time the popup opens. Leave it off to send a request only when you click the button.

## Read page content

Titles and URLs do not always say what a page is about. Turn on **Read page content** in **Options**, then **AI**, and folder recommendations, **Auto-Tagging**, and **Content Summarizer** also send the main text of each page. Turning it on asks for access to websites; if you decline, it stays off.

- Bookmark Scout downloads each page itself, without your cookies, so you get the logged-out version of a site. It keeps the article text without menus, scripts, images, or link addresses.
- Each page sends up to about 3,000 characters, and one tool run reads up to 40 pages. Later bookmarks in a large folder are sent with their title and URL only, as are pages that do not load.
- Pages on your local network, such as `localhost`, private IP addresses, and `.local` names, are never read, so intranet pages do not reach a cloud provider.
- Page text comes from the web and could contain instructions aimed at the AI. Bookmark Scout tells the model to treat it only as data, and you still review every suggestion before it is saved.

## See what was sent

To check exactly what a tool sent and what the provider answered, go to **Options**, then **AI**, and turn on **Record requests** under **AI activity**. Each AI call then shows its source, address, status, and time; open one to see the request headers and the request and response bodies, or copy it as JSON for a bug report.

Recording is off by default. The log stays on this device and keeps only the most recent calls. API keys and other credential headers are replaced with `[redacted]` before anything is stored, but bookmark titles and URLs in the requests are kept, so turn recording off when you are done: that also deletes the log.

## Save a page with a folder recommendation

Click the sparkle button in the popup. Choosing a suggested existing folder saves the page there. Choosing a suggested new folder opens **Review new folder** with the full path and the page; **Create Folder and Save** creates only the missing folders and saves the page. If the page is already in that folder it is not saved twice, and if a bookmark already uses one of the folder names in the path, nothing is created. **Cancel** changes nothing.

## Suggest tags and summaries

Run **Auto-Tagging** or **Content Summarizer** with **Analyze**. Suggestions are shown for review, and saved only when you click **Save Suggested Tags** or **Save Suggested Summaries**. **Merge Mode** decides whether saved suggestions are appended to what you have or replace it.

Saved tags and summaries live in this browser's local storage. You can also edit them by hand in **Bookmark Details**. They are not synced, searchable, or included in bookmark exports.

The tag count and style, summary length, and reorganization limits in Settings are sent to the provider as instructions; the provider's output is not checked against them.

## Reorganize folders

**AI Folder Reorganization** asks the provider for a new folder plan. With **Always Preview First** on (the default), the plan opens as a list of folders to create, rename, and remove and bookmarks to move, and nothing changes until you click **Apply Changes**.

## Export context for an AI chat

**AI Context Packer** exports the selected bookmarks as Markdown or XML that you can paste into any AI chat. It can include folder paths, dates, and your saved tags and summaries (**Include Saved Tags** and **Include Saved Summaries**). Like bookmark exports, it opens a privacy review when the file would contain values that may be private.

<Callout title="Firefox">
The manager is not reachable in Firefox, so the manager's AI tools are not available there. AI is not covered by the Firefox automated tests.
</Callout>
