このページは、ロードマップのドキュメントが実装とずれないように、リポジトリの現状をまとめたものです。

## 実装済み [#implemented]

- WXT、React、TypeScript、Zustand、Base UI プリミティブ上の shadcn/ui コンポーネント、ブラウザのブックマーク API で構築したブラウザ拡張機能
- Chrome を主な対象とし、Firefox と Edge のビルドターゲットを用意
- ポップアップでのブックマーク検索、フォルダの絞り込み、ドラッグ＆ドロップによる整理、クイック追加、フォルダの作成、展開と折りたたみの操作
- ポップアップ、サイドパネル、マネージャーからの削除。確認ダイアログ（初期設定でオン、設定で変更可能）と、サブツリーと保存したタグ・要約を復元する 10 秒間の「元に戻す」付き
- Chrome のサイドパネルのエントリーポイント
- ポップアップ、サイドパネル、マネージャーでのキーボードショートカット: 検索、ツリーと表の移動、現在のページの保存、親フォルダへの移動、保存した検索を開く操作、`?` によるヘルプダイアログ。Ctrl/Cmd との組み合わせは使わず、入力中やダイアログが開いている間は働きません
- フォルダツリー、パンくずリスト、ブックマークの表、ツール サイドバーを備えた独自のブックマークページ（置き換え）
- マネージャーの保存した検索（スマートビュー）。フィルター、並べ替え、フォルダの範囲だけをローカルストレージに保存し、現在のブックマークツリーに対して評価します。削除されたフォルダはスキップします
- 追加日順、自然なアルファベット順、フォルダ優先の並び順を設定可能。保存されているブックマークの順序は変更しません
- 外観、言語、検索、動作、UI サイズの詳細設定、AI、AI ツール、メンテナンス、メタデータ、セキュリティ、分析、データ、コンテキストメニューの設定を備えたオプションページ
- `chrome.storage.sync` による設定の保存
- 設定ファイルで定義した AI プロバイダー: OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、OpenRouter、Ollama、CLIProxyAPI、カスタムの OpenAI 互換エンドポイント
- AI によるフォルダの提案。提案された新しいフォルダパスを確認してから作成し、現在のページをそこに保存する機能を含みます
- 保存したタグと要約を含む AI コンテキストの書き出し、タグの提案、要約、フォルダの再整理（初期設定では適用前にプレビュー）
- ブックマークのメンテナンスツール: 重複のクリーンアップ、URL のクリーンアップ、リンク切れのスキャン（リンク切れ確定と手動確認が必要な結果を区別し、確認してから修復: 削除、リダイレクト先、Wayback Machine のコピー、URL の編集。元に戻せます）、メタデータの取得（確認したタイトルを適用。説明はプレビューのみ）、プライバシースキャン、統計
- サイトアイコンを更新: 任意のウェブサイトへのアクセスを許可した後、ウェブサイトごとにアイコンを 1 つ、ブックマークしたサイト自身からダウンロードします（サードパーティのアイコンサービスは使いません）。確認したアイコンをサイズ上限付きでローカルストレージに保存し、ポップアップ、サイドパネル、マネージャーでブラウザのアイコンキャッシュより優先して表示します。保存したアイコンは消去できます
- ブックマークのエクスポートと AI コンテキストのエクスポートの前に、任意で伏せ字にできるプライバシーの確認
- HTML または JSON からのブックマークのインポート。インポート先フォルダ、件数、重複のプレビュー、重複の扱いの選択、元に戻す機能付き
- HTML、JSON、Markdown、CSV へのブックマークのエクスポート
- リンクを保存する右クリックのコンテキストメニュー
- 英語、簡体字中国語、繁体字中国語、日本語、韓国語、スペイン語、ドイツ語、フランス語、ブラジルポルトガル語に対応した拡張機能とマーケティングサイト
- Fumadocs によるドキュメントサイト
- ポップアップ、マネージャー、設定、メンテナンス、レポート、インポートとエクスポート、ルートをモックしたネットワークツールとローカルサーバーを使うネットワークツール、モックのプロバイダーを使う AI ツールについての、ユニットテストと無人で実行する Chromium の E2E テスト
- 同じ Playwright のテストを Microsoft Edge で Edge のビルドに対して実行（`nx run extension:test:e2e:edge`）。また、Firefox のビルドに対して 9 件の Firefox スモークテストを実行（`nx run extension:test:e2e:firefox`）: ポップアップでの検索とフォルダ作成、ポップアップに表示される保存済みのサイトアイコン、サイドパネルのページ、ポップアップとサイドパネルからのマネージャーの起動、マネージャーの読み込みと絞り込み、設定の保存、JSON のエクスポートとインポートの往復、統計とプライバシーのレポート
- すべての設定を、それを読み取るコードと、それを変更するテストに対応付けた、設定と動作の対応表（`apps/extension/tests/settings-matrix.ts`）

## 部分的 [#partial]

- ブックマークのタグと要約: ブックマークの詳細で編集でき、確認した AI の提案から保存できますが、拡張機能のローカルストレージにのみ保存されます。同期されず、検索対象にならず、ブックマークのエクスポートにも含まれません。
- AI ツールの上限（タグの数とスタイル、要約の長さ、再整理のフォルダの上限）は指示としてプロバイダーに送られますが、出力がそれに従っているかどうかは確認されません。実際のプロバイダーとの互換性は手動で確認しています。
- Firefox の実行時のテストはスモークテストで、すべてのテストではありません。Playwright は `moz-extension://` のページを開けないため、Firefox のテストは geckodriver（Selenium）で通常の Firefox を操作し、ビルドを本来のアドオン ID で一時的なアドオンとしてインストールします。そのため、Firefox Add-ons が受け取るマニフェストをテストできます。コンテキストメニューからの保存（Chromium のテストはサービスワーカーから `contextMenus.onClicked` を発火しますが、Firefox のビルドはテストハーネスから操作できない MV2 のバックグラウンドページを使います）、ドラッグ＆ドロップ、キーボードショートカット、ネットワークツール、AI ツール、ロケールは対象外です。
- Firefox の API の違い: Firefox には `_favicon` サービスがないため、ブラウザのアイコンキャッシュは使えず、**サイトアイコンを更新** で保存したアイコンがない限り、ブックマークには汎用のアイコンが表示されます。Firefox はブックマークページを置き換えられないため、マネージャーとツール サイドバーはポップアップの **ブックマークマネージャーを開く** から開きます。サイドパネルのページは Firefox のサイドバーとして宣言されており、自動化ではサイドバー自体を開けないため、テストではそのページをタブで読み込みます。
- 4 つのツールの範囲の設定は固定です: 自動タグ付けとコンテンツ要約は常に現在のフォルダを使い、重複クリーナーとプライバシースキャナーは常にすべてのブックマークをスキャンします。

## 予定 [#planned]

- Firefox の実行時のテストの拡大: コンテキストメニュー、ドラッグ＆ドロップ、キーボードショートカット、ネットワークツール、AI ツール、ロケール
- Chrome ウェブストア、Firefox Add-ons、Edge アドオンへの申請。掲載用の資料と申請のチェックリストはリポジトリの <RepoLink tree="store">`store/` フォルダ</RepoLink>にあります。申請は手動で、リリースの承認が必要です。Firefox のパッケージには、恒久的なアドオン ID とデータ収集の申告が設定されています

## ドキュメントのルール [#documentation-rules]

- 機能の状況、インストール手順、ブラウザ対応、プライバシーに関する前提、設定が変わったときは、ドキュメントを更新してください。
- AI 機能はオプトインで、ブックマークのデータを選んだプロバイダーに送信する場合があります。
- CI は、拡張機能のユニットテスト、Chromium のエンドツーエンドテスト、Edge のテスト、Firefox のスモークテストを、手動のセットアップなしで必須チェックとして実行します。ビルドが通っても、実行時の動作が確認されたことにはなりません。
