このページは、ロードマップのドキュメントが実装とずれないように、リポジトリの現状をまとめたものです。

## 実装済み [#implemented]

- WXT、React、TypeScript、Zustand、Base UI プリミティブ上の shadcn/ui コンポーネント、ブラウザのブックマーク API で構築したブラウザ拡張機能
- Chrome を主な対象とし、Firefox と Edge のビルドターゲットを用意
- ポップアップ、サイドパネル、マネージャーでの、タイトル、アドレス、フォルダ、タグ、要約によるブックマーク検索（`tag:`、`domain:`、`folder:`、`after:` などの演算子に対応）、ポップアップでのフォルダの絞り込み、ドラッグ＆ドロップによる整理、クイック追加、フォルダの作成、展開と折りたたみの操作。仮想化したツリーにより大きなライブラリでも快適に動作し、再読み込みせずにブックマークのイベントから更新します
- 名前やパスの一部を入力して見つけたフォルダへの保存。一致の順位付け、1 文字の入力ミスの許容、最近のフォルダの優先表示付き
- クイック保存ショートカット（<Shortcut id="commands.quick-save" /> で最もよく一致するフォルダ、最後に使ったフォルダ、指定したフォルダに保存。<Shortcut id="commands.ai-quick-save" /> で AI の最初の提案に保存）。ページ内の通知で「元に戻す」「移動先」「再試行」「AI を使わずに保存」を提供し、通知を表示できないページではツールバーのバッジとポップアップを使います。設定でショートカットを設定でき、Firefox ではキーの記録、Chrome と Edge では <Shortcut id="browser.bookmark_page" /> の案内、ブラウザがショートカットにキーを割り当てなかった場合の通知があります
- ポップアップ、サイドパネル、マネージャーからの削除。確認ダイアログ（初期設定でオン、設定で変更可能）と、サブツリーと保存したタグ・要約を復元する 10 秒間の「元に戻す」付き
- マネージャーのブックマーク履歴: Bookmark Scout による変更も、ほかで行われた変更（別の拡張機能、ブラウザのマネージャー、同期）も、項目と読み直しによる確認とともにこのデバイスに記録。セッションに変更が残っている間は元に戻すとやり直し、再起動後は保存したコピーから削除した項目を復元。拡張機能がオフの間の変更は 1 つの差分として表示
- サイドパネルのエントリーポイント（Chrome と Edge ではサイドパネル、Firefox ではサイドバー）
- 新規インストールの後に一度だけ開き、アップデート後には開かないウェルカムページ
- ポップアップとサイドパネルでのキーボードショートカット: 検索、ツリーの移動、現在のページの保存。ブラウザ自体のショートカットには割り当てません。マネージャーでは Chrome のブックマーク マネージャーと同じキー（すべて選択、コピー、切り取り、貼り付け、元に戻す、やり直し、タブで開く）と、<Shortcut id="manager.show_help" /> によるヘルプダイアログ。すべてのショートカットは `apps/extension/config/ui/shortcuts.toml` で一度だけ定義され、ドキュメント、ウェブサイト、README はそこからキーの表記を表示します。入力中やダイアログが開いている間は働きません
- フォルダツリー、パンくずリスト、ブックマークの表、ツール サイドバーを備えた独自のブックマークページ（置き換え）。Chrome のマネージャーと同じように動作します: `?id=` と `?q=` のアドレス（Chrome のフォルダへのリンクを含む）、行の選択、1 つのブックマーク操作レジストリから作られ設定でカスタマイズできる右クリックメニューと ⋯ メニュー、マネージャーのタブをまたぐ切り取り・コピー・貼り付け、すべてをタブ、新しいウィンドウ、シークレット ウィンドウで開く操作、名前順の並べ替え、ブックマークやフォルダの追加、行・フォルダ・リンクのドラッグ＆ドロップ、Chrome と同じキーで操作でき、アカウントとデバイスのセクションを分けた ARIA のフォルダツリー、狭いウィンドウでのドロワー、セッションストレージに保存する直近 100 件の変更の元に戻す・やり直し履歴
- マネージャーの保存した検索（スマートビュー）。フィルター、並べ替え、フォルダの範囲だけをローカルストレージに保存し、現在のブックマークツリーに対して評価します。削除されたフォルダはスキップします
- ブラウザの順序（既定）、追加日順、自然なアルファベット順、フォルダ優先の並び順を設定可能。保存されているブックマークの順序は変更しません
- **基本設定**（多くの人が変更するいくつかの設定）で開き、**詳細設定** の下にさらに 11 のカテゴリ（保存と検索、外観、動作、AI、AIツール、メンテナンス、ページのタイトルとアイコン、セキュリティ、分析、インポートとエクスポート、開発者向け）、設定の検索、リストとセグメントの編集、折りたたまれた詳細設定を備えた設定ページ
- 初期値に対する上書きとして保存する設定: 同期する設定は `chrome.storage.sync`、デバイスごとの設定はローカルストレージに保存し、保存した値は zod で検証するバージョン付きのエンベロープに入れ、複数のページからの書き込みは Web Locks で直列化します。新しい形式は、古い保存データを変換せずに置き換えました
- 設定のバックアップファイル（変更した設定、カスタムプロンプト、キーを除く AI サービス、保存した検索、マネージャーの列と並べ替え）と復元
- 設定ファイルで定義した AI プロバイダー: OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、xAI、Azure OpenAI、OpenRouter、Ollama、CLIProxyAPI、ローカルサーバー、models.dev カタログのほか約 200 のプロバイダー、カスタムの OpenAI 互換と Anthropic 互換のエンドポイント
- Chrome の内蔵 AI（Prompt API 経由の Gemini Nano）を、フォルダの提案と AI クイック保存のための、ユーザーのパソコン上で動く無料のサービスとして使用。単語の一致による代替と、設定でのデバイスの確認付き
- AI によるフォルダの提案。提案された新しいフォルダパスを確認してから作成し、現在のページをそこに保存する機能を含みます
- 保存したタグと要約を含む AI コンテキストの書き出し、タグの提案、要約、フォルダの再整理（常に適用前にプレビュー）。いずれも元に戻せます
- エディターにプレースホルダーの一覧（`{{today}}`、`{{language}}`、`{{aboutMe}}`、`{{existingTags}}`）を表示するプロンプトライブラリ、AI の出力言語の設定、すべての組み込みプロンプトに使われる自己紹介のテキスト、自動タグ付けへの既存のタグ名の送信（オフにできます）
- ポップアップとサイドパネルの AI に質問。ブックマーク操作レジストリの読み取りツール（語句、フォルダ、タグ、サイト、日付での検索、フォルダ、タグと要約、重複、フォルダの提案、リンクの確認、ページの読み取り）、承認後にだけページを保存したり、移動、名前の変更、削除、新しいフォルダの計画を適用したりする書き込みツール（元に戻せます）、最新の回答についてメッセージ欄の上に表示される提案ボタン、設定の **AI に質問でできること** を備えています
- `bookmark-scout-mcp` MCP サーバーとネイティブ メッセージング ホスト（`packages/mcp-bridge`）によるローカル AI エージェント: デバイスごとに初期設定でオフ。検索では非公開の値を隠し、変更は **変更を許可** がオンのときだけ、それぞれ Bookmark Scout のウィンドウで承認されてから行います
- ブックマークのメンテナンスツール: 重複のクリーンアップ、URL のクリーンアップ、リンク切れのスキャン（リンク切れ確定と手動確認が必要な結果を区別し、確認してから修復: 削除、リダイレクト先、Wayback Machine のコピー、URL の編集。元に戻せます）、メタデータの取得（確認したタイトルを適用。説明はプレビューのみ）、プライバシースキャン、統計
- サイトアイコンを更新: 任意のウェブサイトへのアクセスを許可した後、ウェブサイトごとにアイコンを 1 つ、ブックマークしたサイト自身からダウンロードします（サードパーティのアイコンサービスは使いません）。確認したアイコンをサイズ上限付きでローカルストレージに保存し、ポップアップ、サイドパネル、マネージャーでブラウザのアイコンキャッシュより優先して表示します。保存したアイコンは消去できます
- ブックマークのエクスポートと AI コンテキストのエクスポートの前に、任意で伏せ字にできるプライバシーの確認
- HTML または JSON からのブックマークのインポート。インポート先フォルダ、件数、重複のプレビュー、重複の扱いの選択、元に戻す機能付き
- HTML、JSON（各ブックマークのタグと要約を含む）、Markdown、CSV へのブックマークのエクスポート
- リンクを保存する右クリックのコンテキストメニュー
- <Languages of="extension" />に対応した拡張機能とマーケティングサイト
- Fumadocs によるドキュメントサイト
- ポップアップ、マネージャー、設定、メンテナンス、レポート、インポートとエクスポート、クイック保存、ルートをモックしたネットワークツールとローカルサーバーを使うネットワークツール、モックのプロバイダーを使う AI ツール、画面をまたぐユーザーの一連の操作についての、ユニットテストと無人で実行する Chromium の E2E テスト
- 同じ Playwright のテストを Microsoft Edge で Edge のビルドに対して実行（`nx run extension:test:e2e:edge`）。また、Firefox のビルドに対して 18 件の Firefox スモークテストを実行（`nx run extension:test:e2e:firefox`）: ポップアップでの検索とフォルダ作成、ポップアップに表示される保存済みのサイトアイコン、サイドパネルのページ、ポップアップとサイドパネルからのマネージャーの起動、マネージャーの読み込み、絞り込み、アドレス、元に戻す、フォルダツリーのキー、右クリックメニュー、ドラッグ＆ドロップ、クイック保存ショートカットの通知とキーの記録、AI のデータ送信への同意、ツールの実行時のサイトごとのウェブサイトへのアクセス、設定の保存、JSON のエクスポートとインポートの往復、統計とプライバシーのレポート
- コンパイルした `bookmark-scout-mcp` バイナリを、Linux と macOS でテスト用ブラウザのネイティブホストとして実行するブリッジのエンドツーエンドテスト（`nx run extension:test:e2e:bridge`）
- 大きなライブラリでの応答時間とスクロールの性能測定（`nx run extension:test:perf`。毎日と必要に応じて実行）と、実際のプロバイダーに対するライブ AI テスト（`nx run extension:test:live`。必要に応じて実行）
- すべての設定を、それを読み取るコードと、それを変更するテストに対応付けた、設定と動作の対応表（`apps/extension/tests/settings-matrix.ts`）

## 各ブラウザでテストされている範囲 [#what-is-tested-in-each-browser]

主な対象は Chrome です。Edge は Chromium ベースで同じエンドツーエンドテストを実行し、Firefox では Manifest V2 のビルドを使います。

- **Chrome（Chromium）**: ポップアップ、サイドパネル、マネージャー、設定、メンテナンスツール、レポート、インポートとエクスポート、キーボードショートカット、クイック保存、保存した検索、コンテキストメニューからの保存、ドラッグ＆ドロップ、ネットワークツール、モックのプロバイダーを使った AI ツール、それらのいくつかをまたぐ一連の操作について、ユニットテストとエンドツーエンドテストがあります。ブリッジのテストでは、Linux と macOS の Chromium で `bookmark-scout-mcp` プログラムを拡張機能と一緒に実行します。
- **Edge**: 同じエンドツーエンドテストを Edge のビルドで実行します。
- **Firefox**: スモークテストで、ポップアップでの検索とフォルダ作成、タブで読み込んだサイドパネルのページ、ポップアップとサイドパネルからのマネージャーの起動、マネージャーのページ（アドレス、`Delete` と元に戻す、フォルダツリーのキー、右クリックメニュー、スクリプトで発生させたドラッグイベントによるドラッグ＆ドロップ）、クイック保存ショートカットの通知とキーの記録、AI のデータ共有への同意、ツールの実行時にそのブックマークのサイトだけへのアクセスを求めること、設定の保存、JSON のエクスポートとインポートの往復、統計とプライバシーのレポート、ポップアップに表示される保存済みのサイトアイコンを確認しています。ページ上の右クリックメニューからの保存、その他のキーボードショートカット、ポップアップでのドラッグ＆ドロップ、クイック保存の通知そのもの、ローカル AI エージェント、ネットワークツールと AI ツール（**サイトアイコンを更新** 自体を含む）は対象外です。

Edge のテストと Firefox のスモークテストは、Chromium のテストと同様に CI の必須チェックです。実際の AI プロバイダーと実際のウェブサイトは、自動テストではなく手動で確認しています。

## 部分的 [#partial]

- ブックマークのタグと要約: ブックマークの詳細で編集でき、確認した AI の提案から保存できますが、拡張機能のローカルストレージにのみ保存されます。同期されませんが、すべての検索ボックスでこれらによってブックマークを検索できます。JSON のブックマークエクスポートには含まれ、そのファイルをインポートすると、作成されるブックマークに復元されます。
- AI ツールの上限（タグの数とスタイル、要約の長さ、再整理のフォルダの上限）は指示としてプロバイダーに送られますが、出力がそれに従っているかどうかは確認されません。実際のプロバイダーとの互換性は手動で確認しています。
- Firefox の実行時のテストはスモークテストで、すべてのテストではありません。Playwright は `moz-extension://` のページを開けないため、Firefox のテストは geckodriver（Selenium）で通常の Firefox を操作し、ビルドを本来のアドオン ID で一時的なアドオンとしてインストールします。そのため、Firefox Add-ons が受け取るマニフェストをテストできます。コンテキストメニューからの保存（Chromium のテストはサービスワーカーから `contextMenus.onClicked` を発火しますが、Firefox のビルドはテストハーネスから操作できない MV2 のバックグラウンドページを使います）、ポップアップでのドラッグ＆ドロップ（マネージャーでのドラッグ＆ドロップは、スクリプトで発生させたドラッグイベントでテストしています）、マネージャーの `Delete`、元に戻す、フォルダツリーのキー以外のキーボードショートカット、ネットワークツール、AI ツール、ローカル AI エージェント、ロケールは対象外です。
- Firefox の API の違い: Firefox には `_favicon` サービスがないため、ブラウザのアイコンキャッシュは使えず、**サイトアイコンを更新** で保存したアイコンがない限り、ブックマークには汎用のアイコンが表示されます。Firefox はブックマークページを置き換えられないため、マネージャーとツール サイドバーはポップアップの **ブックマークマネージャーを開く** から開きます。サイドパネルのページは Firefox のサイドバーとして宣言されており、自動化ではサイドバー自体を開けないため、テストではそのページをタブで読み込みます。
- 4 つのツールの範囲の設定は固定です: 自動タグ付けとコンテンツ要約は常に現在のフォルダを使い、重複クリーナーとプライバシースキャナーは常にすべてのブックマークをスキャンします。

## 予定 [#planned]

- Firefox の実行時のテストの拡大: コンテキストメニューからの保存、ポップアップでのドラッグ＆ドロップ、キーボードショートカット、ネットワークツール、AI ツール、ロケール
- Firefox Add-ons と Edge アドオンへの申請（Chrome ウェブストアには掲載済みです）。掲載用の資料と申請のチェックリストはリポジトリの <RepoLink tree="store">`store/` フォルダ</RepoLink>にあります。申請は手動で、リリースの承認が必要です。Firefox のパッケージには、恒久的なアドオン ID とデータ収集の申告が設定されています
- `bookmark-scout-mcp` の配布: GitHub リリースでのバイナリ、npm パッケージ、MCP レジストリへの登録。それまでは、リポジトリからビルドするか実行してください
- マネージャーのメニューや AI ツールと同じように、ポップアップの行とクイック保存の通知のコマンドをブックマーク操作レジストリから取得すること

## ドキュメントのルール [#documentation-rules]

- 機能の状況、インストール手順、ブラウザ対応、プライバシーに関する前提、設定が変わったときは、ドキュメントを更新してください。
- AI 機能はオプトインで、ブックマークのデータを選んだプロバイダーに送信する場合があります。
- CI は、拡張機能のユニットテスト、Chromium のエンドツーエンドテスト、Edge のテスト、Firefox のスモークテストを必須チェックとして、またブリッジや拡張機能が変更された場合はブリッジのエンドツーエンドテストを、手動のセットアップなしで実行します。実際の AI プロバイダーは、プルリクエストではなく、必要に応じて実行するライブテストで確認します。ビルドが通っても、実行時の動作が確認されたことにはなりません。
