## 已实现 [#implemented]

- 使用 WXT、React、TypeScript、Zustand、基于 Base UI 基础组件的 shadcn/ui 组件以及浏览器书签 API 构建的浏览器扩展程序
- 以 Chrome 为主要目标，并提供 Firefox 和 Edge 构建目标
- 弹出窗口中的书签搜索、文件夹筛选、拖放整理、快速添加、文件夹创建以及展开/折叠控件，采用虚拟化的文件夹树，在大型书签库中也能保持流畅，并根据书签事件更新而无需重新加载
- 输入文件夹名称或路径的一部分即可找到文件夹并保存，匹配结果经过排序，可容忍一处拼写错误，最近使用的文件夹排在前面
- 快速保存快捷键（`Alt+Shift+S` 保存到最匹配的文件夹、上次使用的文件夹或指定文件夹；`Alt+Shift+D` 保存到 AI 建议的第一个文件夹），页面中的通知提供“撤消”“移动到”“重试”和“不使用 AI 保存”；在无法显示通知的页面上，改用工具栏徽标和弹出窗口；可在设置中配置快捷键，包括 Firefox 中的按键录制器、Chrome 和 Edge 中关于 `Ctrl+D` 的指引，以及浏览器未给快捷键分配按键时的提示
- 在弹出窗口、侧边栏和书签管理器中删除，带有确认对话框（默认开启，可在设置中关闭），并提供 10 秒撤消，可恢复整个子树及其已保存的标签和摘要
- 侧边栏入口（Chrome 和 Edge 中为侧边栏，Firefox 中为侧栏）
- 弹出窗口和侧边栏中的键盘快捷键，用于搜索、在文件夹树中导航和保存当前网页，从不占用 Ctrl/Cmd 组合键；书签管理器中使用 Chrome 书签管理器的按键，包括 `Ctrl/Cmd` 全选、复制、剪切、粘贴、撤消、重做和在标签页中打开，并提供 `?` 帮助对话框。快捷键在输入文字或对话框打开时暂停
- 自定义的书签页面替换，包含文件夹树、路径导航、书签表格和工具侧栏，用法与 Chrome 书签管理器一致：`?id=` 和 `?q=` 地址（包括 Chrome 的文件夹链接）、行选择、基于同一个书签操作注册表构建并可在设置中自定义的右键菜单和 ⋯ 菜单、跨书签管理器标签页的剪切、复制和粘贴、在标签页、新窗口或无痕式窗口中全部打开、按名称排序、添加书签或文件夹、拖放行、文件夹和链接、支持 Chrome 按键且分为账号和设备两个部分的 ARIA 文件夹树、窄窗口中的抽屉面板，以及保存在会话存储中、记录最近 100 项更改的撤消和重做历史
- 书签管理器中的已保存的搜索（智能视图），只在本地存储中保存筛选条件、排序和文件夹范围，并针对实时书签树重新计算，跳过已删除的文件夹
- 可配置的按添加日期、自然字母顺序和文件夹优先排序，不会改变已存储的书签顺序
- 选项页面，包含十个类别（保存与搜索、外观、行为、AI、AI 工具、维护、页面标题与图标、安全、分析，以及导入与导出）、设置搜索、列表和分段编辑器，以及折叠的高级设置
- 设置以默认值的覆盖项形式存储：同步设置保存在 `chrome.storage.sync` 中，设备设置保存在本地存储中，存储的值放在带版本号并经 zod 校验的封装结构中，多个页面的写入通过 Web Locks 串行执行。新格式取代了旧的存储数据，没有进行转换
- 设置备份文件（已更改的设置、自定义提示词、不含密钥的 AI 服务、已保存的搜索、书签管理器的列和排序）及恢复
- 来自配置的 AI 服务商：OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、OpenRouter、Ollama、CLIProxyAPI，以及自定义的兼容 OpenAI 的端点
- AI 文件夹推荐，包括在经你确认后创建建议的新文件夹路径，并将当前网页保存到其中
- 带有已保存标签和摘要的 AI 上下文打包、标签建议、摘要以及文件夹重组（始终在应用前预览），均可撤消
- 弹出窗口和侧边栏中的“询问 AI”，提供来自书签操作注册表的读取工具（按关键词、文件夹、标签、网站或日期搜索，文件夹、标签和摘要，重复项，文件夹建议，链接检查和网页读取），以及只在批准后才保存网页或应用移动、重命名、删除和新建文件夹方案的写入工具，支持撤消；回答下方提供建议按钮；设置中提供**询问 AI 可以执行的操作**
- 通过 `bookmark-scout-mcp` MCP 服务器和原生消息传递宿主（`packages/mcp-bridge`）连接本地 AI 智能体：每台设备默认关闭，查询时隐藏隐私值，只有开启**允许更改**后才能更改，且每项更改都要在 Bookmark Scout 窗口中批准
- 书签维护工具：重复书签清理、网址清理、失效链接扫描（区分确认失效和需手动检查的结果，并提供需经审阅的修复方式：删除、使用重定向目标、使用 Wayback Machine 副本或修改网址，支持撤消）、元数据获取（应用经审阅的标题；描述仅供预览）、隐私扫描以及统计
- 刷新网站图标：在你授予可选的网站访问权限后，直接从已加入书签的网站本身为每个网站下载一个图标（从不使用第三方图标服务），将经审阅的图标保存在有大小上限的本地存储中，并在弹出窗口、侧边栏和书签管理器中优先于浏览器的图标缓存显示；已保存的图标可以清除
- 书签导出和 AI 上下文导出之前的隐私检查，可选择脱敏
- 从 HTML 或 JSON 导入书签，可预览目标文件夹、数量和重复项，选择重复项处理方式，并支持撤消
- 将书签导出为 HTML、JSON（包含每个书签的标签和摘要）、Markdown 或 CSV
- 通过右键菜单保存链接的流程
- 扩展程序和宣传网站支持英语、简体中文、繁体中文、日语、韩语、西班牙语、德语、法语和巴西葡萄牙语

- 单元测试，以及针对弹出窗口、书签管理器、设置、维护、报告、导入/导出、快速保存、使用路由模拟和本地服务器的联网工具、使用模拟服务商的 AI 工具，以及跨界面用户流程的无人值守 Chromium E2E 测试

## 各浏览器的测试范围 [#what-is-tested-in-each-browser]

Chrome 是主要目标浏览器。Edge 基于 Chromium，运行同一套端到端测试；Firefox 使用 Manifest V2 版本。

- **Chrome (Chromium)**：单元测试，以及针对以下内容的端到端测试：弹出窗口、侧边栏、书签管理器、设置、维护工具、报告、导入和导出、键盘快捷键、快速保存、已保存的搜索、通过右键菜单保存、拖放、联网工具、使用模拟服务商的 AI 工具，以及跨越其中多项的用户流程。桥接测试会在 Linux 和 macOS 上的 Chromium 中，将 `bookmark-scout-mcp` 程序与扩展程序一起运行。
- **Edge**：针对 Edge 版本运行同一套端到端测试。
- **Firefox**：一套冒烟测试，覆盖弹出窗口中的搜索和文件夹创建、在标签页中加载的侧边栏页面、从弹出窗口和侧边栏打开书签管理器、书签管理器页面及其地址、`Delete` 和撤消、文件夹树按键、右键菜单和拖放（通过脚本化的拖动事件）、快速保存快捷键提示和按键录制器、AI 数据共享同意、保存设置、JSON 导出再导入的往返流程、统计和隐私报告，以及弹出窗口中已保存的网站图标。在网页上通过右键菜单保存、其他键盘快捷键、弹出窗口中的拖放、快速保存通知本身、本地 AI 智能体，以及联网工具和 AI 工具（包括**刷新网站图标**本身）均未覆盖。

与 Chromium 测试套件一样，Edge 测试套件和 Firefox 冒烟测试套件也是 CI 中的必需检查。真实的 AI 服务商和在线网站通过人工检查，而非自动化测试。

## 部分实现 [#partial]

- 书签标签和摘要：可在书签详情中修改，也可从经审阅的 AI 建议中保存，但只存储在扩展程序的本地存储中。它们不会同步，也不可搜索；JSON 书签导出文件会包含它们，导入该文件时会将其恢复到导入新建的书签上。
- AI 工具的限制（标签数量和样式、摘要长度、重组时的文件夹限制）会作为指令发送给服务商；不会检查输出是否遵守这些限制。真实服务商的兼容性通过人工验证。
- Firefox 运行时覆盖范围是一套冒烟测试，而不是完整的测试套件。Playwright 无法打开 `moz-extension://` 页面，因此 Firefox 测试通过 geckodriver（Selenium）驱动原版 Firefox，并使用真实的附加组件 ID 将构建版本安装为临时附加组件，从而测试 Firefox 附加组件商店收到的清单文件。这些测试不覆盖通过右键菜单保存（Chromium 测试从 service worker 派发 `contextMenus.onClicked`；Firefox 版本使用测试框架无法编写脚本控制的 MV2 后台页面）、弹出窗口中的拖放（书签管理器中的拖放通过脚本化的拖动事件覆盖）、除书签管理器的 `Delete`、撤消和文件夹树按键之外的键盘快捷键、联网工具、AI 工具、本地 AI 智能体或多语言。
- Firefox 的 API 差异：由于 Firefox 没有 `_favicon` 服务，因此无法使用浏览器的图标缓存，除非通过**刷新网站图标**保存了图标，否则书签会显示通用图标；由于 Firefox 无法替换书签页面，书签管理器和工具侧栏需通过弹出窗口中的**打开书签管理器**打开；侧边栏页面被声明为 Firefox 侧栏，由于自动化工具无法打开侧栏本身，测试会在标签页中加载该页面。
- 四个工具的范围设置是固定的：自动标签和内容摘要始终使用当前文件夹；重复书签清理和隐私扫描始终扫描所有书签。

## 文档规则 [#documentation-rules]

- 当功能状态、安装路径、浏览器支持、隐私预期或配置发生变化时，请更新文档。
- AI 功能需主动开启，并且可能会将书签数据发送给所选的服务商。
- CI 会将扩展程序单元测试、Chromium 端到端测试套件、Edge 测试套件和 Firefox 冒烟测试套件作为必需检查运行，并在桥接程序或扩展程序发生变化时运行桥接端到端测试，无需手动设置。真实 AI 服务商由按需运行的实时测试套件检查，不在拉取请求中运行。构建通过并不等于运行时覆盖。
