本页总结代码仓库的当前状态，以免路线图文档与实际实现脱节。

## 已实现 [#implemented]

- 使用 WXT、React、TypeScript、Zustand、基于 Base UI 基础组件的 shadcn/ui 组件以及浏览器书签 API 构建的浏览器扩展程序
- 以 Chrome 为主要目标，并提供 Firefox 和 Edge 构建目标
- 弹出窗口中的书签搜索、文件夹筛选、拖放整理、快速添加、文件夹创建以及展开/折叠控件
- 在弹出窗口、侧边栏和书签管理器中删除，带有确认对话框（默认开启，可在设置中关闭），并提供 10 秒撤消，可恢复整个子树及其已保存的标签和摘要
- 侧边栏入口（Chrome 和 Edge 中为侧边栏，Firefox 中为侧栏）
- 弹出窗口、侧边栏和书签管理器中的键盘快捷键，用于搜索、在树和表格中导航、保存当前网页、跳转到上级文件夹、打开已保存的搜索，以及打开 `?` 帮助对话框；快捷键从不占用 Ctrl/Cmd 组合键，并在输入文字或对话框打开时暂停
- 自定义的书签页面替换，包含文件夹树、路径导航、书签表格和工具侧栏
- 书签管理器中的已保存的搜索（智能视图），只在本地存储中保存筛选条件、排序和文件夹范围，并针对实时书签树重新计算，跳过已删除的文件夹
- 可配置的按添加日期、自然字母顺序和文件夹优先排序，不会改变已存储的书签顺序
- 选项页面，包含外观、语言、搜索、行为、高级界面尺寸、AI、AI 工具、维护、元数据、安全、分析、数据和右键菜单等设置
- 通过 `chrome.storage.sync` 持久保存设置
- 来自配置的 AI 服务商：OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、OpenRouter、Ollama、CLIProxyAPI，以及自定义的兼容 OpenAI 的端点
- AI 文件夹推荐，包括在经你确认后创建建议的新文件夹路径，并将当前网页保存到其中
- 带有已保存标签和摘要的 AI 上下文打包、标签建议、摘要以及文件夹重组（默认在应用前预览）
- 书签维护工具：重复书签清理、网址清理、失效链接扫描（区分确认失效和需手动检查的结果，并提供需经审阅的修复方式：删除、使用重定向目标、使用 Wayback Machine 副本或修改网址，支持撤消）、元数据获取（应用经审阅的标题；描述仅供预览）、隐私扫描以及统计
- 刷新网站图标：在你授予可选的网站访问权限后，直接从已加入书签的网站本身为每个网站下载一个图标（从不使用第三方图标服务），将经审阅的图标保存在有大小上限的本地存储中，并在弹出窗口、侧边栏和书签管理器中优先于浏览器的图标缓存显示；已保存的图标可以清除
- 书签导出和 AI 上下文导出之前的隐私检查，可选择脱敏
- 从 HTML 或 JSON 导入书签，可预览目标文件夹、数量和重复项，选择重复项处理方式，并支持撤消
- 将书签导出为 HTML、JSON、Markdown 或 CSV
- 通过右键菜单保存链接的流程
- 扩展程序和宣传网站支持英语、简体中文、繁体中文、日语、韩语、西班牙语、德语、法语和巴西葡萄牙语
- Fumadocs 文档网站
- 单元测试，以及针对弹出窗口、书签管理器、设置、维护、报告、导入/导出、使用路由模拟和本地服务器的联网工具，以及使用模拟服务商的 AI 工具的无人值守 Chromium E2E 测试
- 在 Microsoft Edge 中针对 Edge 版本运行的同一套 Playwright 测试（`nx run extension:test:e2e:edge`），以及针对 Firefox 版本运行的包含九项测试的 Firefox 冒烟测试套件（`nx run extension:test:e2e:firefox`）：弹出窗口中的搜索和文件夹创建、弹出窗口中已保存的网站图标、侧边栏页面、从弹出窗口和侧边栏打开书签管理器、书签管理器的加载和筛选、保存设置、JSON 导出再导入的往返流程，以及统计和隐私报告
- 设置与行为对照表（`apps/extension/tests/settings-matrix.ts`），将每项设置映射到读取它的代码以及更改它的测试

## 部分实现 [#partial]

- 书签标签和摘要：可在书签详情中修改，也可从经审阅的 AI 建议中保存，但只存储在扩展程序的本地存储中。它们不会同步，不可搜索，也不会包含在书签导出文件中。
- AI 工具的限制（标签数量和样式、摘要长度、重组时的文件夹限制）会作为指令发送给服务商；不会检查输出是否遵守这些限制。真实服务商的兼容性通过人工验证。
- Firefox 运行时覆盖范围是一套冒烟测试，而不是完整的测试套件。Playwright 无法打开 `moz-extension://` 页面，因此 Firefox 测试通过 geckodriver（Selenium）驱动原版 Firefox，并使用真实的附加组件 ID 将构建版本安装为临时附加组件，从而测试 Firefox 附加组件商店收到的清单文件。这些测试不覆盖通过右键菜单保存（Chromium 测试从 service worker 派发 `contextMenus.onClicked`；Firefox 版本使用测试框架无法编写脚本控制的 MV2 后台页面）、拖放、键盘快捷键、联网工具、AI 工具或多语言。
- Firefox 的 API 差异：由于 Firefox 没有 `_favicon` 服务，因此无法使用浏览器的图标缓存，除非通过**刷新网站图标**保存了图标，否则书签会显示通用图标；由于 Firefox 无法替换书签页面，书签管理器和工具侧栏需通过弹出窗口中的**打开书签管理器**打开；侧边栏页面被声明为 Firefox 侧栏，由于自动化工具无法打开侧栏本身，测试会在标签页中加载该页面。
- 四个工具的范围设置是固定的：自动标签和内容摘要始终使用当前文件夹；重复书签清理和隐私扫描始终扫描所有书签。

- 当功能状态、安装路径、浏览器支持、隐私预期或配置发生变化时，请更新文档。

- CI 会将扩展程序单元测试、Chromium 端到端测试套件、Edge 测试套件和 Firefox 冒烟测试套件作为必需检查运行，无需手动设置。构建通过并不等于运行时覆盖。
