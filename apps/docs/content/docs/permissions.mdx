These are the permissions in the built extension for each browser. Bookmark Scout has no content scripts, so it never reads the pages you visit.

## Granted at install

| Permission | Browsers | Why |
| --- | --- | --- |
| `bookmarks` | All | Show and search your bookmarks, and create, edit, move, and delete them when you act in the popup, side panel, manager, or right-click menu |
| `tabs` | All | Read the title and URL of the active tab so you can save the page you are on, and open bookmarks in a new tab. It does not read other tabs or track browsing |
| `storage` | All | Save your settings, and on this device only, your AI provider settings, tags, summaries, saved searches, recent folders, recent searches, and site icons saved with **Refresh Site Icons** |
| `contextMenus` | All | Add **Save bookmark to...** to the right-click menu on links. Turn it off with **Context Menu** in [Settings](/settings#data) |
| `favicon` | Chrome, Edge | Show each bookmark's site icon from the browser's own icon cache. No network request is made for icons |
| `sidePanel` | Chrome, Edge | Provide the side panel view. Firefox declares the same page as a sidebar instead |

In Chrome and Edge the extension also replaces the browser's bookmarks page with the Bookmark Scout manager. That is a page override, not a permission. Firefox does not allow it, so there the manager opens from **Open bookmark manager** in the popup; see [Browser support](/browser-support).

## Optional website access

The extension also declares access to `http://*/*` and `https://*/*`, but none of it is granted at install. The browser asks you at the moment you need it:

- **Check Dead Links**, **Metadata Fetcher**, and **Refresh Site Icons** ask for access to websites the first time you run them, because bookmarks can point to any site. Requests are sent without cookies, and only the page head is read for titles and icon links. If you decline, nothing is scanned. See [Find and repair dead links](/guides/dead-links) and [Refresh site icons](/guides/clean-up#refresh-site-icons).
- **Read page content** in the AI settings asks for access to websites when you turn it on, so AI tools can download pages, without cookies, and send their main text to your AI provider. Pages on your local network are never read. See [Read page content](/guides/ai-tools#read-page-content).
- **Verify Service** and **Refresh Models** in the AI settings ask for access to that one provider's address only. See [Set up AI tools](/guides/ai-tools).

To take website access back, open the browser's page for the extension (for example `chrome://extensions/`, then **Details** on Bookmark Scout) and change its site access.

## What is not requested

- No access to page content, and no content scripts
- No history, downloads, or cookies permissions
- No host access at install

Where your data goes when a permission is used is covered on [Privacy](/privacy). The justification for each permission, as submitted to the stores, is in the repository's <RepoLink file="store/permissions.md">`store/permissions.md`</RepoLink>.
