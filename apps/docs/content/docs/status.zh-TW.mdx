本頁摘要說明存放區目前的狀態，讓發展藍圖文件不會與實作脫節。

## 已實作 [#implemented]

- 以 WXT、React、TypeScript、Zustand、建構於 Base UI 基本元件上的 shadcn/ui 元件，以及瀏覽器書籤 API 建置的瀏覽器擴充功能
- 以 Chrome 為主要目標，並提供 Firefox 和 Edge 建置目標
- 彈出式視窗中的書籤搜尋、資料夾篩選、以拖放方式整理、快速新增、建立資料夾，以及展開/收合控制項
- 可從彈出式視窗、側邊面板和書籤管理員刪除，並顯示確認對話方塊 (預設開啟，可在設定中選擇關閉)，以及可在 10 秒內「復原」，還原子樹狀結構及其已儲存的標籤和摘要
- 側邊面板進入點 (Chrome 和 Edge 中為側邊面板，Firefox 中為側邊欄)
- 彈出式視窗、側邊面板和書籤管理員中的鍵盤快速鍵，可用於搜尋、樹狀結構和表格導覽、儲存目前網頁、前往上層資料夾、開啟已儲存的搜尋，以及開啟 `?` 說明對話方塊；這些快速鍵一律不使用 Ctrl/Cmd 組合鍵，並會在輸入文字或對話方塊開啟時暫停
- 自訂的書籤頁面覆寫，包含資料夾樹狀結構、路徑導覽、書籤表格和工具側欄
- 書籤管理員中的已儲存的搜尋 (智慧檢視)，只將篩選條件、排序和資料夾範圍儲存在本機儲存空間中，並依即時的書籤樹狀結構進行評估，略過已刪除的資料夾
- 可設定依新增日期、自然字母順序和資料夾優先排序，不會變更已儲存的書籤順序
- 選項頁面，提供外觀、語言、搜尋、行為、進階 UI 尺寸、AI、AI 工具、維護、中繼資料、安全性、分析、資料和右鍵選單等設定
- 透過 `chrome.storage.sync` 保存設定
- 由設定檔定義的 AI 供應商：OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、OpenRouter、Ollama、CLIProxyAPI，以及自訂的 OpenAI 相容端點
- AI 資料夾推薦，包括經確認後建立建議的新資料夾路徑，並將目前網頁儲存至該處
- 含已儲存標籤和摘要的 AI 脈絡打包、標籤建議、摘要，以及資料夾重組 (預設在套用前先預覽)
- 書籤維護工具：清理重複書籤、清理網址、掃描失效連結 (結果分為確定失效和需手動檢查，並提供經確認的修復：刪除、重新導向的目的地、Wayback Machine 副本或編輯後的網址，且可復原)、擷取中繼資料 (套用經確認的標題；說明僅供預覽)、隱私掃描和統計資料
- 重新整理網站圖示：在取得選用網站存取權後，從已加入書籤的網站本身為每個網站下載一個圖示 (絕不使用第三方圖示服務)，將經確認的圖示儲存在有大小上限的本機儲存空間中，並在彈出式視窗、側邊面板和書籤管理員中優先於瀏覽器的圖示快取顯示；已儲存的圖示可以清除
- 匯出書籤和匯出 AI 脈絡前的隱私確認，並可選擇遮蔽
- 從 HTML 或 JSON 匯入書籤，並預覽目標資料夾、數量和重複項目，可選擇重複項目的處理方式，且可復原
- 將書籤匯出為 HTML、JSON、Markdown 或 CSV
- 透過右鍵選單儲存連結的流程
- 擴充功能和行銷網站提供英文、簡體中文、繁體中文、日文、韓文、西班牙文、德文、法文和巴西葡萄牙文版本
- Fumadocs 說明文件網站
- 單元測試，以及無人值守的 Chromium 端對端測試，涵蓋彈出式視窗、書籤管理員、設定、維護、報告、匯入/匯出、以路由模擬和本機伺服器測試的網路工具，以及以模擬供應商測試的 AI 工具
- 在 Microsoft Edge 中對 Edge 建置版本執行相同的 Playwright 測試套件 (`nx run extension:test:e2e:edge`)，以及對 Firefox 建置版本執行包含九項測試的 Firefox 冒煙測試套件 (`nx run extension:test:e2e:firefox`)：彈出式視窗的搜尋和建立資料夾、彈出式視窗中已儲存的網站圖示、側邊面板頁面、從彈出式視窗和側邊面板開啟書籤管理員、書籤管理員的載入和篩選、儲存設定、JSON 匯出再匯入的完整流程，以及統計資料和隱私報告
- 設定與行為對照表 (`apps/extension/tests/settings-matrix.ts`)，將每項設定對應到讀取它的程式碼，以及變更它的測試

## 部分完成 [#partial]

- 書籤標籤和摘要：可在「書籤詳細資料」中編輯，也可從經確認的 AI 建議儲存，但只儲存在擴充功能的本機儲存空間中。這些資料不會同步、無法搜尋，也不會包含在書籤匯出檔案中。
- AI 工具的限制 (標籤數量和樣式、摘要長度、重組時的資料夾限制) 會以指示的形式傳送給供應商；系統不會檢查輸出是否符合這些限制。與實際供應商的相容性以人工驗證。
- Firefox 執行階段的測試範圍是冒煙測試套件，而非完整的測試套件。Playwright 無法開啟 `moz-extension://` 頁面，因此 Firefox 測試會透過 geckodriver (Selenium) 操作標準版 Firefox，並以實際的附加元件 ID 將建置版本安裝為暫用附加元件，藉此測試 Firefox 附加元件商店收到的資訊清單。這些測試不涵蓋從右鍵選單儲存 (Chromium 測試會從 Service Worker 觸發 `contextMenus.onClicked`；Firefox 建置版本使用 MV2 背景頁面，測試框架無法對其編寫指令碼)、拖放、鍵盤快速鍵、網路工具、AI 工具或語言設定。
- Firefox API 的差異：由於 Firefox 沒有 `_favicon` 服務，因此無法使用瀏覽器的圖示快取，除非已使用「**重新整理網站圖示**」儲存圖示，否則書籤會顯示通用圖示；由於 Firefox 無法取代書籤頁面，書籤管理員和工具側欄要從彈出式視窗中的「**開啟書籤管理員**」開啟；側邊面板頁面已宣告為 Firefox 側欄，且由於自動化工具無法開啟側欄本身，測試會在分頁中載入該頁面。
- 有四項工具範圍設定是固定的：自動加上標籤和內容摘要工具一律使用目前資料夾；重複書籤清理工具和隱私掃描工具一律掃描所有書籤。

## 規劃中 [#planned]

- 擴大 Firefox 執行階段的測試範圍：右鍵選單、拖放、鍵盤快速鍵、網路工具、AI 工具和語言設定
- 提交至 Chrome 線上應用程式商店、Firefox 附加元件和 Edge 附加元件。商店資訊頁面的資料和提交檢查清單位於存放區的 <RepoLink tree="store">`store/` 資料夾</RepoLink>中；提交以人工方式進行，且需要核准發布版本。Firefox 套件已有永久的附加元件 ID 和資料收集聲明

## 說明文件規則 [#documentation-rules]

- 功能狀態、安裝路徑、瀏覽器支援、隱私預期或設定有所變更時，請更新說明文件。
- AI 功能需自行啟用，且可能會將書籤資料傳送給所選的供應商。
- CI 會將擴充功能的單元測試、Chromium 端對端測試套件、Edge 測試套件和 Firefox 冒煙測試套件作為必要檢查項目執行，不需要手動設定。建置成功不代表執行階段已有測試涵蓋。
