本頁摘要說明存放區目前的狀態，讓發展藍圖文件不會與實作脫節。

## 已實作 [#implemented]

- 以 WXT、React、TypeScript、Zustand、建構於 Base UI 基本元件上的 shadcn/ui 元件，以及瀏覽器書籤 API 建置的瀏覽器擴充功能
- 以 Chrome 為主要目標，並提供 Firefox 和 Edge 建置目標
- 在彈出式視窗、側邊面板和書籤管理員中依標題、網址、資料夾、標籤和摘要搜尋書籤，支援 `tag:`、`domain:`、`folder:` 和 `after:` 等運算子；彈出式視窗中的資料夾篩選、以拖放方式整理、快速新增、建立資料夾，以及展開/收合控制項；樹狀結構採用虛擬化，即使書籤庫很大也能保持回應迅速，並依書籤事件更新，而不是重新載入
- 輸入資料夾名稱或路徑的一部分來找到資料夾並儲存，相符結果會依序排列，容許一個錯字，並優先列出最近使用的資料夾
- 快速儲存快捷鍵 (<Shortcut id="commands.quick-save" /> 儲存到最相符、上次使用或指定的資料夾；<Shortcut id="commands.ai-quick-save" /> 儲存到 AI 的第一個建議)，並在網頁中顯示通知，提供「復原」、「移動到」、「重試」和「不使用 AI 儲存」；在網頁無法顯示通知時，改用工具列徽章和彈出式視窗；可在設定中設定快捷鍵，包括 Firefox 中的按鍵錄製器、Chrome 和 Edge 中 <Shortcut id="browser.bookmark_page" /> 的設定說明，以及瀏覽器未替快捷鍵指派按鍵時的提示
- 可從彈出式視窗、側邊面板和書籤管理員刪除，並顯示確認對話方塊 (預設開啟，可在設定中選擇關閉)，以及可在 10 秒內「復原」，還原子樹狀結構及其已儲存的標籤和摘要
- 書籤管理員中的書籤記錄：Bookmark Scout 所做的和在其他地方（其他擴充功能、瀏覽器的管理員、同步）所做的每一項變更，都會連同其項目和重新讀取的核對結果記錄在此裝置上；在工作階段仍保留變更時可復原和重做，重新啟動後可從儲存的副本還原已刪除的項目，擴充功能關閉期間的變更顯示為一項差異
- 側邊面板進入點 (Chrome 和 Edge 中為側邊面板，Firefox 中為側邊欄)
- 歡迎頁面，在全新安裝後開啟一次，更新後絕不會開啟
- 彈出式視窗和側邊面板中的鍵盤快速鍵，可用於搜尋、樹狀結構導覽和儲存目前網頁，不佔用瀏覽器本身的快速鍵；書籤管理員則使用 Chrome 書籤管理員的按鍵，包括全選、複製、剪下、貼上、復原、重做和在分頁中開啟，並提供按 <Shortcut id="manager.show_help" /> 開啟的說明對話方塊。每個快速鍵都只在 `apps/extension/config/ui/shortcuts.toml` 中定義一次，文件、網站和 README 中的按鍵文字都由此產生。這些快速鍵會在輸入文字或對話方塊開啟時暫停
- 自訂的書籤頁面覆寫，包含資料夾樹狀結構、路徑導覽、書籤表格和工具側欄，操作方式與 Chrome 的書籤管理員相同：`?id=` 和 `?q=` 網址 (包括 Chrome 的資料夾連結)、列選取、由同一個書籤動作登錄檔建構且可在設定中自訂的右鍵選單和 ⋯ 選單、可在多個書籤管理員分頁之間剪下、複製和貼上、在分頁、新視窗或無痕式視窗中全部開啟、依名稱排序、新增書籤或資料夾、拖放列、資料夾和連結、支援 Chrome 按鍵並分開顯示帳戶和裝置區段的 ARIA 資料夾樹狀結構、窄視窗中的抽屜式面板，以及儲存在工作階段儲存空間中、包含最近 100 項變更的復原和重做記錄
- 書籤管理員中的已儲存的搜尋 (智慧檢視)，只將篩選條件、排序和資料夾範圍儲存在本機儲存空間中，並依即時的書籤樹狀結構進行評估，略過已刪除的資料夾
- 可設定依瀏覽器順序 (預設)、新增日期、自然字母順序和資料夾優先排序，不會變更已儲存的書籤順序
- 設定頁面，開啟時顯示「**常用設定**」(大多數人會變更的幾項設定)，「**進階設定**」下另有十一個類別 (儲存與搜尋、外觀、行為、AI、AI 工具、維護、頁面標題與圖示、安全性、分析、匯入與匯出，以及開發人員選項)，並提供設定搜尋、清單和區段編輯器，以及收合的進階設定
- 設定以預設值的覆寫形式儲存：同步設定儲存在 `chrome.storage.sync` 中，裝置設定儲存在本機儲存空間中，儲存的值放在以 zod 驗證、附有版本的封裝中，多個頁面的寫入則以 Web Locks 依序處理。新格式取代了舊的儲存資料，而沒有加以轉換
- 設定備份檔案 (已變更的設定、自訂提示詞、不含金鑰的 AI 服務、已儲存的搜尋、書籤管理員的欄位和排序) 及還原
- 由設定檔定義的 AI 供應商：OpenAI、Anthropic、Google、Groq、Mistral AI、DeepSeek、xAI、Azure OpenAI、OpenRouter、Ollama、CLIProxyAPI、本機伺服器、models.dev 目錄中其他約 200 個供應商，以及自訂的 OpenAI 相容和 Anthropic 相容端點
- Chrome 的內建 AI (透過 Prompt API 使用 Gemini Nano)，作為使用者電腦上的免費服務，用於資料夾推薦和 AI 快速儲存，並提供字詞比對的備援方式，以及設定中的裝置檢查
- AI 資料夾推薦，包括經確認後建立建議的新資料夾路徑，並將目前網頁儲存至該處
- 含已儲存標籤和摘要的 AI 脈絡打包、標籤建議、摘要，以及資料夾重組 (一律在套用前先預覽)，且每項都可以復原
- 提示詞庫，編輯器中提供預留位置清單 (`{{today}}`、`{{language}}`、`{{aboutMe}}`、`{{existingTags}}`)、AI 輸出語言設定、用於所有內建提示詞的「關於我」文字，以及供自動加上標籤使用的現有標籤名稱 (可以關閉)
- 彈出式視窗和側邊面板中的「詢問 AI」，提供來自書籤動作登錄檔的讀取工具 (依字詞、資料夾、標籤、網站或日期搜尋，以及資料夾、標籤和摘要、重複書籤、資料夾建議、連結檢查和網頁讀取)、只有在核准後才會儲存網頁或套用移動、重新命名、刪除和新增資料夾計畫的寫入工具 (可復原)、針對最新回答顯示在訊息框上方的建議按鈕，以及設定中的「**詢問 AI 可以執行的動作**」
- 透過 `bookmark-scout-mcp` MCP 伺服器和原生訊息傳遞主機 (`packages/mcp-bridge`) 支援本機 AI 代理：每部裝置預設為關閉，查詢時會隱藏私密值，而且只有開啟「**允許變更**」才能進行變更，每項變更都要在 Bookmark Scout 視窗中核准
- 書籤維護工具：清理重複書籤、清理網址、掃描失效連結 (結果分為確定失效和需手動檢查，並提供經確認的修復：刪除、重新導向的目的地、Wayback Machine 副本或編輯後的網址，且可復原)、擷取中繼資料 (套用經確認的標題；說明僅供預覽)、隱私掃描和統計資料
- 重新整理網站圖示：在取得選用網站存取權後，從已加入書籤的網站本身為每個網站下載一個圖示 (絕不使用第三方圖示服務)，將經確認的圖示儲存在有大小上限的本機儲存空間中，並在彈出式視窗、側邊面板和書籤管理員中優先於瀏覽器的圖示快取顯示；已儲存的圖示可以清除
- 匯出書籤和匯出 AI 脈絡前的隱私確認，並可選擇遮蔽
- 從 HTML 或 JSON 匯入書籤，並預覽目標資料夾、數量和重複項目，可選擇重複項目的處理方式，且可復原
- 將書籤匯出為 HTML、JSON (包含每個書籤的標籤和摘要)、Markdown 或 CSV
- 透過右鍵選單儲存連結的流程
- 擴充功能和行銷網站提供<Languages of="extension" />版本
- Fumadocs 說明文件網站
- 單元測試，以及無人值守的 Chromium 端對端測試，涵蓋彈出式視窗、書籤管理員、設定、維護、報告、匯入/匯出、快速儲存、以路由模擬和本機伺服器測試的網路工具、以模擬供應商測試的 AI 工具，以及跨介面的使用者流程
- 在 Microsoft Edge 中對 Edge 建置版本執行相同的 Playwright 測試套件 (`nx run extension:test:e2e:edge`)，以及對 Firefox 建置版本執行包含 18 項測試的 Firefox 冒煙測試套件 (`nx run extension:test:e2e:firefox`)：彈出式視窗的搜尋和建立資料夾、彈出式視窗中已儲存的網站圖示、側邊面板頁面、從彈出式視窗和側邊面板開啟書籤管理員、書籤管理員的載入、篩選、網址、復原、資料夾樹狀結構按鍵、右鍵選單和拖放、快速儲存快捷鍵提示和按鍵錄製器、AI 資料同意、工具執行時依網站授予的網站存取權、儲存設定、JSON 匯出再匯入的完整流程，以及統計資料和隱私報告
- 橋接端對端測試，在 Linux 和 macOS 上將編譯後的 `bookmark-scout-mcp` 二進位檔作為測試瀏覽器的原生主機執行 (`nx run extension:test:e2e:bridge`)
- 在大型書籤庫上測量延遲和捲動的效能測試 (`nx run extension:test:perf`)，每日執行並可隨需執行，以及針對實際供應商的即時 AI 測試套件 (`nx run extension:test:live`)，隨需執行
- 設定與行為對照表 (`apps/extension/tests/settings-matrix.ts`)，將每項設定對應到讀取它的程式碼，以及變更它的測試

## 各瀏覽器的測試範圍 [#what-is-tested-in-each-browser]

Chrome 是主要支援的瀏覽器。Edge 以 Chromium 為基礎，執行相同的端對端測試套件；Firefox 使用 Manifest V2 建置版本。

- **Chrome (Chromium)**：單元測試和端對端測試，涵蓋彈出式視窗、側邊面板、書籤管理員、設定、維護工具、報告、匯入和匯出、鍵盤快速鍵、快速儲存、已儲存的搜尋、從右鍵選單儲存、拖放、網路工具、以模擬供應商測試的 AI 工具，以及橫跨其中多項功能的使用者流程。橋接測試會在 Linux 和 macOS 上的 Chromium 中，搭配擴充功能執行 `bookmark-scout-mcp` 程式。
- **Edge**：對 Edge 建置版本執行相同的端對端測試套件。
- **Firefox**：冒煙測試套件涵蓋彈出式視窗的搜尋和建立資料夾、在分頁中載入的側邊面板頁面、從彈出式視窗和側邊面板開啟書籤管理員、書籤管理員頁面及其網址、`Delete` 和復原、資料夾樹狀結構按鍵、右鍵選單和拖放 (使用模擬的拖曳事件)、快速儲存快捷鍵提示和按鍵錄製器、AI 資料分享同意、工具執行時只要求其書籤所在網站的存取權、儲存設定、JSON 匯出再匯入的完整流程、統計資料和隱私報告，以及彈出式視窗中已儲存的網站圖示。從網頁上的右鍵選單儲存、其他鍵盤快速鍵、彈出式視窗中的拖放、快速儲存通知本身、本機 AI 代理，以及網路和 AI 工具 (包括「**重新整理網站圖示**」本身) 都不在測試範圍內。

Edge 測試套件和 Firefox 冒煙測試套件與 Chromium 測試套件一樣，都是 CI 的必要檢查項目。實際的 AI 供應商和線上網站則以人工檢查，而非自動化測試。

## 部分完成 [#partial]

- 書籤標籤和摘要：可在「書籤詳細資料」中編輯，也可從經確認的 AI 建議儲存，但只儲存在擴充功能的本機儲存空間中。這些資料不會同步，但每個搜尋框都能依這些資料找到書籤；JSON 書籤匯出檔案會包含這些資料，匯入該檔案時會將其還原到匯入所建立的書籤上。
- AI 工具的限制 (標籤數量和樣式、摘要長度、重組時的資料夾限制) 會以指示的形式傳送給供應商；系統不會檢查輸出是否符合這些限制。與實際供應商的相容性以人工驗證。
- Firefox 執行階段的測試範圍是冒煙測試套件，而非完整的測試套件。Playwright 無法開啟 `moz-extension://` 頁面，因此 Firefox 測試會透過 geckodriver (Selenium) 操作標準版 Firefox，並以實際的附加元件 ID 將建置版本安裝為暫用附加元件，藉此測試 Firefox 附加元件商店收到的資訊清單。這些測試不涵蓋從右鍵選單儲存 (Chromium 測試會從 Service Worker 觸發 `contextMenus.onClicked`；Firefox 建置版本使用 MV2 背景頁面，測試框架無法對其編寫指令碼)、彈出式視窗中的拖放 (書籤管理員中的拖放以模擬的拖曳事件測試)、書籤管理員的 `Delete`、復原和資料夾樹狀結構按鍵以外的鍵盤快速鍵、網路工具、AI 工具、本機 AI 代理或語言設定。
- Firefox API 的差異：由於 Firefox 沒有 `_favicon` 服務，因此無法使用瀏覽器的圖示快取，除非已使用「**重新整理網站圖示**」儲存圖示，否則書籤會顯示通用圖示；由於 Firefox 無法取代書籤頁面，書籤管理員和工具側欄要從彈出式視窗中的「**開啟書籤管理員**」開啟；側邊面板頁面已宣告為 Firefox 側欄，且由於自動化工具無法開啟側欄本身，測試會在分頁中載入該頁面。
- 有四項工具範圍設定是固定的：自動加上標籤和內容摘要工具一律使用目前資料夾；重複書籤清理工具和隱私掃描工具一律掃描所有書籤。

## 說明文件規則 [#documentation-rules]

- 功能狀態、安裝路徑、瀏覽器支援、隱私預期或設定有所變更時，請更新說明文件。
- AI 功能需自行啟用，且可能會將書籤資料傳送給所選的供應商。
- CI 會將擴充功能的單元測試、Chromium 端對端測試套件、Edge 測試套件和 Firefox 冒煙測試套件作為必要檢查項目執行，並在橋接程式或擴充功能有所變更時執行橋接端對端測試，不需要手動設定。實際的 AI 供應商由隨需執行的即時測試套件檢查，不會在提取要求中檢查。建置成功不代表執行階段已有測試涵蓋。
